Usage:
  agentx                                  TUI dashboard (all workspaces)

=== agentx roles ===
Inspect role definitions or reset a retired workspace endpoint
Usage: agentx roles [OPTIONS] [COMMAND]
Commands:
  show            Inspect one resolved role, including its literal prompt
  reset-endpoint  Clear the selected workspace's endpoint binding after exact retirement
  help            Print this message or the help of the given subcommand(s)
Options:
      --dir <PATH>  Discover the workspace containing this directory
      --workspace <PATH|global>  Select an exact workspace, or the global context
      --all  Include auxiliary roles and shadowed ancestor/global definitions
      --json  Emit workspace and role metadata as JSON
      --iam <NAME>  Inspect discovery as this existing Agent; normally identity is automatic
  -h, --help  Print help
Role files:
  Published: <workspace>/.agent-guides/roles/NAME.md or OWNER.HELPER.md
  Overrides: <workspace>/.agentx/roles/NAME.toml
  Global: $AGENTX_DIR/roles/NAME.toml (default: ~/.agentx/roles/NAME.toml)
  Markdown requires YAML frontmatter schema: role; optional role must match the filename.
  Only immediate role files are discovered; reference Markdown without schema: role is ignored.
  Short names resolve the selected workspace, parents, then global.
  Workspace: explicit --workspace > explicit --dir project > AGENTX_WORKSPACE > cwd project > ~/.agentx.
  Project discovery searches nearest Git root (.git directory or worktree file), then .agentx/,
  then the existing .agent-guides/roles boundary. A target without a root continues to inheritance.
  Bound Agents inherit persisted membership; environment values only carry the default to children.
  --dir sets cwd; omitted --dir preserves caller cwd, independently of workspace selection.
  Within one workspace, TOML overrides Markdown; a nearer Markdown beats a farther TOML.
  local:NAME selects only the current workspace; global:NAME selects global TOML definitions.
  OWNER.HELPER is auxiliary; default discovery shows public roles plus your adopted owner's helpers
  from the same logical workspace, including mixed Markdown/TOML sources. --all shows shadowed
  roles and all helpers. Explicit show/launch is unrestricted. Disabled names never fall through.
  Identity discovery probes an existing daemon only; unavailable implicit identity shows public roles.
Setup:
  Install role Markdown into .agent-guides/roles/; no wrapper is required for ordinary roles.
  agentx profile create team-codex --tool codex
  agentx profile default team-codex
  agentx launch --role coder
  Optional .agentx/roles/coder.toml: profile = "team-codex"
  Optional .agentx/roles/controller.toml: default = true
  Thin TOML inherits only the same-workspace Markdown prompt and description.
  Explicit prompt or prompt_file replaces the Markdown prompt; use at most one.
  Without matching Markdown, one prompt field is required. prompt_file is relative to TOML.
  File prompts retain their absolute source path and unchanged body, with parent-relative references.
  Omitted profile uses ordinary launch defaults; --profile overrides the role's explicit profile.
  Listing/show needs no default profile; role launches require a concrete named profile.
  default = true chooses a directory recipient, independently of the default launch profile.
  At most one default per namespace; auxiliaries cannot be default recipients.
  To suppress a role including ancestor/global fallback: NAME.toml containing only disabled = true.
Examples:
  agentx roles --dir /path/project
  agentx roles show controller --dir /path/project --json
  agentx launch --dir /path/project --role controller --headless --go
  agentx launch --workspace /path/project --role global:reviewer --headless --go
  agentx list --dir /path/project
  agentx list --all
  agentx send --dir /path/project --dry-run
  agentx send --dir /path/project --intent request -- "Handle this task"
Each launch creates a new member. Directory send reuses or starts one default recipient;
parent fallback uses the parent's endpoint and preserves the originally requested directory.
Role/profile/instruction snapshots survive resume and fork; editing files affects new agents.
Role/workspace launches are local; shared Codex app-server stdio is unsupported.
More reference: agentx docs --cli

=== agentx launch ===
Launch one or more agents
Usage: agentx launch [OPTIONS] [-- <NATIVE_ARGS>...]
Arguments:

Options:

      --bind <BINDINGS>  Bind a Task/Delivery file and include it in the initial message where supported; repeatable, relative to caller cwd

      --batch-id <BATCH_ID>  Explicit launch batch identifier
      --dir <DIR>  Working directory for the agent
      --role [<ROLE>]  Adopt a role; omit its value to select in a local terminal

      --json  `--json`: report the outcome as one JSON object on stdout
      --run-here  Run in the invoking terminal
      --no-run-here  Open elsewhere; with tmux, create a detached session

Routine task delegation:
  agentx launch --go --headless --title "Task title" --bind ".controller/xx/xx.task.md" --agentx-prompt "Assignment"
Run directly with configured defaults; if launch fails, follow its diagnostic to recover.
Add --role NAME when needed. Role discovery/setup: agentx roles / agentx roles --help.
Omit the value of --role, --profile or --tool to select in a local terminal.
Use --count N for multiple agents, --dir PATH for cwd, or --workspace PATH|global for membership.
Workspace defaults: explicit --workspace > --dir project > AGENTX_WORKSPACE > cwd project > ~/.agentx.
Project discovery prefers the nearest Git/worktree root, then a project .agentx/ boundary.
Without --dir, cwd stays at the caller's current directory; workspace does not move it.
Put all native tool arguments after --.
Each launch creates a new member; agentx send --dir PATH reuses or starts its default recipient.
Role/workspace launches are local; shared Codex app-server stdio is unsupported.
Environment options (before --):
  --env-file PATH (repeatable)
  --env-override / --no-env-override
Supported tools: claude, gemini, codex, opencode, kilo, kilocode, pi, pi-agent, omp, omp-agent, hermes, antigravity, agy, cursor, cursor-agent, kimi, copilot, qoder, qodercli, grok, grok-build

=== agentx resume ===
Usage:
  agentx resume <target> [flags] [-- tool-args...]    Resume a stopped agent
Omit <target> in a terminal to select an eligible session.
<target> can be:
  <name>                            agentx name (e.g. luna)
  <uuid>                            claude/codex/gemini session UUID
  ses_<id>                          opencode/kilo session ID
  <thread-name>                     claude /rename title or codex thread_name
  <target>:<device>                 run on a remote device via relay
Adopting by UUID or thread-name reclaims the original agentx
identity if one existed; otherwise a new identity is assigned.
CWD is recovered from the session's transcript/DB.
Flags (parsed before tool args; pass `--` to stop parsing):
  --terminal <preset>               Override terminal; tmux attaches unless headless/no-run-here
  --device <device>                 Run on a remote device via relay
  --dir <path>                      Working directory
  --env-file <path>                 Load dotenv data (repeat for ordered files)
  --env-override / --no-env-overrideReplace / preserve inherited environment values
  --headless                        Run in background
  --run-here / --no-run-here        Use current terminal / open elsewhere (tmux: detach)
  --agentx-prompt <text>            Initial prompt
  --agentx-system-prompt <text>     System prompt
  --json                            Print the result as one JSON object
  --go                              Skip preview, run immediately
Native tool arguments must follow --; unknown AgentX options are errors.
See also:
  agentx f <target>                   Fork an agent session (claude/codex/opencode/kilo/pi/omp/qoder/grok)

=== agentx send ===
Usage:
  agentx send @name -- message text  Direct message
  agentx send @name1 @name2 -- message  Multiple targets
  agentx send --dir PATH -- message  Reuse/start the directory's default role recipient
  agentx send --workspace PATH -- message  Address an exact workspace's default recipient
  agentx send --dir PATH --dry-run  Inspect default routing without launch or message
  agentx send -- message text     Broadcast to all
  agentx send @name               Message from stdin (pipe or heredoc)
  agentx send @name --file <path>  Message from file
  agentx send @name --base64 <encoded>  Message from base64 string
  agentx send --receipt REQUEST_ID [--json]  Read the original send receipt by ID without resending
  agentx send --delivery-status ID [--json]  Read accepted-message delivery facts without resending or draining mail
  Everything after -- is the message (no quotes needed).
  All flags must come before --.
Directory routing:
    --dir PATH                     Discover the target workspace from PATH
    --workspace PATH|global        Select an exact workspace or the global default
    Without @recipients, reuse/start one default = true role recipient.
    Search the selected workspace, then parents, then shared roles; no default is an error.
    Parent fallback uses the parent's endpoint and retains the originally requested directory.
    Concurrent first sends share one endpoint; startup-pending messages enter its durable mailbox.
    With @recipients, check their workspace instead; never create a replacement.
    Setup and examples: agentx roles --help
Target matching:
    @luna                          exact base name
    @luna:BOXE                     exact or uniquely prefixed remote agent
  Partial local names are rejected to avoid accidental fan-out.
Envelope:
    --intent <type>                request | inform | ack
    request: expect a response
    inform: FYI, no response needed
    ack: replying to a request (requires --reply-to)
    --reply-to <id>                Link to event ID (42 or 42:BOXE)
    --thread <name>                Threaded routing: seed recipients once, then reuse thread members
    broadcast + --thread reuses prior thread members; seed with @mentions first
Sender:
    --from <name>                  External sender identity
    -b                             Shorthand for --from bigboss
    --iam <name>                   Caller identity (default: injected process/session binding)
Output:
    --json                         Acceptance receipt plus current delivery observation; leaves mail unread
    --quiet                        No output; leaves mail unread
    Acceptance, mailbox confirmation and model execution are separate facts.
Inline bundle (attach structured context):
    --title <text>                 Create and attach bundle inline
    --description <text>           Bundle description (required with --title)
    --events <ids>                 Event IDs/ranges: 1,2,5-10
    --files <paths>                Comma-separated file paths
    --transcript <ranges>          Format: 3-14:normal,6:full,22-30:detailed
    --extends <id>                 Parent bundle (optional)
  See 'agentx bundle --help' for bundle details
Examples:
    agentx send @luna -- Hello there!
    agentx send @luna @nova --intent request -- Can you help?
    agentx send --dir /path/project --intent request -- Handle this task
    agentx send -- Broadcast message to everyone
    echo 'Complex message' | agentx send @luna
    agentx send @luna <<'EOF'
    Multi-line message with special chars
    EOF

=== agentx hooks ===
Usage:
  agentx hooks                    Show how each tool loads agentx's hooks
  agentx hooks status [tool]      Same as above, for one tool
    hermes: also asks Hermes whether the plugin is enabled (slow)
  agentx hooks add [tool]         Install persistent hooks (gemini | hermes | antigravity | cursor | kimi | all)
    No tool: auto-detect the current tool, or add all outside one.
    Restart the tool after adding hooks to activate.
  agentx hooks remove [tool]      Remove hooks and legacy installs (claude | gemini | codex | opencode | kilo | pi | omp | hermes | antigravity | cursor | kimi | copilot | qoder | all)
    No tool: remove from all tools.
    Cleans both global (~/) and AGENTX_DIR-local hooks if set.
  Per-run: claude, codex, opencode, kilo, pi, omp, copilot, qoder
    Hooks load only in sessions launched with `agentx launch --tool <tool>`. Nothing to
    install; remove clears installs left by older agentx versions.
  Persistent: gemini, hermes, antigravity, cursor, kimi
    Hooks live in the tool's config; install them with `hooks add`.
  No hooks: grok
    `agentx launch --tool <tool>` gets status and messages over the tool's own connection.
  Without hooks, run `agentx start` inside any AI tool (manual delivery).

=== agentx reset ===
Usage:
  agentx reset                    Archive conversation, clear database
  agentx reset all                Stop all + clear db + remove hooks + reset config
Sandbox / local mode:
  If you can't write to ~/.agentx, set:
    export AGENTX_DIR="$PWD/.agentx"
  Hooks install under the parent of AGENTX_DIR; state stays in AGENTX_DIR.
    AGENTX_DIR=$PWD/.agentx -> $PWD/.claude, .gemini, .codex, .opencode, .kilo, .pi, .omp, .antigravity, .cursor, .kimi, .copilot, .grok
  To remove local setup:
    agentx hooks remove && rm -rf "$AGENTX_DIR"
  Explicit location:
    export AGENTX_DIR=/your/path/.agentx

=== agentx transcript ===
Usage:
  agentx transcript <name>        View agent's conversation (last 10)
  agentx transcript <name> N      Show exchange N
  agentx transcript <name> N-M    Show exchanges N through M (N- = to the end)
  agentx transcript timeline      User prompts across all agents by time
    --last N                       Show the last N exchanges (default: 10)
    --full                         Show complete assistant responses
    --detailed                     Show tool I/O, file edits, errors, token usage
    --json                         JSON output
  agentx transcript search "pattern"  Search agentx agents' conversations (regex), newest first
    --live                         Only currently alive agents
    --all                          Raw search of all transcripts on disk (needs rg)
    --limit N                      Max matching exchanges shown (default: 20)
    --agent TYPE                   Filter: claude | gemini | codex | opencode | kilo | pi | omp | hermes | antigravity | cursor | kimi | copilot | qoder | grok
    --exclude-self                 Exclude the searching agent's own transcript
    --json                         JSON output
  Tip: Reference ranges in messages instead of copying:
  "read my transcript range 7-10 --full"

=== agentx bundle ===
Usage:
  agentx bundle                   List recent bundles (same as bundle list)
  agentx bundle list              List recent bundles
    --last N                       Limit count (default: 20)
    --json                         Output JSON
  agentx bundle cat <id>          Expand full bundle content
  Shows: metadata, files (metadata only), transcript (respects detail level), events
  agentx bundle prepare           Show recent context, suggest template
    --for <agent>                  Prepare for specific agent (default: self)
    --last-transcript N            Transcript exchanges to suggest (default: 40)
    --last-events N                Events to scan per category (default: 10)
    --json                         Output JSON
    --compact                      Hide how-to section
  Shows suggested transcript ranges, relevant events, files
  Outputs ready-to-use bundle create command
  TIP: Skip 'bundle create' — use bundle flags directly in 'agentx send'
  agentx bundle show <id>         Show bundle by id/prefix
    --json                         Output JSON
  agentx bundle create "title"    Create bundle (positional or --title)
    --title <text>                 Bundle title (alternative to positional)
    --description <text>           Bundle description (required)
    --events 1,2,5-10              Event IDs/ranges, comma-separated (required)
    --files a.py,b.py              Comma-separated file paths (required)
    --transcript RANGES            Transcript with detail levels (required)
      Format: range:detail (3-14:normal,6:full,22-30:detailed)
      normal = truncated | full = complete text | detailed = tool I/O+edits+errors
    --extends <id>                 Parent bundle for chaining
    --bundle JSON                  Create from JSON payload (format below)
    --bundle-file FILE             Create from JSON file (format below)
    --json                         Output JSON
  agentx bundle chain <id>        Show bundle lineage
    --json                         Output JSON
JSON format:
  {
    "title": "Bundle Title",
    "description": "What happened, decisions, state, next steps",
    "refs": {
      "events": ["123", "124-130"],
      "files": ["src/auth.py", "tests/test_auth.py"],
      "transcript": ["10-15:normal", "20:full", "30-35:detailed"]
    },
    "extends": "bundle:abc123"
  }

=== agentx kill ===
Kill Agent processes
Usage: kill [OPTIONS] [TARGETS]...
Arguments:
  [TARGETS]...  Names, PIDs or "all"; omit to select local tracked processes
Options:
      --dir <PATH>  Discover the workspace containing this directory
      --workspace <PATH|global>  Select an exact workspace directory, or global
      --label <CONDITION>  Filter current local Agents by key=value, key!=value, key or !key; repeat to AND conditions
      --json  Print one JSON object describing every outcome
  -h, --help  Print help
Examples: agentx kill @NAME | agentx kill PID | agentx kill all
Filter the interactive picker: agentx kill --dir . --label project=atlas
The picker requires selection and confirmation. Filters cannot be combined with explicit targets.

=== agentx term ===
Usage:
  agentx term                     Screen dump (all PTY instances)
  agentx term [name]              Screen dump for specific agent
    --json                         Raw JSON output
      Fields: lines[], size[rows,cols], cursor[row,col], ready, prompt_empty, input_text
      prompt_empty/input_text are null when no composer is read (not parsed for this tool)
    --clean                        No status header or line numbers ([name] labels kept for all)
  agentx term inject <name> [text]  Inject text into agent PTY
    --enter                        Append \r (submit). Works alone or with text.
  agentx term debug on            Enable PTY debug logging (all instances)
  agentx term debug off           Disable PTY debug logging
  agentx term debug logs          List debug log files
  Instances pick up the toggle within ~10s.
  Logs: ~/.agentx/.tmp/logs/pty_debug/

=== agentx relay ===
Usage:
  agentx relay                    Show relay status
  agentx relay status             Show relay status
  agentx relay new                Create new relay group
  agentx relay token              Show join token for other devices
  agentx relay connect <token>    Join relay group
  agentx relay on                 Re-enable sync
  agentx relay off                Disable sync
    --all                          Also disable on all known peers
Setup:
  1. 'relay new' to get token
  2. 'relay connect <token>' on each device
Custom broker:
  agentx relay new --broker mqtts://host:port --password <broker-auth-secret>
  agentx relay connect <token> --password <broker-auth-secret>
Daemon:
  agentx relay daemon             Show daemon status
  agentx relay daemon start       Start the relay daemon
  agentx relay daemon stop        Stop the daemon (SIGKILL after 5s)
  agentx relay daemon restart     Restart the daemon

=== agentx update ===
Usage:
  agentx update                   Check for and apply updates
  agentx update --check           Only check — print status without applying
  Detects install method and runs the right update command:
    brew install    → brew upgrade agentx
    uv tool install → uv tool upgrade agentx
    pip install     → pip install -U agentx
    curl installer  → re-run agentx-installer.sh
