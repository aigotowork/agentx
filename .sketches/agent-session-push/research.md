# 研究记录

目标：一条已进入 AgentX 收件箱的消息，不等 hook、无需按键就能唤醒**正确的原会话**；忙时能排队，失败可判断，恢复时不盲目重发。先分清三个责任：AgentX 保存消息与身份，传输把事件送到一个接收端，宿主决定哪个会话执行下一轮。

- **待证假设**：一个 Agent 会话是否总有独占 MCP 子进程？即使有，向其发送数据是否能跨过 MCP 客户端直接进入对话？
- **对照实验**：真实 Codex 的自建 MCP server 推送与原生会话轮次控制；同一个 ACP 客户端对两个实际适配器使用同一组方法。用本地固定模型响应隔离开会话控制与模型能力。
- **文档与图**：协议按 MCP、ACP 拆开；方案看会话归属、改造成本与证据。图谱把四条路径排到一张图上，用“空闲 / 忙碌 / 断线”切换责任位置。证据等级不随示意动画变化。
- **不确定性**：普通 PTY 与托管会话不是同一个接入面；ACP 目录列出适配器不等于覆盖现有启动参数、权限和历史；收到响应、输入已记录、模型完结、对方产出业务回复分别记录。


本轮已完成：原生 MCP 对照、Codex 与 OpenCode 的 ACP v1、Codex 的 ACP v2 Preview 收录和重试，以及图谱桌面/移动端浏览器验证。精确条件和结果见[证据](evidence.md)。下轮待决定是否保留原生终端，以及优先验证哪个实际使用的 Provider；[候选方案](options.md)尚未成为实施决定。
