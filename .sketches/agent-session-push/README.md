# 怎样主动唤醒一个 Agent 会话

**AgentX 已经知道有信；缺的往往是把信交给正在等待的那条会话。** MCP Events 可以把事件主动推到宿主；ACP 能让宿主向指定会话提交一轮输入。把两者拆开，既能解释当下为什么等 hook，也能看清哪些接入方式真的可以去掉按键。

**最关键的反例**：同一个 Codex App Server 内，两条线程都拿到了探针 MCP 工具，但观察到的是**同一个 stdio 子进程**。给它发消息，子进程可以写出通知；Codex 没因此发起模型请求，通知也没进入随后显式唤醒的输入。另一方面，用同一份 ACP v1 客户端，在 Codex 和 OpenCode 上都能让指定的空闲会话继续，并保留各自历史。两项观察都可[复跑](evidence.md)。

**ACP v2 Preview 值得跟进**：Codex 适配器已在隔离实验中于模型完成前返回收录回执；同一幂等键在干净重启后仍指向同一条消息。这个结果只覆盖本次试验中的适配器和重启条件。

研究建议：**托管接入优先验证 ACP，现有 Codex 原生托管路径继续使用已知的 App Server 能力。** AgentX 内部已经有发信端和收件箱，没必要先把内部消息绕成 MCP；需要接外部事件提供方时，再把 MCP Events 作为入口。原生终端能否保留原会话，要逐宿主验证；改 Codex 源码是可行的备选，不是当前默认。
