已选定的解析顺序

      

        
1 · 显式 --workspace路径或 global，用户明确指定

        
2 · 显式 --dir 的项目根先找最近 Git 根；没有 Git 才找 AgentX 根

        
3 · AGENTX_WORKSPACE已绑定 Agent 用原生归属校准；global 也生效

        
4 · 调用 cwd 的项目根普通终端的当前目录

        
5 · 个人 workspace~/.agentx；与 AGENTX_DIR 的作用不同

      

      
cwd 单独解析：显式 `--dir` 用指定目录；未指定时，建议保留调用者当前目录。选 workspace 只改归属，不应顺带把 Provider 移到 workspace 根。

      
找不到项目边界：继续继承环境、查调用 cwd；最后使用个人 workspace `~/.agentx`。显式或继承的 `global` 表示明确无目录归属。

      

        
变更前
显式 workspace → 显式 dir 的 AgentX roles 边界 → 环境继承 → cwd 的 roles 边界。Git 不参与发现；dir 无边界时会成为 global。未指定 dir 时还会把 workspace 根作为 cwd。

        
已选定设计
显式 workspace → 显式目标目录的 Git / AgentX 根 → 隐式归属 → cwd 的 Git / AgentX 根 → ~/.agentx。cwd 独立：显式 dir 或调用 cwd。

层值责任

        
          
AgentX 原生记录adopted workspace已绑定 Agent 的权威归属；cwd 或可改环境变量不改它

          
Agent 进程环境AGENTX_WORKSPACE=路径 或 global向子进程传递默认值，帮助没有原生绑定的调用继承

已选定规则下的几个结果
        
调用方式默认 workspace结果

          
Agent A，不指定 dirA归属 A；cwd 仍是调用者 cwd

          
Agent A，dir 在 A 的 Git 中A 的 Git 根仍在同一团队；cwd 是指定目录

          
Agent A，dir 在 Git 项目 B 中B 的 Git 根新 Agent 加入 B；父 Agent 仍属于 A

          
Agent A，dir 在无边界的 /tmpA归属继承 A；cwd 是 /tmp/notes

          
Agent A，指定 --workspace A 和 dir BA归属 A；cwd 是 B

          
普通终端在 Git 项目子目录启动Git worktree 根归属在仓库根；cwd 保持当前子目录

        

      

      
Git、AgentX 项目根与个人锚点
        
建议把 Git worktree 根作为 Git 项目的 workspace：同一 worktree 下的子目录属于一个空间，不同 linked worktree 默认是不同空间；明确指定 `--workspace` 可以跨目录共享团队。

        
沿目标目录向上先找最近 `.git` 目录或有效 `gitdir:` 文件；没有 Git 时再找最近项目 `.agentx/` 或已有 `.agent-guides/roles` 边界。仓库中的嵌套 `.agentx/` 不会默认拆分 Git 团队，显式 workspace 仍可选择它。

        
项目 `.agentx/` 标记其父目录。个人 `~/.agentx` 是兜底锚点，其存在不会把整个 HOME 标记为项目；`$AGENTX_DIR` 继续选择 daemon / 数据库。设计位于 .docs/proposals/workspace-discovery.md；实际支持由 .controller/roles-workspaces/tasks/workspace-discovery.task.md 记录。
