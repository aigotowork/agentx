Rust、Workers 与 Durable Objects

编译与执行对象与存储消息与回执

Rust 怎样进入 Workers

先读上方构建链，再看虚线如何接到下方请求链。线上执行 Wasm 模块，生成的 JS 入口负责接收事件。

若已有 Linux daemon，要替换哪些部分？

保留可编译为 Wasm 的纯 Rust 规则。端口监听改成 fetch 事件，文件数据库改用存储绑定，Provider 子进程继续由 Linux 宿主管理。

同一名字怎样找到同一份数据

调用方从命名空间取得 stub；同一 scope 的请求到同一对象。内存字段可随实例释放，私有 SQLite 跟随对象身份。

为什么按场次建订座对象？

最后一个座位属于场次。让两个买家的请求进入同一对象，就能在一笔事务里决定座位归属。若按买家拆分，则需要跨对象协调。

消息在哪一步可以确认

先看发件方拿到回执，再看收件方领取与确认。每次写入数据库都是独立提交点。

如果收件成功，但确认前断线呢？

原 claim 继续绑定原收件实例。宿主恢复后查本地 Provider 接收证据，再按原 claim 确认；证据不明时保留待定。
