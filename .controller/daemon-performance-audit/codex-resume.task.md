The `dancingai` daemon logged 49.055 s and 49.764 s participant operations with zero queue wait. Their dispatch start times match two durable `mapu` creation events, and neither produced a runnable process. The native request deadline is 30 s. The stopped snapshot has one ordinary collision subscription and a gap of hundreds of events. The replay path bypasses the normal indexes and scans the entire KV table for each historical event, including request-watch scans on eligible transitions. Read-only SQLite sampling measured about 526,000 VM instructions per ordinary scan and 525,000 per watch scan. Old protocol-2 hosts also create a separate handshake/logging load; they do not enter the writer queue.

Keep reservation and replay atomic. The subscription index owns exact-key loading in existing row order; replay supplies only its eligible restored keys and reads their current values, preserving cursor, once-only, request-watch and reaction ordering. Normal event delivery keeps its existing selectors. Native observations identify the static resume/launch leaf operations. Verify the existing replay contracts and measure an isolated restore with hundreds of events and unrelated KV history before proposing any live scope changes. Physical SQLite commit latency and already loaded legacy hosts are separate operational work.

The retained baseline is byte-identical to the running `dancingai` daemon (SHA-256 `e576006af1b21da486e2c47c8b1cf2ebad9ac93adf693858bcd36111980fd64e`). Using the selectors from source with 105,000 unrelated KV records and two eligible keys, ordinary replay selection fell from 420,089 to 99 SQLite VM instructions, and watch selection from 420,024 to 46. Both replacement plans seek the existing KV primary key. The managed launch still checks the Codex version and, on a hook trust cache miss, starts a Codex app-server to discover hook hashes before spawning the terminal Provider; the direct command skips these steps and the SessionStart callback.

The separately observed protocol-2 traffic came from 16 retained PTY processes loading a deleted older executable. Replacing the daemon or executable pathname does not move their in-process code. Preserving those sessions requires an exact host migration, following the [previous migration evidence](pty-turn-completion.task.md) and verifying stored sessions, current process identities and inbox cursors before any retirement. A rollout of this fix can switch only the `dancingai` daemon via the candidate's authenticated `daemon restart --scope` command, verify the same generation and all preexisting host tuples, and use the [previous immutable binary](../../.artifacts/pty-turn-completion-20261120/agentx) for per-scope rollback.

The [controlled Provider comparison](../../.artifacts/dancingai-resume-repair/comparison.jsonl) exercises the public CLI, real daemon, SQLite, tmux, daemon-managed PTY and the generated SessionStart command. The test uses 105,000 unrelated KV entries, 745 missed events, a saved collision subscription and fresh caches. Old and candidate both resume the exact synthetic session. CLI return is 13.823 s → 0.302 s, Provider start 13.883 s → 0.366 s, and SessionStart completion 13.919 s → 0.408 s. Direct controlled Provider start is 89 ms and 76 ms. The baseline writer spent 13.189 s in dispatch with no initial queue wait and later forced an Inspection request to queue for 4.631 s; 8.787 s was attributed to subscription candidates alone. The candidate produced no slow dispatch records. These are local controlled timings, not deployed or real Codex startup timings.

The [versioned optimized candidate](../../.artifacts/dancingai-resume-repair/agentx) has SHA-256 `d8fff87c8822a9fb2b8aa3a29820dd4037ef78e0298e56504c91eb750175b672`. It was built from the working source with release optimization, without LTO and with 16 codegen units to avoid the long single-unit link. [68 focused native tests](../../.artifacts/dancingai-resume-repair/native-tests.log) passed, including exact reservation/retirement fences, once/cursor behavior, on-hit ordering, Antigravity request-watch grace and the bounded-work regression. The fixed candidate also passed [three managed Codex PTY cases](../../.artifacts/dancingai-resume-repair/pty-tests.log): daemon reconnect with pending mail, exact failed-session recovery, and delivery after a missed Stop callback.

## Local adoption

After the user's approval, the exact tested candidate was [installed by atomic rename](../../.artifacts/dancingai-resume-repair/rollout-install.json) at `~/.local/bin/agentx` as version `0.7.31`, native build `native-build-v1:9a32a24e-0e31-4af6-a637-3267481f9255`. Authenticated restart switched the seven ordinary persisted scopes: [dancingai](../../.artifacts/dancingai-resume-repair/rollout-dancingai.json), [xsaas](../../.artifacts/dancingai-resume-repair/rollout-xsaas.json), [uiux](../../.artifacts/dancingai-resume-repair/rollout-uiux.json), [template-project](../../.artifacts/dancingai-resume-repair/rollout-template-project.json), [xschema](../../.artifacts/dancingai-resume-repair/rollout-xschema.json), [home](../../.artifacts/dancingai-resume-repair/rollout-home.json), and [agentx](../../.artifacts/dancingai-resume-repair/rollout-agentx.json). Each loaded the exact installed image, retained its database generation and answered a native Agent names query. All 153 tracked Agent/PTY PID and start-tick identities were preserved. The home and AgentX Management listeners at ports 38000 and 38023 returned HTTP 200. The stopped `mapu` session was still queryable; no live resume was launched as part of rollout.

The fixed-version Observability demo, temporary scopes (including isolated Relay), the legacy checkout-root owner without a database, project `.bin/agentx`, and already-running Agent hosts were preserved. The old installed binary remains at `~/.local/bin/agentx.before-dancingai-resume-repair`. To roll back only one running scope, invoke that backup with `daemon restart --scope <exact-scope>`; to roll back the installed executable as well, stage a copy of the backup in the same directory and atomically rename it over `~/.local/bin/agentx`. Neither action needs a database restore or an Agent termination.
