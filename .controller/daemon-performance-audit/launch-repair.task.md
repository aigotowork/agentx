# Fresh launch hot-path repair

Implement the first correction from the [audit](launch-audit.md): keep name, receipt, and subscription authority unchanged, but stop scanning unrelated history on fresh reservation and bootstrap. The daemon installs small derived SQLite indexes alongside its existing optional indexes; failed setup leaves the original selectors available. Avoid a new persistence model or wire protocol. Names reads a narrow current-name projection and an index covering retained stopped names. Subscription storage seeks existing KV by exact owner, while keeping the existing cleanup predicates and delivery memberships. Keep historical/malformed data from blocking index installation or silently bypassing existing cleanup errors. Validate production query paths and work reduction against disposable data, then package an isolated candidate and compare to the installed binary. The later explicitly authorized service transition is recorded below.

The [name selector](../../src/db/launch_names.rs) serves both allocation and bootstrap. It deliberately retains both reads at their existing authority points, making each read cover only stopped-name candidates instead of caching a possibly stale name set across requests. The [owner selector](../../src/db/subscription_index.rs) keeps the original LIKE/JSON predicates as residual checks; its optional index uses deterministic expressions and does not change schema epoch or protocol. A malformed life event fails name allocation closed; malformed subscription rows keep the existing cleanup error. Codex preflight and wait policy remain separate follow-ups.

The [retained offline snapshot comparison](../../.artifacts/launch-performance-audit/snapshot-production-selectors.jsonl) ran the production SQL against a disposable copy with 1,633 reserved stopped names and 103,833 KV records. On that sampled run, stopped-name selection was 41.84 → 2.96 ms (49,300 → 13,800 VM instructions at 100-instruction resolution); ordinary and delivery membership cleanup changed from 34.22 and 31.72 ms to 0.148 and 0.116 ms. The two cleanup queries went from approximately 416,100 instructions each to fewer than 100 for a name with no matches. The result sets and deletion counts matched; the cleanup was rolled back. First creation of both indexes took about 186 ms on that copy. Do not extrapolate the cold-disk cost or live latency from this snapshot sample.

`just test --bin agentx -- launch_` passed 294 native cases with one ignored and zero failures ([log](../../.artifacts/launch-performance-audit/native-tests.log)). The two new cases run the shipped selectors through bundled SQLite, assert the same reserved names and cleanup effects, and require an over 20× drop in VM work on unrelated history. They also exercise malformed legacy rows and verify that retained delivery-only memberships are not removed by ordinary cleanup.
