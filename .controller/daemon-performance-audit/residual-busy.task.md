After adoption, home showed 64 queue refusals among 50,602 decoded calls. At sampling both queues were idle. A later retained journal slice contained 515 DeliveryPoll and 458 generically labeled Messages calls with no Busy records. Separately, a two-minute log slice showed 480 protocol-2 Hello failures from one still-running host and about 93 repeated not-idle messages each from four compatible hosts. Hello refusal does not reach either application queue; the old host requires deliberate session migration. No live Agent lifecycle action is part of this repair.

A broader retained post-release log slice contained explicit `service unavailable: daemon is busy` on 77 home and 72 project PTY snapshot failures. They arrived in bursts, including 38 home and 25 project failures in the same one-minute bucket. That establishes PTY callers were affected, while the existing aggregate metric cannot distinguish a full read channel from the pre-decode connection cap. Compare exact lane and operation after deploying the diagnostic.

Keep the existing queue sizes and wire protocol. Record pre-decode connection saturation separately from queue refusal; for the latter record the exact operation and selected lane through the existing asynchronous logger. On the PTY host, wait longer only when Codex's hook-owned state says it is not idle, and allow existing wake notifications to interrupt that wait. Do not repeatedly send a blocked-gate update the daemon cannot apply to a non-listening row. Local input/screen gates, pending model recovery and the fresh participant/cursor checks before Enter retain their current timing and authority. Coalesce frequent PTY heartbeat writes after exact registration validation; preserve endpoint repair and the poll checkpoint.

Verify a full read queue still refuses only work for that lane while writes work, logging the exact refused operation. Exercise the blocked-gate cadence and writer-side no-op semantics in a disposable fixture. Capture live observations separately from source and test evidence.

Twelve selected native cases passed. The saturation fixture held the Management reader and found a read-lane `admission.busy` record for `AdoptedWorkspaces` while a writer request completed. A SQLite trigger proved a repeat PTY heartbeat did not update the timestamp; validation, renewal after staleness, TCP-presence repair, and the existing poll checkpoint/registration fence cases passed.

The four compatible `not_idle` hosts all had a latest Codex transcript `task_complete` whose turn ID matched the stored model turn. Their AgentX status remained `active / model:request` for hours or days. Three stored request phases were still `started`; one was `completed`. This distinguishes missing lifecycle state from four ongoing model turns. Stop and PostModelRequest were declared in the observed launch/account configuration; the retained operational log does not establish whether Codex skipped the callback, an old callback failed, or AgentX ignored it. Diagnose that gap separately from queue refusal. No age, current-screen or transcript-only observation changes participant state in this patch.

The read-only covered mailbox route projection showed 16 eligible directed events across those four blocked participants (3, 2, 7 and 4). The protocol-2 host had no eligible events in that sample; its retry pressure is independent of this pending backlog. Do not resend or advance receipts as part of lifecycle diagnosis.

Follow-up completion reconciliation should keep provider evidence on the terminal owner side, outside SQLite dispatch. First reproduce a lost or rejected Stop callback. Recover on an exact same-session terminal turn only when the daemon can condition on the unchanged participant, session, turn, current status and latest observed activity. Preserve unresolved model errors and approval/exit states, and fail closed when a newer turn or user input makes the evidence ambiguous. Exercise the real wake and mailbox receipt after reconciliation, plus late/duplicate completion, no completion, successor, approval and error exclusions. Do not turn an ordinary quiet-screen timeout into a lifecycle transition.
