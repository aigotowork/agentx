The PTY host owns timer jitter and reads bounded Codex rollout evidence only for pending mail at a safe prompt. A complete latest root turn with the exact session and turn is required, and the local screen/user-input evidence must not change during the read. The daemon independently checks the exact process registration and compares the current active model state to the observed session, turn, phase, progress timestamp, status time and mailbox cursor before recording listening. This does not clear model errors, complete model requests, confirm mail, or authorize Enter. The ordinary delivery path checks the current gate again before injecting and submitting.

The normal idle timeout is randomized from 25 to 30 seconds, keeping its original upper bound and the 35-second TCP health threshold. Wake notifications still interrupt the wait. An active Codex host can read the root rollout at most once every five seconds per delivery loop and only for an eligible pending gate. The budget is a 64 KiB header and 256 KiB tail; malformed, changing, incomplete, newer-turn or mismatched data fails closed. No rollout I/O enters daemon dispatch.
