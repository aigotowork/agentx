# Restore reliable Space message history

The exact Agent history endpoint can exceed the native two-second read budget while expanding JSON recipients for unrelated messages. The first successful history read gates sending, so a 503 blocks the conversation. Fix native examined work without changing the public HTTP or SDK contract, browser workflow, exact identity, or delivery receipts.

Keep the immutable event journal authoritative. Hook unread routing uses `scope`, `mentions`, and broadcast eligibility; it cannot answer message history, which uses the routing `instance` and actual `delivered_to`. Add a rebuildable conversation projection keyed by participant and event ID. Plain SQL triggers maintain it transactionally on insert/update/delete, including writes by older binaries. Start it additively on the daemon writer and fill pre-existing IDs in bounded idle transactions. Consult indexed membership only if the entire requested ID window is covered; otherwise keep the journal path. Preserve timestamp/exact-incarnation bounds, cursor order, payload budget, attachment links, and sender/recipient semantics. Leave read deadlines and daemon generation unchanged.

Use the existing event row pager for both routes so byte-limited and count-limited pages retain the same continuation behavior. The index remains private to native storage and never becomes a second source of message content. Verify cold fallback, steady-state sparse history, append/delete/reset and resume boundaries in disposable scopes. A packaged candidate must pass real browser conversation journeys and shared service smoke checks before considering any live transition. No production operations belong to the verification assignment.

Space checks `Agent.snapshot()` before loading or sending messages; roster and detail supply `pending_messages` via the existing unread count projection. Use the same covered participant keys to select candidates for those counts, then keep the original actual-recipient array check and per-Agent delivery cursor. Sender-side history alone never increases unread. This avoids the same wide scan on the neighboring browser request without changing unread authority or automatic delivery.

The rollout must distinguish process readiness from backfill completion. Uncovered windows still use the journal and may hit the original read budget. Wait for `db/conversation.index_ready` for a newly backfilled scope, then repeat exact message reads before declaring the incident resolved. No journal, generation, runtime protocol, HTTP schema, SDK contract, or browser state migration is required. An older executable can continue to write through the plain SQL triggers; reverting the executable does not require deleting the additive tables.
