# Verify sparse message history via HTTP

Own the reusable independent scale / consumer check for the Space release blocker. Prepare it while the controller implements `src/` changes. Use a disposable AgentX daemon and fixture Provider (see `.controller/space-ui-styles/style-library/native-check.py` and `tests/live_ui_integration/live_fixture.py`). A new run should exercise initial exact-Agent history, pagination and incremental append after many unrelated native message events; distinguish cold index construction and steady-state with bounded waits. Share any better design or constraints early. Keep all writes to the test script and this Task, with results in a new `.artifacts/space-domain-sdk/` directory. Use private data, processes, and non-default loopback ports only. No live service writes, other agent operations, dependency installs, Cargo builds, or changes under `src/`. Controller will prepare and run/hand off the valid binary; a baseline run is valuable if it can finish quickly. Report the finite evidence and any remaining limits. Preserve exact current/stopped addressing and publicly observable responses; private fixture seeding is acceptable only with the daemon safely stopped or using a separate copy, and must never touch production files.

## Fixture model

[The runner](verification/history-scale.py) uses a digest-pinned legacy binary to launch a real disposable Qoder hook fixture. After the Provider acknowledges a pause and the private daemon stops, the test reserves unused journal IDs. The legacy binary restarts to stop the Agent normally, producing a public stopped-event reference after the reserved IDs. The runner then seeds native message rows within those unused IDs while the daemon and Provider are stopped. The candidate migrates that stopped history without relying on a live Provider surviving backfill. Read-only private coverage samples distinguish startup from steady state. The oracle uses public HTTP responses, original operation receipts and an actual generated-hook reply. Run outputs retain request evidence, private logs and timings; private processes and seeded storage are removed after successful cleanup.

Eight small matching rows exercise routing sender and actual recipients separately, with misleading display sender, mentions, and pre-incarnation rows excluded. Thirty-six long rows exercise count and byte limits without exceeding the native per-message limit; the test forwards cursors verbatim. After coverage the runner checks exact stopped history and then resumes the same name into a new exact incarnation. It verifies workspace, current roster, exact detail and actual-delivery pending counts, an initially empty current history, send/read-after, attachment byte equality, and the unchanged stopped history. The optional maintenance pass verifies update/delete against the stopped journal and a native private reset through public HTTP generation fences. The first unindexed full scan and a smaller cold read are separately reported: a transient bounded failure under scale is a startup availability limit.

## Run and evidence

From the repository root, on Linux with Python 3.11+ and the digest-pinned pre-projection `.bin/agentx-space-domain-sdk-r1` bootstrap:

```sh
python3 -B .controller/space-domain-sdk/verification/history-scale.py \
  CANDIDATE EXPECTED_SHA256 .artifacts/space-domain-sdk/NEW_RUN \
  --maintenance
```

Use a fresh evidence directory per run. The default is 750,000 unrelated rows, with up to 150 seconds for background coverage after the startup probes and 1,500 ms per steady history read; override with `--noise`, `--coverage-timeout` or `--steady-ms`. Alternate pre-projection binaries require `--bootstrap` and `--bootstrap-sha256`. Exit 0 means pass, exit 2 means the initial full read returned the native bounded interrupt, and exit 1 represents other assertion or infrastructure failure. `--allow-cold-unavailable` relaxes exit 2 only for a candidate that passed every later check; it does not change the recorded startup result. See `report.json` for timings and cursor outcomes, `manifest.json` for owned process cleanup, and numbered HTTP JSON files for raw public observations. Runtime and SQLite writes use only a disposable home/scope on an ephemeral loopback port.

The pinned [legacy scale run](../../.artifacts/space-domain-sdk/history-scale-baseline-750k-20261121/report.json) reproduced the failure: HTTP 503 `Error code 9: interrupted` at 1,317 ms for the exact `limit=20` open; an adjacent two-row prefix returned HTTP 200 at 4.36 ms with continuation. The [legacy 1,000-row check](../../.artifacts/space-domain-sdk/history-scale-baseline-maintenance-smoke-20261121/report.json) passed, including the 42+2 byte split, original send receipt and Provider reply, exact stopped/resumed fences, and maintenance. Both scopes and processes were cleaned. An early smoke established that public history retains an attachment notice after the original text and that Qoder's reply to the human mailbox returns an empty Agent recipient list; the oracle now checks both wire behaviors.

The repair owner handed off frozen Linux development candidate `.bin/agentx-space-history-r1`, SHA-256 `440d1141359e2a6b7bdd1e5f9ff1dae0b20dc04e032b5de70c9db62767e6b265`. The [first candidate run](../../.artifacts/space-domain-sdk/history-scale-candidate-20261121/report.json) saw cold `503` in 2,096 ms, cold prefix `200` in 15.74 ms, and completed coverage in 95.77 s, but the original fixture Agent became stale before the steady read. A private snapshot shortened the daemon switchover and [passed at 1,000 rows](../../.artifacts/space-domain-sdk/history-scale-candidate-1k-r3-20261121/report.json). At [750,000 rows](../../.artifacts/space-domain-sdk/history-scale-candidate-750k-r2-20261121/report.json) it still lost the original Agent; the retained private logs show a 15 s generated Stop-hook subprocess timeout, a 22.8 s `PrepareOutput` dispatch and a 17.6 s queued delivery heartbeat ending at a stale fence. These trials do not prove live Agent continuity during backfill. The final stopped-history fixture avoids that dependency while exercising real current Agent actions after coverage.

The [final fixture at 1,000 rows on R1](../../.artifacts/space-domain-sdk/history-scale-candidate-1k-r5-20261121/report.json) passed all cases, including the requested exact current detail, current roster, and workspace reads. Both current surfaces reported five unread messages according to actual delivery; duplicate recipient entries did not double the count, and sender-only history did not add unread. The [final fixture at 750,000 rows on R1](../../.artifacts/space-domain-sdk/history-scale-candidate-750k-r3-20261121/report.json) confirmed the history repair after 103.15 s of startup and backfill: the cold open returned `503` in 2,021 ms, while the post-coverage exact stopped open returned `200` in 329 ms and count and byte continuations passed. The current roster following resume still returned `503` in 2,019 ms, so the full R1 workflow failed at scale.

The [750,000-row development R2 run](../../.artifacts/space-domain-sdk/history-scale-r2-750k-20261121/report.json), SHA-256 `4a5fa736c6c4a45645425f5d8e8598cc9d5d08b977f519ef8f5d4eb7fbc27c07`, reached the cold exact stopped open (`503` due to native interrupt in 2,214 ms) and the two-row cold prefix (`200` in 77.57 ms with continuation). Coverage was incomplete before both observations (17,408 before open; 34,816 of 750,053 after the prefix). The user stopped scale work while the runner was waiting for full coverage. R2 steady history, detail/roster/unread, append, and maintenance were not reached. [Cleanup](../../.artifacts/space-domain-sdk/history-scale-r2-750k-20261121/manifest.json) terminated all three owned daemon instances without errors, verified the frozen binary remained unchanged, and removed private fixture data. The assignment closed at the user's direction without R2 acceptance. No further scale runs or builds were started, and no live or Space service was changed by this assignment.

The fixture result applies to Management HTTP and does not establish Chromium behavior, full native suite coverage, production data migration duration or installed/live adoption.
