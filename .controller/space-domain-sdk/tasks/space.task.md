## Owned structural decision and current status

The public SDK supplies a pinned listener/scope/generation, discovery and exact Workspace/Agent handles. Space continues to own the single selection and exact draft/channel state. These are the source boundaries for the selected implementation:

| Module / contract | Responsibility and effects |
| --- | --- |
| `live/host.ts`, `main.tsx → App` | An explicit `SpaceHostBinding` from `VITE_AGENT_SPACE_MANAGEMENT_URL`, `VITE_AGENT_SPACE_EXPECTED_SCOPE`, optional `VITE_AGENT_SPACE_PAGE_LIMIT`. A present binding takes priority over query-based legacy and demo modes. An incomplete/invalid binding or rejected scope has an explicit Retry; no alternate endpoint, catalog or Agent read before the pin. The same pinned listener backs ancillary Management calls and original receipt recovery. Generation/scope replacement disables the old session; deliberate reconnect remounts Space and drops its old route target, drafts and view state. |
| `live/domain-office.ts` | One disposable scoped reader adapter. Private SDK handles/cursors; bounded discovery separately from an active Workspace exploration and separately from an exact reader. A single page updates first-seen observations, coverage and continuation together. One initial snapshot and forward message page per exact opening; one page per explicit continuation. Workspaces and reader sessions abort/ignore superseded requests. Failure keeps prior records and exact identity. A separately resolved exact subject can open a reader without counting as a roster observation. |
| `live/controller.ts`, `live/projection.ts` | Compose the selected Workspace read provider or legacy feed once per office, translate SDK snapshots at the current projection seam, and keep live actions, receipts, launch relations, Provider and human activity with their existing owners. SDK-roster admission is never write capability; the current address must still be reverified before deliberate Send via the existing journal path. |
| `SpaceController`, `App`, `SceneSpace`, `HallScene` | One `openConversation(exactKey, origin)` intent for the named actor, directory, list or resume. Scene mounts use their current Hall projection/presented input for actor validation; app checks membership in the current roster before accepting an interaction. Existing room, actor, prop and presentation values retain ownership; neither Canvas nor diagnostic object IDs become Agent addresses. The frame/clock/runtime are reused. View-only memory covers exact channel scroll, workspace/list return and camera. |

## Completed source and evidence

- Host: the [usage](../../../web/agent-space/README.md#工作区-sdk-接入) describes the opt-in pair and optional sparse page size. The SDK pins the exact listener/scope/generation; a confirmed replacement freezes the old read state and blocks the journal eligible actions. Explicit reconnect remounts the page, drops the old exact route and draft state, and notifies existing location consumers. Wrong scope stops after describe.
- Page: [DomainOfficeReads](../../../web/agent-space/src/live/domain-office.ts) owns typed cursors and one cancelable exploration/reader each. [LiveSpace](../../../web/agent-space/src/live/controller.ts) atomically publishes observed membership and coverage separately from route-only reader subjects. [SpaceController](../../../web/agent-space/src/offline/controller.ts) owns selection/draft revisions; the UI accepts one exact-key intent from the actor, named directory and list. Forward append leaves scroll in place, and the already open reader retains records and scroll when switching modes. Back and reopen restore the addressed draft; a new open performs a fresh bounded initial read, so reloading a previous later page still takes a continuation.
- Canvas: [scene mapping](../../../web/agent-space/src/scene/AGENTS.md) documents Room → Actor/Prop using the existing Hall projection and one presented frame. Actors are keyed by exact card, cabinet uses room/slot, and the human anchor stays outside the roster. The SDK removes raw cursor/discriminator bookkeeping from Scene and makes the choice of open-intent, membership and layout owners visible; the bridge still has to project a global scan subset and retain a distinct exact reader subject. A second object graph would duplicate frame membership and identity without improving authority or presentation.
- Camera: first [independent candidate](../../../.artifacts/space-domain-sdk/run-01/report.json) uncovered a narrow return after resize where center-preserving translation left the selected actor clipped. The return path now preserves zoom, reframes only a clipped axis and owns focus restoration once. A current-source Chrome replay returned the exact actor to (195, 327) inside the 390×844 viewport after a desktop zoom, retained scale 0.9567636986, and keyboard Enter reopened the same draft with zero effects. The built follow-up independently passed the corrected path; the narrow controls lose the duplicate Resume entry when the actor or row is already reachable.
- Verification: scoped typecheck and 36 focused adapter, route, context, relation and scene/runtime cases passed; `git diff --check` is clear. A long-record Chrome probe found the old History tail-follow jumped on explicit forward append (1136 → 2331); the fix disables tail-follow in the scoped reader only. The [final independent build](../delivery.delivery.md#independent-verification) verifies this fix together with the other seven browser cases, with zero writes, request violations or page errors.

Existing :38000, :38023 and other services were preserved. The legacy/demo preview is [18983](http://192.168.2.178:18983/?supply=demo); the temporary configured dev port 18984 was used with Playwright-intercepted synthetic requests in probes. No release or live rollout, real Provider/send acceptance, or independent native listener claim is made. Durable command dispatch remains on the existing journal/capability path rather than the SDK write ports.
