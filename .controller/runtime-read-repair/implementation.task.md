## Implemented structural refinements

The compact native `AdoptedWorkspaces` projection preserves the previous first1000 current-name/stopped-desc ordering and coverage while extracting only launch contexts. Management calls the shared fallible unread batch in `service::queries_store::listing`; ordinary native listing retains its previous fallback wrapper. Linux self reexec pins the loaded image into a private per-build cache only if the original pathname is gone; a `/proc/self/exe` spawn alone was rejected because downstream launcher steps also need an existing `current_exe()` pathname. This cache is not pruned automatically while Agents may still reference it.

Worker supervision is isolated in `service/supervision.rs`. Stderr is drained with bounded16KiB retention and bounded cancellation, credentials from sensitive environment keys are redacted in that private diagnostic, and raw stderr is never put in public receipts. Input writes are cancellable on Unix rather than leaving an unbounded detached writer after timeout. Windows pipe cancellation is authored but Linux is the execution platform for this delivery. Existing Unknown semantics remain unchanged.

Two later proportional refinements preserve the intended contracts: compact workspace deduplication retains first occurrence before the existing100-workspace admission cap; recent-log reads stream rotations into a bounded top-limit map instead of accumulating all retained events. Direct Inspector `?ref=` selection performs one exact SDK GET when the selected record is not in the loaded page, rather than reviving full-history collection. Independent cases cover these corrections.

Always-on native dispatch error/slow classification supplements optional Observation, reusing its safe static OperationLabel and ServiceFailureClass. HTTP diagnostics distinguish admission from native unavailable/unknown outcomes and correlate the returned x-request-id with the scoped log. Successful calls below500ms are not access-logged. Existing JSONL logging gains a stable cross-process rotation/append lock and explicit-scope writes; no second logging backend or payload tracing is introduced. Operational usage and retention belong to [runtime diagnostics](../../.docs/architecture/runtime-diagnostics.md).
