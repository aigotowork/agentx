The project incident separated SQLite commit, post-commit subscription work, and slow Management reads. Subscription indexing now defaults on in current source and retains its own rollout evidence. This follow-up owns the independently observed human mailbox scan and dispatch diagnostics, including their consumers in OfficeActivity and the native daemon. Preserve exact generation/participant fences, native wire types, and durability. Live replacement is tracked separately.

| Responsibility | Contract |
| --- | --- |
| Database / human addressing | Persist only derived human-addressed event IDs. Triggers maintain IDs under the same transaction; backfill old events in bounded idle batches using the exact shared address predicate. Until coverage is complete the original query supplies the full view. Events and generation-keyed handling records remain authoritative. Bookkeeping never changes delivery or read receipts. |
| Management mailbox / office | Count from derived IDs, join event payloads only for the requested page, seek by before-cursor. Generation checks on reads must use a read of the retained key, not the creating helper's write transaction. |
| Daemon / diagnostics | Queue only the existing sanitized diagnostic fields to one finite best-effort log worker. A blocked filesystem or full diagnostic queue must never hold a dispatch reply or its successor. |
| Dispatch isolation | Keep one writer; isolate demonstrably read-only heavy Management calls under a bounded independent lane. SQLite read transactions must verify the durable generation inside their snapshot and reject a changed generation before returning. No fallback into the write queue when the read lane is full. |

Verify legacy and indexed page/count/handling parity, transaction rollback and changes, no startup-wide mailbox rebuild, and behavior under a held log or Management read. Keep unavailable and unknown outcomes distinct. Report remaining limits under physical storage stalls separately from queue amplification.

In-memory SQLite workload comparison using the actual SQL: 60,000 message events, 600 addressed to `bigboss`, both count queries returned 600. The legacy count executed approximately 1,210,200 SQLite VM instructions; the indexed count executed approximately 10,200. This measures query work, not production response time. A separate 272,000 unrelated KV row fixture with 180 subscription/watch rows used about 1,092,500 instructions for the old subscription selector versus 3,700 indexed; the due-watch lookup used about 1,088,900 before and fewer than 100 after. The indexes are already default in the current startup source; this does not verify their adoption on a running binary.

The final Linux build passed 37 focused Rust tests: a native IPC Management request held at a barrier while a Participants request returned; a WAL read saw only committed mail while the writer held an uncommitted append, then rejected a changed durable generation; mailbox pagination, malformed historical rows, handling, rollback and trigger updates retained the intended results. The same run covered file bindings and dispatcher/observation regressions. The dispatch log worker was validated by code path and compilation; no kernel I/O hang was induced. No installed executable, active daemon, database, or Agent host changed.

Potential follow-ups once the isolated source candidate is adopted on a selected scope: batch or index `delivered_to` membership for roster unread counts if they remain hot; measure SQLite commit versus checkpoint time before changing WAL policy; separately profile the first subscription index build on cold disk. The reader prevents unrelated Management work from blocking the writer; a physical disk stall can still hold a required SQLite commit or a reader syscall. SQL instruction deadlines cannot interrupt a kernel I/O wait.

## Integration follow-up

Implement the [isolation proposal](../.docs/proposals/daemon-request-isolation.md) on the existing reader/PTY work. Keep the read-only WAL snapshot and writer authority. Move first-page cleanup off HTTP demand to one bounded periodic Management maintenance loop using the existing reaper and commit-before-apply effects. Own file discovery and the assignment index on one bounded background worker; Management Agent views read its published exact-assignment snapshot, while explicit file-binding queries request fresh data with a bounded wait. In Space reuse the OfficeActivity mailbox prefix whenever it proves the requested head page; preserve the exact pending filter/cursor and fetch only when that prefix is insufficient or the user changes filters/pages. Record distinct native sub-operation labels. Verify using target fixtures and synthetic contention before any project replacement.

Implementation and initial evidence: the source removes synchronous cleanup and file scanning from regular list pages, queues Management HTTP diagnostics, records native sub-operations and dispatch lane, and owns a composable SQLite progress budget so nested label reads cannot clear the outer limit. Space's real controller passed four scope, pagination, and mailbox-consumer cases plus TypeScript checking. The held-reader test sealed a full read queue before proving a native business call could still complete, while a WAL fixture verified committed visibility and generation rejection. The first release candidate passed real managed Hook delivery and answered an invalid HTTP request and a native list with the log's exclusive file lock held; the installed baseline timed out on the HTTP request under the same lock. A 20,000-event, four-client comparison measured Hook p95 99.4 → 11.1 ms, mailbox 208.3 → 35.9 ms, and Agents 269.0 → 58.9 ms; see [receipt](../.artifacts/daemon-isolation-integration-20261120/same-workload.json). This finite sample has no production latency or saturation guarantee.

The first package exposed a scope-first query-plan regression in the concurrent names/workspace query: the strict workspace type expression suppressed the existing expression index. The corrected selector uses the original seek expression plus a residual type guard, requiring no index rebuild. [Isolated plan evidence](../.artifacts/daemon-isolation-integration-20261120-r2/workspace-index-probe.txt) shows the existing index is used and array/malformed history remains excluded. The previous release and first candidate both pass the binding projection cases through B08 and fail the same B09 launch-compensation fixture; this is retained as a pre-existing failure, not a candidate-only regression.
