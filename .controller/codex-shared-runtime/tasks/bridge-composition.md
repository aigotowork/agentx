### Routing and lifecycle invariants

- Keep downstream pending requests separate from native server requests. Remap every outer and internal downstream request through one monotonically allocated ID namespace; retain the exact outer ID JSON type/value. Forward native server request IDs and nested `serverRequest/resolved.requestId` unchanged.
- Preserve unknown payload data with raw JSON at the forwarding boundary; inspect only the envelope and required lifecycle fields. Every stream has one writer. Output contains native protocol frames only; diagnostics use stderr.
- Initialize and subscriptions belong to each connection. Preserve clientInfo and capabilities; remove internally required notification methods only from the native opt-out list, retaining the original list as the outer filter. No internal input before both handshake halves finish.
- Root qualification comes only from a correlated successful outer start/resume/fork result. Unsolicited started, read/list/history and native internal/ephemeral work do not reserve or replace an AgentX identity. Commit the attachment before releasing success to the caller.
- Bridge ownership is per proxy (`AttachmentOwnerId`), backend generation is per service, and `BindingId` fences activation and receipts. Disconnect may retire only this proxy's attachments; it cannot revoke a sibling proxy or terminate the service.
- Freeze the actual `PreparedBatch` and correlation ID before issuing. Persist Issuing before a possible native write. A matching recorded userMessage must match thread, client ID and frozen actual content; successful RPC, assistant output or completed turn alone never acknowledges delivery.
- Prioritize arrived user controls before internal scheduling. Approval/input requests block automatic injection; cancellation/archive/unsubscribe and unknown possibly mutating methods require a fresh reliable state. Never transform user start into steer or use an empty marker as a lock.
- A dropped response/write ambiguity retains an uncertain claim. Late internal responses stay internal even when an earlier event confirmed the batch. Rebinding, EOF and service generation changes cannot make old receipts commit to a new attachment.

### Concrete interface dependencies and ambiguity

1. Service connection must support bounded/pollable reads plus native writes while user responses and cancellation remain serviceable; its drop semantics must disconnect only this client.
2. Root registration needs preparation data for launcher ancestry/cursor/args and identity context, with a transaction that handles canonical resume and live-owner conflict. Exact reservation timing must follow the published API rather than a bridge-local duplicate identity model.
3. Hooks need an explicit shared-service marker and backend generation/home; tools need per-session environment merged into existing caller shell policy without replacing unrelated config. The root participant must be available before composing identity exports, or tool identity must resolve solely by generation/home/thread.
4. The current launcher marks `name_announced=true` before a fixed launch bootstrap and its cleanup finalizes one process binding. The shared path must bypass both assumptions and use per-root flushed announcements and owner-scoped cleanup.
5. Native app-server detection must parse command-position options rather than test whether any arbitrary argument contains `app-server`; `generate-*`, daemon management, proxy and non-stdio listeners need explicit classification so they do not enter a JSONL bridge accidentally.

## Protocol implementation structure

The production declarations in [`protocol.rs`](../../../src/integrations/codex/protocol.rs) own exact public types. Private protocol leaves divide raw envelope handling, the two independent request ledgers, routing, and connection handshake/subscription observation. `RawObject` stores ordered fields with `serde_json::RawValue` values; rewriting the envelope ID never parses or reconstructs opaque nested content. `ProtocolRouter` allocates every client request ID, restores only outer responses, returns internal responses to its caller, and tracks native requests independently. Native server IDs and embedded resolved IDs are never rewritten. `ConnectionHandshake` virtualizes only required notification opt-outs and grants readiness after successful initialize plus forwarded initialized; root qualification and turn arbitration remain bridge-owned.

Independent acceptance/oracle details now live in [`acceptance.md`](../../../.docs/codex-activation/acceptance.md); protocol counterexamples are supplied by integration's [`codex_shared_vectors.json`](../../../tests/support/codex_shared_vectors.json).
