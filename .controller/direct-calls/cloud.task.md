## Resource contract and ownership

The caller pins the Namespace through its direct Admin Namespace read or member descriptor. Both host and Agent directory routes delegate to the same communication read functions; both Workspace routes use the same control read function. Each validates the request generation against the selected Namespace and reads rows in the existing SQLite transaction that verifies that generation. The resulting page carries the verified generation. No global snapshot is promised across different pages. Keep optional generation at the HTTP boundary for already-deployed v2 callers; the updated SDK accepts an unbound first page but requires its returned generation for a cursor continuation. Built-in consumers already know the generation, so they send it from page one. A stale response aborts the current sequence and invalidates rows and cursors. Diagnostics report protocol without gating access. Unknown routes, denied credentials and missing resources retain separate outcomes; no generation fallback or write replay is introduced.

Generation depends on compiling the Rust HTTP projections; if the shared integrated build is in flight, use an isolated export/verification bootstrap rather than changing local lane files or hand-editing generated output.
