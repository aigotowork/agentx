## Boundaries and selected structure

Management binds the original HTTP generation to a passive native Client; daemon dispatch remains responsible for generation and exact target checks. Only descriptor and host-only work need an explicit status read. SDK selection pins one descriptor; native Workspace member and exact Agent history methods use their own capability guards. A missing history endpoint cannot provide a latest-first live checkpoint: keep the pane and verified composer usable without starting a forward scan from the beginning. The ordinary forward message method remains available to SDK callers.

Keep explicit local states: a Workspace may have unavailable members without losing catalog, roles or the independent scope inventory; an exact conversation may have unavailable history without losing its snapshot or send capability. Generation changes abort the associated leases and stop old cursors and pending lookups; stale exact references remain local to their Agent. The native Client exposes `connect_existing_fenced` and distinguishes `StaleGeneration` from a stale exact domain reference. Management projects that distinction without adding a status read. To retain the caller's original Scope even if a listener is retargeted to a copied dataset with the same generation, SDK resource requests use the [optional expected Scope header](../../.docs/api-panorama/service-contract-design.md). Current Management checks it before native work; existing browser CORS handles the standard cross-origin preflight independently.

Verification cases: missing either capability independently, one describe over repeated healthy refresh, generation refusal and mismatched response, exact same-name replacement, and recovery of the original receipt after a dropped send response.
