## Composition plan

The decision under test is whether an operator can identify the exact resource, understand its related workspace/Role, take the appropriate next action, and recover the original operation without losing the resource context. Use one compact resource workspace with a selectable collection, a contextual inspection surface and a focused action layer. Keep operation receipts navigable independently from the selected agent. A static fleet overview with charts was considered; a compact selectable distribution alongside the actual records has greater value given the finite collection and no measured history. Route names and branching semantics follow the experience owner; shared controls and theme follow the system owner.

Source boundaries: `index.html` is the stable entry and shell; `fixtures.js` is deterministic synthetic data; `blocks.js` supplies named resource-specific HTML compositions; `app.js` owns routes, selected context, local draft and receipt state; `management.css` owns product geometry. Keep the two exact-reference variants and the generation on operation fixtures as strings. Do not render or adopt a namesake implicitly. No network requests other than static assets.

## Author verification and correction

Final served fixture `management-2026-11-18-r2` was operated in isolated Chrome at 1440×900 and 390×844 on the shared preview. Checked live vs stopped namesake (read-only and no Resume while a successor exists), exact Reply draft and thread retained across view changes, independent Transcript read, Escape focus, lost receipt surviving reload, one authored send effect before and after original-ID lookup, eligible absent original-ID replay, nonreplayable Unknown and old-generation barrier, directory edited-path invalidation and preview/actual recipient divergence, generated-name launch → explicit exact selection → terminate → history → resume, labels conflict/rebase preserving both intended changes and concurrent keys, and narrow picker with in-viewport submit. The operated browser run reported no page or asset errors.

Desktop keeps Agent selection, exact ID, issue and three communicating rows in the same workspace alongside send and local follow-ups. Narrow view preserves the exact ID, status, receipt, one or more message rows and composer; the list and remaining messages each have their own local scroll. This is an observation of the selected synthetic states, not a comparative density score. Product fit and independent screenshots/findings are owned by [Management Experience](management-experience.task.md) and [Evaluation](evaluation.task.md).

Corrections from product fit and independent evaluation: fake admission is performed at submission, while lookup reveals the stored result; label review reapplies only the drafted changes to the current revision; namesake recovery cannot be offered from stopped history; Launch asks for optional title and exposes the generated name; the old route is visually removed when its directory no longer matches; reply uses the exact source message ID; closing a receipt with a missing invoker focuses the page heading.

Remaining prototype limits: no live/delayed incoming response, freeform thread editor, full native pagination or catalog search outside fixture paths; no daemon-wide operation history, continuous polling, cancellation, or production validation. Treat the [target design's capability disposition](../../../.docs/web-product-design/management.md#capability-disposition-and-engineering-handoff) as the reconstruction coverage source.
