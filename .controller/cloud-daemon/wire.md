# Daemon control wire

The deployment bearer issues or observes operations. The scope bearer can publish capabilities, acquire work, and report effects for its exact installation under a live daemon lease. The [communication wire](../cloud-scope/communication-wire.md) remains separate: its legacy host heartbeat never enables management. [Control declarations](../../src/cloud/control/types.rs) generate both OpenAPI surfaces; [control store](../../src/cloud/control/store.rs) owns transitions inside the existing generation-fenced communication database.

| Surface | Method and path | Operation ID | Body / result |
| --- | --- | --- | --- |
| Admin | GET /api/v1/admin/scopes/{id}/hosts/{host}/capabilities | `getAdminHostCapabilities` | → `{generation,host,installation_id,online,observed_at,workspaces,directory_launch?,workspace_management?}`. A heartbeat-only host has `online:false,observed_at:null,workspaces:[]`. |
| Admin | POST /api/v1/admin/scopes/{id}/operations | `createAdminControlOperation` | `{generation,request_id,host,installation_id,command}` → receipt |
| Admin | GET /api/v1/admin/scopes/{id}/operations/{request_id} | `getAdminControlOperation` | → receipt |
| Scope | PUT /hosts/{host}/control/lease | `scopeRenewControlLease` | Optional query `directory_launch=true` and feature headers below; `{generation,installation_id,lease_id,previous_lease_id?,workspaces}` → capabilities |
| Scope | POST /hosts/{host}/control/poll | `scopePollControlOperation` | `{generation,installation_id,lease_id,wait_ms?}` → `{operation:receipt|null}` |
| Scope | POST /hosts/{host}/control/operations/{request_id}/report | `scopeReportControlOperation` | `{generation,installation_id,lease_id,claim_id,outcome}` → receipt |

Scope paths are relative to the configured scope URL plus `/api/v1`. All names above are wire names. A catalogue allows up to 64 workspace aliases and 512 role entries total. Each workspace is `{alias,default_available,default_reason,roles:[{name,available,reason}]}`. Reasons are required nullable, bounded opaque codes and present only for unavailable entries. `observed_at` is required nullable, and otherwise the server Unix timestamp of the last daemon lease publication; expired hosts keep their last catalogue but have `online:false`. The launch and stop `ControlCommand` variants are `{kind:"launch",workspace,role?,name?,title?,initial_prompt?,working_directory?,create_directory?}` or `{kind:"stop",name,incarnation}`. Workspace is an exported alias; role is the exact advertised selector for that alias. An omitted role selects local default Codex and requires `default_available`. Launch starts one headless Agent with host-side defaults and can supply an exact short name, native short title, and up to 16 KiB of plain initial task text. It accepts no provider command, arguments or environment. Stop refers to the exact current registration on this installation. A successful launch or stop reports `{status:"succeeded",agent:{name,host,incarnation}}` as its `ControlOutcome`. Any operation may report `{status:"failed",code}` or `{status:"uncertain",code}`; code is a stable opaque token. A `ControlReceipt` is `{generation,request_id,host,installation_id,command,status,claim_id,outcome}`, where the last two are required nullable. Status is `queued|running|succeeded|failed|uncertain`. The request ID is the operation ID within a scope and matches `[A-Za-z0-9_.:-]{1,128}`, excluding the URL dot segments `.` and `..`.

A live lease with `directory_launch:true` accepts a slash-separated `working_directory` within the published workspace. Blank or omitted cwd means the workspace root. Absolute paths, dot segments, backslashes, control characters and paths over 1024 UTF-8 bytes are rejected. A true `create_directory` allows the host to create only the final directory under an existing parent, and requires a nonempty path. Passing either field requires the advertised capability; omitting both preserves the original launch and receipt replay contract. The host rejects symlinks in the selected path and enters the opened directory rather than resolving its name again. The [Space directory task](../cloud-space/shared/directory.task.md) records the editor and integration evidence.

A host supporting workspace registration sends `X-AgentX-Features: workspace_management` and optionally `X-AgentX-Workspace-Parents: main,other` on each lease PUT. Both headers accept comma-separated values. Unknown feature tokens are ignored. Parent aliases must appear in that same publication and represent configured export roots. The lease JSON keeps its previous shape so an older deployment can still renew it. A supporting live lease exposes `workspace_management:true`. The deployment adds the read-only `managed_parent:true` to eligible entries in the response catalogue and omits it elsewhere. A registered workspace can be used for launch and does not itself become a configured root.

With that capability, an admin can submit `{kind:"add_workspace",parent,directory,alias,create_directory}`. Parent and alias use the workspace alias grammar (1–63 lowercase ASCII letters, digits or hyphens, with alphanumeric ends). Directory takes the same relative path syntax as launch and must be nonempty. `create_directory` is a required boolean. Admission and claiming both require an eligible published parent; a used alias fails with `workspace_alias_taken`. The host verifies its configured parent and filesystem confinement, persists the registration and renews the catalogue before reporting `{status:"workspace_added",alias}`. The deployment confirms the exact claim, requested alias and published alias; the enclosing receipt has `status:"succeeded"`. See the [workspace Task](../cloud-space/shared/workspace.task.md) for ownership and evidence.

Daemon generates a fresh opaque lease ID per boot/acquisition. It renews every ~5 seconds with the same ID. TTL is 30 seconds. A replacement while live requires matching the previous lease ID (host may persist that ID), otherwise it can acquire after expiry. Old IDs cannot reacquire after expiry or replacement. Lease publication also renews the messaging heartbeat for the same installation. Rejected expired/replaced lease requests return `409 stale_lease`. Online eligibility is determined by the control lease only. A queued operation is bound to the live lease at admission; it becomes `failed/host_lease_lost` if that lease is lost before claim. Poll can wait for an operation with `wait_ms` (default 0, capped at 10,000; host should use 5,000) without holding a transaction. It atomically claims a queued operation before returning it and returns the same running operation/claim on retry during that lease; a lost poll reply cannot grant execution to a new lease. A running operation whose execution lease is lost is observed as `uncertain/host_lease_lost`. An exact journaled claim can subsequently report its known outcome under the current lease on the same installation, including across daemon restart. A lost poll reply followed by lease loss has no locally journaled claim to reconcile, so the receipt remains uncertain and is never handed to a replacement for execution. There is no explicit release; withdrawal occurs on expiration or replacement. The local journal must be durable before the effect and must never execute again if it cannot establish whether an earlier effect occurred. Identical terminal reports replay. A wrong claim returns `409 control_claim_conflict`; a different outcome for a terminal claim returns `409 control_outcome_conflict`. Token rotation immediately wakes control waits and revokes the old bearer.

An identical admin submission replays by `request_id` before checking current online state, role availability or stop registration. Changed payload under the same request ID returns 409. New launch validates the advertised alias/role pair (or the available Codex default), plus short-name syntax if supplied; new stop validates exact active Agent binding at admission and again when claiming. A stale scope generation always fails. Read receipts with the Admin GET path; the existing Scope `/operations/{request_id}` is for message receipts.

State coverage: live daemon with zero Agents; legacy-only and expired hosts; wrong generation, installation, lease, request or claim; role/Agent changes between admission and poll; replay after offline, lost poll reply, and reports before/after replacement; expiry before claim versus after claim.
