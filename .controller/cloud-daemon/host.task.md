Cloud control authorizes one operation for the current installation and daemon lease. The host journals its effect boundary before invoking the shared local process path. A terminal outcome is saved before reporting, so a lost receipt never causes another process effect. On restart, recover from exact local process evidence where available and otherwise report uncertainty. No replay by mutable Agent name or inferred process identity. The journal binds both cloud and native generation and stores an operation fingerprint rather than initial prompts or credentials.

Native shutdown cancels unready launches, drains cloud IPC alongside any already authorized effect, and joins the uplink before releasing the local singleton. Cloud availability ages out after the control lease's 30-second TTL; there is no release endpoint. Verified restart reloads `cloud.toml`; transient connectivity retries need no restart.

The [worker](../../src/cloud/uplink/worker.rs) renews about every five seconds, rediscovers [capabilities](../../src/cloud/uplink/capabilities.rs) on renewal, and uses the [bounded long-poll wire](wire.md) when idle. It discovers only explicit exports and native public roles, filters unsupported selectors, and publishes within the service's catalogue bounds. It revalidates both the advertised path and the role before launch. Status is keyed to the exact native daemon instance and exposes only short reason categories.

The [operation journal](../../src/cloud/uplink/journal.rs) is private to the local scope. A successor retains the exact previous lease ID for takeover and retries stored outcomes using the original claim. A started launch requires matching ready local ownership to recover success. A started stop requires matching local/cloud generation and positive exact exit evidence. Unresolved attempts and lost claims are never re-executed. A cloud generation replacement creates a new journal namespace and never redirects old receipts.
