[Three-host control acceptance](../../.tmp/cloud-daemon/acceptance-physical-control-candidate-2-r4/result.json) passed with the cloud daemon on 192.168.10.3, xser01 as remote worker and longser as operator. Both workers advertised workspaces and roles with zero Agents. Chromium submitted a typed launch and the remote Codex received its initial task. The packaged CLI stopped the exact incarnation and the fixture verified supervisor exit. Offline admission, receipt replay, same-installation reconnection and a second launch/stop passed. The [operator IPC run](../../.tmp/cloud-daemon/acceptance-local-operator-candidate-2/result.json) verified confirmed request/reply using real Provider processes with a scripted model in a separate isolated topology. Temporary deployments were removed; installed binaries and existing services were preserved.

Candidate-2 passed the [pure local Linux regression](../../.tmp/cloud-daemon/local-regression.log) for concurrent native scope startup and Codex PTY message delivery/reconnect. Its [embedded consumers](../../.tmp/cloud-daemon/consumer-native-final/result.json) passed with a scripted control host. The [Codex socket probe](../../.tmp/cloud-daemon/codex-socket-probe/result.json) established that the legacy workspace-write configuration with network access disabled also denied AF_UNIX connect on this Linux build. The candidate-2 local fixture observed actual Provider launch before that denial. The [explicit path-grant probe](../../.tmp/cloud-daemon/codex-unix-allow-probe/result.json) also observed an AF_UNIX denial in Linux Codex 0.171.0 with that documented narrow grant. Tool-originated messaging under this configuration remains blocked. See the acceptance task for the separate physical control outcome.
