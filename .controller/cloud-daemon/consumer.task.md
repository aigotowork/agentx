## Consumer contract and structure

Operators act from an exact scope and target. The [API-owned wire contract](wire.md) defines authority, capability freshness and receipt state. Native exporters feed the fixed package generator; generated types and named Cloud Admin SDK methods feed Web and HTTP CLI, while the native TUI uses Rust wire types over its existing shared HTTP transport. No control flow is available on the public scope communication SDK's handwritten surface.

Keep the existing Management deployment shell, Chinese copy and [tokens](../../.ui-craft/tokens.md). Host rows retain their Agent drilldown and expose an adjacent launch entry. The launch dialog resolves that host's live role and workspace catalogue; Agent rows offer a separate exact-instance stop confirmation. A scope receipt lookup accepts the original request ID from a previous session. Use compact server-state labels and explicit receipt refresh; disable mutation while unresolved. Keep receipts separate from mutable inventory and avoid optimistic effects, arbitrary commands or a second navigation shell.

The HTTP CLI uses selective flags and the existing private durable intent mechanism before dispatch. On a lost reply, recover the original receipt by request ID before offering exact-input replay. Native TUI adds the same host launch, exact stop and receipt actions via its existing asynchronous worker and modal conventions. Preserve live services and installed executables. Package and browser verification use disposable outputs; full daemon/Provider integration is acceptance-owned.

Build dependency: the native binary embeds a Web bundle using generated SDK methods. Generate from the API producer's actual exporter first, then build the integrated candidate and compare its emitted contracts to the package projections.

## Implementation and verification

- The [Cloud Admin SDK](../../packages/agentx-client/src/cloud-admin.ts) exposes named capability, submit and original-receipt calls; the [package guide](../../packages/agentx-client/README.md#cloud-deployment-and-scopes) documents CLI selectors and recovery. The original launch input includes optional role, short name, title and plain initial task. Stop selects the exact installation and incarnation. Both surfaces distinguish queued/running from completed and retain an unconfirmed original request.
- The [Management workspace](../../web/management/AGENTS.md#cloud-deployment-entry) places launch on host rows, stop on Agent rows and receipt lookup inside the selected Scope. The [terminal dialog](../../src/cloud/tui/control.rs) opens with `l` on a host, `s` on an Agent, or `o` on a Scope. Inside it, Tab and arrows select catalogue fields; Enter confirms, looks up or refreshes the receipt. F6 is offered only after a missing original receipt and repeats the complete captured command. Refreshing a catalogue preserves selections by alias and role name.

The [wire](wire.md) now excludes those segments, and all consumers follow that grammar. A separate capability lease gates launch/stop; expired and legacy hosts can still appear online in the messaging inventory.
