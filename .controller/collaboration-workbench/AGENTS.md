## Collaboration boundaries

- The controller coordinates; specialists own professional design and implementation decisions. Use [AgentX-native orchestration](../domain-daemon/orchestration.md) for the engineering team.
- No nested delegation. Two initial specialists have disjoint design writes. Further workers start only for ready implementation Tasks; no revival of archived teams or review committee.
- UI design begins with user scenarios and information hierarchy, without copying the existing diagnostic screen. Domain design establishes minimal truth and reusable capabilities in parallel. Reconcile concrete mismatches directly; do not turn technical limitations into the initial information architecture.
- Production implementation waits for the actual SVG offering to be discussed with the user and for usable domain contracts. This is the user's requested design-first sequence. Routine implementation choices and bounded fixes need no extra approval.
- Every Task must name the Delivery outcome it advances. Peripheral cases stay within the owning mainline Task or remain deferred. Do not invent a generic scheduler, task platform, fleet manager or enterprise authorization system.
- Preserve accepted daemon/observability semantics, dirty source and prior receipts. Do not stop or replace the running user demonstration at `http://192.168.2.178:18731/` or its persistent scope. Design assignments have no production source, manifest, build or runtime writes.
- Authors label cases unexecuted. A separate integration owner executes appropriate checks once actual cooperating code is released. No speculative test suites, repeated successful checks or production claims from SVGs.
- Store progress in the original Task. Send only usable decisions/contracts, concrete blockers and final handoffs. Notify-on-finish replaces polling. On interruption, reconcile current writes/resources before replacement.
