## Reader model

App owns whether a pane is visible, minimized, focused or closed. `LiveSpace` keeps only the first two distinct desired exact IDs in caller order; the active ID drives the legacy paging wrapper and navigation fencing and does not change the reader set. `DomainOfficeReads` owns one lease per admitted ID in the current office, with its own snapshot, messages, opaque cursor, request and error state. Feed refresh may poll a ready current lease after its backlog is exhausted; archived leases advance only on explicit paging. A failure or in-flight page in one pane cannot suspend the other pane's records. Existing snapshots and receipts remain native-owned; the UI must not infer streaming or write success from a GET.

The window integration needs saved scroll to survive visibility changes. Removing an ID aborts its lease but parks completed pages and their exact cursor in memory, limited to eight active plus parked readers. The oldest parked entry is evicted first. The visible-ID contract cannot distinguish a close from minimize, focus or a narrow layout, so these cases share the same bounded cache. Parked data has no polling or sends. Restoring acquires a new lease and fetches the exact snapshot before publishing the full cached history and re-enabling capabilities, with no page fetch required for a cache hit. The conversation layout waits for available records before restoring scroll. The fresh snapshot must match the cached native membership bucket (adopted office or legacy/unavailable classification), even in the all-offices view. Office changes and scope disposal clear the cache.

An office change clears the desired set and independently revokes every domain lease before new office reads, including switches between overview views without a workspace provider. The rejected alternative was to rely solely on App visibility changes, which can be delivered after an in-flight admission. App may explicitly reselect eligible IDs in the new office. A send uses the submitted ID's current lease, revalidates exact membership and capability natively, then checks that lease and selected scope before journaling. A focus change within the same visible set is irrelevant to admission; close, minimize, office change, disposal or reset ends the original lease even if the same ID is reopened. A send already journaled keeps its original receipt semantics.
