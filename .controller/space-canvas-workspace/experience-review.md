# Space conversation experience: authorship and acceptance

Status: selected improvements delivered to isolated LAN preview; direct recent entry remains a native contract gap. Decision owner: vedime. Use the [project product-experience method](../../.agent-guides/domains/product-experience/AGENTS.md) for scenario design/evaluation, [interface resource-workspace criteria](../../.agent-guides/scenarios/interface-design.md#review-resource-workspaces) for density and disclosure, [UI Craft](../../.codex/skills/ui-craft/SKILL.md) for design lenses, and [AI Chat](../../.codex/skills/ui-craft/references/ai-chat.md) for reader and composer risks.

## What failed in the previous method

We divided the product into layout, surface, transport and feedback, which was useful for implementation ownership but incomplete as an experience assignment. The top-level acceptance criteria were derived from those boundaries: could two windows open, could a draft be retained, did an explicit next-page click return data? In fact, the prior browser case actively required the manual next-page affordance (the [original run](../../.artifacts/space-canvas-workspace/browser-r6/report.json) pre-dates its replacement with the current wheel-driven test); its draft was a short string and only the control's bounding box was checked. The measured reader rectangle rewarded area even if padding consumed it. No owner was accountable for an operator reading enough context and composing a substantial instruction under realistic conditions. The tool's use and independent checks were real; the selected claims were too narrow.

## How to run the work

1. Start with what the operator is trying to accomplish. Agree one whole journey, a plausible demanding fixture, a few directly observable success and failure signals, and existing invariants. Keep the frozen current version as the comparison.
2. Give one owner the full conversation experience [assignment](conversation-experience.task.md) including discovery, design, implementation and ordinary fixes. Give UI Craft references as lenses and ask for investigator judgment: find consequential omissions, challenge the brief, and own how the result works in the actual app. Split only by substantially different responsibility.
3. Run independent [experience evaluation](conversation-evaluation.task.md) for this consequential correction. The evaluator builds their own task replay and adverse cases before seeing the fix. Controller integrates the result and treats a usability blocker as cause to reopen the whole journey with its owner, not to start a chain of unrelated polish tickets.
4. Match evidence to each claim. Same fixture/viewport screenshots and visible content units measure density. Browser actions and network/durable receipt observations establish interaction and effect boundaries. Expert walkthrough predicts comprehension risks; an actual user trying the workflow without coaching is evidence about comprehension, not a passage implied by code or one score. Keep coverage gaps visible and avoid promising global usability guarantees.

| Promise | Deciding evidence |
| --- | --- |
| A1 · Read enough, compare, and stay oriented | Same content and viewport; measure actual visible message headers/body lines and line readability, as well as chrome. Include two panes / narrow sidebar; focus and record identity remain clear. |
| A2 · Continue naturally even at a network boundary | Follow the actual cursor by scrolling (no ordinary pagination click), existing content/scroll position stays stable; slow/load/error/retry/end, independent panes, no uncontrolled paging. |
| A3 · Write and revise a substantial next instruction | Paste/type/wrap/delete multiline Chinese and code. Growth cap leaves history and send reachable; deliberate height control works by input mode; textarea scrolls at cap. Return restores the right draft and no Enter or IME path sends by accident. |
| A4 · Know whether the result happened | Verify exactly one intended exact-identity write and appropriate pending/failure/draft behavior; moving away/closing does not retarget. Exercise a surprising case independently selected by the evaluator. |

Discovery prompts (not acceptance quotas): long/short, keyboard/touch, slow/error/empty, current/stopped, initial/return, two panes/same name, pending/received during reading. Select the important combinations and name what is not known. Do not claim a printed checklist or a tool score covers unexercised behavior.

## Baseline and capability boundary

The frozen candidate R5 is the controlled comparison, with the same [long-history fixture](../../web/agent-space/tests/workspace.fixture.mjs) supplying 120/84/52/5 mixed paragraph, list and code records across four conversations (12 per page). [Controller measures and screenshots](../../.artifacts/space-canvas-workspace/experience-baseline/metrics.json) show that a 15-line draft leaves the input fixed at 44px at 1280×800, 768×1024, and 375×812; the desktop initial view fits two whole message headings and six body lines. This is one reproducible comparison, not a universal density budget. Visible boundaries, fixed row dimensions and repeated per-record provenance consume reading space. Preserve message authorship, time, reply/thread disclosure, tap and focus affordances as the record stream is tightened.

Independent early browser work also identified a key issue outside the user's three examples: initial entry to a 120-message conversation starts at message 1. [The native message read](../../src/management/store.rs) takes a forward `after` cursor with a default of 0; there is no latest-page or reverse-history contract. Forward continuation can remove paging clicks, but cannot make current work immediately available without scanning the backlog. A genuine recent-entry + upward-history solution needs an exact-reference bounded latest/before read and its own stable scroll behavior; leave it visible as a contract gap instead of inventing capability or hiding it under a prettier timeline.

## Repeat this on other consequential workbench changes

Use the existing [Space product scenarios](../../.docs/web-product-design/space.md#first-usable-path-contract) to choose the next affected task, rather than starting an undirected screen inventory or extending this delivery to every workflow. For each task, trace entry, decision, effect, adverse branch and return; vary data volume, identity, viewport/input, service condition and interruption only where the combination could change the result. Explicitly classify observed defect, unresolved capability, and untested condition. Finding count is a measure of what a selected evaluation observed; it is not an estimate of remaining defects.

The author owns professional choices and normal repairs; the evaluator owns selection and interpretation of independent evidence; the Controller owns the release decision and unresolved product trade-offs. An untested guarantee cannot be promoted by a detector score, more Agents or multiple passing component checks. On a minor change, exercise only the affected behavior; split author and evaluator here because the earlier decomposition missed a core experience even though its component and composition checks passed. Do not turn this case into a standing review queue.

## Evidence that changed the work

The independent evaluator's [baseline and dispositions](conversation-evaluation.task.md#baseline-verdict-and-dispositions) found, beyond the user's stated complaints, earliest-first entry, restoration to the wrong message after width changes, and a reset editing position. It also distinguished a transport-fault simulation from proof of a durable operation result. The controller added a real commit-then-drop response in the synthetic integration browser test, which verified that the exact draft is retained until the original receipt is queried and there is no second POST. The fixture now returns the versioned SDK's typed result/error envelopes; a raw decoder message from the earlier malformed test response is fixture friction, not proof of a production receipt bug.

Candidate R2 demonstrated what independence should buy: the evaluator verified natural cursor progression, exact-message restoration after width changes, local 503 retry and a bounded short-page request; it also found that long input left just 61px of readable history at 375×520, so the controller returned that state to the experience author before adopting the candidate. The user-facing density criterion remained in force even where some already-passing checks would have let R2 ship.

The durability outcome remains scoped: the preview's typed response comes from an in-memory fixture and the browser fault occurs after that fixture accepted the write. Production native durability, real input-method/touch hardware, participant discoverability, and adjacent journeys such as archive search or attachment-intensive handoff require their own evidence. Suggested next product question: can an operator who opens a cold, high-volume active Agent identify the current decision before drafting? Test direct recent entry plus walking backward without scroll jumps on an exact current and stopped namesake. The stable capability needed is a genuinely bounded latest/older read; the forward reader must continue to work against existing listeners.

## Accepted improvement and actual LAN evidence

The [author's result](conversation-experience.task.md#authored-result-and-local-evidence) and [independent evaluation](conversation-evaluation.task.md) describe exact candidate R3 / E. In the independent matched reference, 1440×900 paired Luna showed 199→247 visible body characters (+24%); 768×1024 went 276→307 and 375×812 went 178→199, with one more complete message at both sizes; 1280×800 single retained 199 characters and two full records. At 375×520 with the long draft, history increased from 61px in R2 to 128px in R3 in auto mode; a real emulated touch swipe moved 114px, exposing four complete lines and 90 body characters while keeping the draft and input/send reachable. The old scene-tip obstruction went from two of nine sampled hit points to zero. Read [the independent raw report](../../.artifacts/space-canvas-workspace/independent/experience-r3/results.json), not just the counts.

The [integration run](../../.artifacts/space-canvas-workspace/experience-r3-integration/report.json) passed scene, both panes, semantic history restore, relations, launch/resource overlays, and original-request recovery after one committed synthetic send whose response was dropped. The new isolated [LAN preview](http://192.168.2.178:18983/space/) serves the immutable `experience-r3` bundle through `agentx-space-conversation-lan-preview.service`. [LAN Chrome smoke](../../.artifacts/space-canvas-workspace/experience-r3-lan.json) verified the exact JavaScript, two visible conversations, continuation by wheel and 44→123px actual editor growth without page errors. It uses synthetic data; the existing native deployment is unchanged. Prior preview rollback input remains `.artifacts/space-canvas-workspace/candidate-r5` and the same fixture command without the `long` argument.
