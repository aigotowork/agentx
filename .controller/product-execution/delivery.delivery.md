# Dedicated product execution for Hypit

AgentX owns the upstream runtime and activation path. **rasova** is accountable for delivery and integration; **mira** owns the Hypit consumer contract, and **vifome** owns its private TLS adapter and isolated Host integration window. The [Hypit product runner contract](../../../hypit/docs/planning/ai-video-platform-agentx-integration.zh-CN.md#产品-runner-与-hypit-工具接线) defines the consuming path. Hypit's local retirement release is independent of this delivery.

The source candidate must register a dedicated workspace/role/profile execution through native AgentX authorities and bind the actual exact incarnation and Codex root. The usual Hypit management SDK sends the original request. The runner independently combines the original UUID and Sent event, the one exact frozen inbox member and digest, and the completed native user item for the actual thread and turn. The same registered peer delivers the installed tool witness, final reply when present, terminal outcome and drain. A native client-executed tool request enters the formal Hypit MCP route with its original durable invocation identity; Hypit retains actor authority and writes proposals only through its existing native consumer.

Acceptance is one isolated end-to-end execution with the real native Codex binary using a fixed loopback model-response fixture, candidate AgentX daemon and SDK, generated temporary mTLS peer, and Hypit private ingress/MCP consumer on a disposable paired/token project. Verify exact registration, persisted causal joins, one actual native tool round trip, one formal proposal, final native reply and terminal, and no release before drain. Include negative cases for wrong peer/installation/exact member/incarnation/thread, premature tool admission, dropped acknowledgement and restart without duplication, and unresolved invocation or missing response fence. Scripted native frames can verify fault handling independently; they cannot establish real native tool or installation compatibility.

Source and disposable verification are authorized. Keep the installed CLI, shared daemons, development sessions/configuration and user credentials or quota intact. A remote/paid model run or any installed/live adoption is a separate administrator decision: dedicated runtime and role/workspace, approved provider allocation or demonstrably non-billed endpoint, private peer credential reference, and a Hypit ingress/operator window. Provider-side access to the trusted peer, runner journal or AgentX control socket is disqualifying.
