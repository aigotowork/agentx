## Source findings and implementation boundary

- [Management worker](../../src/management/worker.rs) forwards the original request ID into daemon-native Send. [Management Send](../../src/management/store.rs) validates the live exact ref and returns the native acceptance event as `Sent.message_id`. [Message acceptance](../../src/db/message_acceptance.rs) retains generation/request/event/normalized command. Product provenance must retain the exact management target and original command identity at the trusted source, rather than reverse-match text, name, recipient history or a public operation GET. In particular, inbox events are not exact-incarnation proofs by themselves.
- [Inbox prepare](../../src/messaging/inbox_store.rs) serializes access and freezes the actual messages with the formatted input; `PreparedBatch.window.through` is only a frontier. A product turn must have exactly one authorized member, matched against that frozen list before native input. [The native driver](../../src/integrations/codex/bridge/driver.rs) already verifies full text, client correlation and native thread before confirming delivery. Product proof must also preserve the actual native input item and nonempty turn with the same original claim and frozen-input digest. Existing generic receipt and predecessor recovery are not sufficient by themselves. Preserve ambiguous issued state across crash; never restart a turn based on a missing reply.
- [Shared stdio launch](../../src/runtime/launcher.rs) rejects role/workspace and [shared driver](../../src/integrations/codex/bridge/driver.rs) can steer active turns. Start from a separate opt-in, single-root, runner-owned app-server transport using the same attachment/claim authority and verified native protocol. The product runner must exclude arbitrary native ingress, hook/explicit alternate delivery, competing/foreign mail, steering, and adoption by cwd or display-name reassignment. Reuse qualified root/host paths or extend their native inputs as needed; the workspace, role/profile, incarnation, execution and thread must come from actual registration. This is the implementation direction, pending installation and authority seam validation.
- [Hypit event and locate consumer](../../../hypit/packages/platform-server/src/modules/agentx/service.ts), [installation supply](../../../hypit/packages/platform-server/src/host/agentx-supply.ts), and [MCP tools](../../../hypit/packages/platform-server/src/host/agentx-tools.ts) are the wire source today. Per product turn, event sequence starts at 1 for input; tool sequence is independent. Hold a correlated event until its original Hypit locator exists; hold native tool requests until exact input is accepted. Use the actual loaded dynamic-tool declarations with the same reviewed installation digest, stable native request identity preserved with its original ID type, and Hypit-compatible canonical arguments digest. Journal events before transmitting; retries, where permitted, retain the original key and immutable payload. Tool effect uncertainty, Provider disconnect or loss of the native response fence must hold drain. Use actual final assistant item and actual terminal; empty/aborted turns do not fabricate a reply.
