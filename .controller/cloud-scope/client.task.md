The native CLI keeps its public command names and routes only a configured cloud scope to HTTP. [Communication wire](communication-wire.md) owns route and DTO semantics; the native client maps this wire to `launch`, `send`, `list`, `listen`. `client/http.rs` owns bounded HTTPS transport and is reusable by the admin TUI. `client.rs` owns command selection, local installation identity and the scope wire. `client/host.rs` owns local OS lifetime, one private Codex process/thread per Agent, and delivery after native turn acceptance. Cloud never starts or acquires a local AgentX daemon. Local Codex auth, profile/config, cwd and process handles never travel over scope HTTP.

A launch binds a fresh incarnation and keeps its exact credential context local. The host renews its installation lease while working; eligible idle threads consume at most one message at a time. A stable claim ID and Codex client input correlation distinguish lost HTTP responses, known pre-delivery failures and ambiguous provider writes. Ambiguous writes are checked against native thread history and never automatically repeated. Normal stop retires the exact Agent; an abrupt process death cannot release its reserved name. Initial scope operations require an exact registered Agent sender; there is no synthetic human sender.

Integration seams discovered: the installed Codex app-server `--listen` flag accepts just one transport, so both the local supervisor and the optional interactive TUI attach to the same private Unix socket. Smoke probes observed HTTP 101 on the native socket and an idle thread from the installed Codex 0.171.0 (no model call). Cross-host behavior remains a separate independent acceptance task.

Native use: set `AGENTX_SCOPE_URL` to the scope URL (`https://HOST/scopes/ID`, or explicit loopback HTTP for tests), `AGENTX_SCOPE_TOKEN` to its scope bearer, and optionally `AGENTX_HOST_NAME` to a stable host name. `agentx launch --tool codex --headless --go --json [--name NAME] [--agentx-prompt TEXT]` starts one Linux host and reports the local supervisor PID and Codex session ID. Without `--name`, normal AgentX short-name allocation excludes registered and locally retained names, then retries an exact reservation collision. An interactive terminal can use `--run-here`, which attaches the local Codex TUI to the same private app-server socket. Local profile, role, cwd and supported Codex model/config flags feed only the Provider. Use SIGTERM on the reported supervisor PID for a graceful stop; it retires that incarnation and removes the private context. After an abnormal stop or scope-token rotation, set the current credential and run `agentx launch --headless --name NAME --recover` from the original working directory to resume the exact saved Agent and Codex thread. The new worker reconciles pending receipt or native history evidence, preserves unresolved output without replay, and removes the previous private credential context.

Inside the launched thread, ordinary `agentx send @NAME --intent request -- MESSAGE`, `agentx list --json`, and `agentx listen [SECONDS] [--json]` inherit that Agent. A local shell can select an owned live Agent with `--iam NAME`; address another host as `@HOST/NAME`. Send `--request-id ID` makes a one-target request replayable, `agentx send --operation ID` reads the durable receipt, and `--reply-to MESSAGE_ID` preserves the inverse response relation. Cloud-mode unsupported commands fail before local daemon acquisition. Plain HTTP is restricted to loopback; bearer redirects are disabled. Local logs and context are owner-only.
