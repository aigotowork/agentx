**Decision: no release blocker remains in the independently sampled final browser paths.** The revised composer compacts interaction without putting additional complete messages on screen in this matched sample; useful reading density stays the same, while rest height is smaller (especially mobile). Keep this as a monitored design tradeoff. The evaluated object is the frozen Chromium candidate; the Controller owns exact integrated native and release/adoption evidence.

Limits: sampled default style, one Chromium engine, four stated viewport sizes, a synthetic touch device without an OS keyboard, and synthetic composition events rather than a real Chinese IME. The visible-area metrics do not establish user discoverability or usability across different content, skins, fonts, mobile browsers, or assistive technologies. Staged attachment/media use and Provider Transcript content were bounded (only one draft file and its retained count, Transcript unavailable view); no real attachment send, provider content, desktop resize drag, old-daemon switch or stopped/generation transition was exercised here. Transport fault injection is not a live production outage. The short feedback and visibility samples provide finite evidence, not a server throughput or polling-envelope claim. No product code, existing LAN preview, installed binary, or Agent processes were changed by this evaluation.
