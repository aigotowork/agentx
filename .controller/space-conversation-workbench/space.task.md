## Frontend structure and decisions

- `live/domain-office.ts` owns exact reader leases and a single chronological cache per reader. A descriptor selects latest/backward or legacy forward on lease creation. Latest mode has independent demand and live request state, shares only the deduplicated records, and never changes the live watermark during an older read. Parked entries revalidate their exact subject and membership before exposing content; legacy office-switch behavior remains.
- `ConversationLayout` owns the semantic viewport, tracking the first visible record and offset or intentional end-following. A cache-local arrival count supports an exact unread count without treating prepended records as new. Each exact channel has its own bookmark; window leases remain with the existing workspace selector.
- `Conversation` adapts the read state, commands and dialogue into shared UIUX controls. The relation disclosure acquires only while open. Fork uses the existing confirmation, original request journal and typed receipt result validation; an exact follow-up is a separate deliberate navigation.
- Existing styles supply the palette and spacing. Shared conversation tokens and controls own the single composer frame, tool hit areas, popup constraints and focus. No skin-specific redesign or new persistence.
- Baseline LAN descriptor is legacy and has no advertised history support; the companion native assignment owns the new wire contract. Baseline code also dropped parked history on office change and treated Fork dispatch completion as enough to close the confirmation, even without a confirmed operation.

R4 also allows Escape for the active Space overlay when body has focus, which happens after pointer-only preview or a removed pagination control.
