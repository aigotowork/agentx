## Delivery workflow used

1. Core materializes canonical types/public entry and publishes exact portable artifact/checkpoint contract early. UI materializes shell/module boundaries first and consumes that contract before real behavior. Acceptance authors cases from the design and actual API, independently of the source authors.
2. Source authors fill coherent modules and document usage/limits, then release exact source claims. They do not run tools, tests, builders or services. Acceptance is the sole executable/check/browser/artifact owner after releases and returns concrete defects to original owners.
3. Integrate actual artifact, run scoped positive/negative/data/native/browser checks, preserve failures and verify meaningful rendered use. No extra approval or reviewer cycle. No production Cargo build, install/lock change, Provider or user-scope operation is needed.

## Complete user path and limits

Open a domain object → identify business identity/state/invariants → inspect an owned method/native input and outcomes → navigate to its process/data source → select success/refusal/unknown scenario → play/pause/step and compare expected with recorded state → locate diagnostics/source/docs. The map supports container-sized pan/zoom and node movement without mutating domain state. Keyboard and390px touch paths stay in one compact workspace. Metadata/docs are inert and portable.

No arbitrary TS AST inference or graph-to-arbitrary-source writer, oRPC auto importer, general concurrency/loop dataflow, universal rule theorem prover, workflow runtime, general obstacle router or remote collaboration backend is implied. Unsupported constructs get diagnostics. Source-first definitions plus explicit source/process/data witnesses own design correspondence. A text rule/source link is never shown as executed proof.

New user-accessible demo is authorized on a free nondefault port, prefer18959; preserve existing18957/18958 demos and all AgentX runtimes/.bin/.agentx/installed defaults. An existing single-artifact static server implementation can serve the new output; no new network API is needed. Final support/evidence must say exactly what is implemented and exercised.
