# Native contract release

The native skeleton is materialized. This releases the named leaves for implementation; it does not establish running support or exclusive database ownership. Runtime worker identities and active claims remain in the [controller](controller.md), rather than permanent architecture guidance. [Acceptance](../../.docs/architecture/acceptance.md) is owned by integration.

The [storage-boundary disposition](../../.docs/model/storage-boundary.md) names daemon adapters, mixed-module helper call paths, separate read-only archive/Provider exceptions and remaining effect/caller gaps for the final guard. It grants no directory-wide client allowance and requires no mass relocation of existing domain helpers. Integration owns translating that model into scanner policy and independent evidence.

## Shared executable and application boundary

- [`src/service/mod.rs`](../../src/service/mod.rs) owns `Request`, `Response` and injected `Application::handle(&mut self, &RequestContext, Request) -> ServiceResult<Response>`. Transport serializes these native Rust enums through serde. No separately authored schema, method-name/JSON, SQL or argv API is authorized.
- [`context.rs`](../../src/service/context.rs) separates captured invocation configuration from observed process authority. `CallerContext` is wire metadata; `RequestContext` is constructed at the daemon boundary and adds peer process evidence, daemon instance and persistent database generation. Environment and explicit names remain claims, not authentication.
- [`error.rs`](../../src/service/error.rs) owns application errors. A transport write followed by a lost reply is an unknown result; only an operation's declared durable acceptance lookup/deduplication permits replay.
- One application dispatch worker can own a non-`Sync` SQLite connection. External Provider work and waiting for terminal output must not hold write transactions. Bounded worker/queue decisions belong to daemon implementation.

Initial domain exports and serde derives needed by the first slice are explicitly handed to consistency. Architecture does not concurrently edit those leaves. Each released owner may refine its native contract against actual consumer requirements, publishing a signature change directly to affected owners. New aggregate variants remain a coordinated architecture edit.

### Runtime delivery host extraction

Consistency transferred `src/messaging/delivery/{mod.rs,grok.rs,antigravity.rs}` exclusively to the runtime Paseo binding recorded in the [runtime Task](tasks/runtime.md). These leaves own terminal/native I/O, screen and input ownership, local waiting, title effects and transport receipt observations. Runtime adds `delivery/host.rs` as the client coordinator. Consistency retains `delivery_service.rs`, `delivery_store.rs`, inbox claims and receipt transactions. Integration owns fixture/test leaves and execution. This extraction preserves the host/domain dependency direction; it does not authorize runtime to replace durable policy with a database-shaped client facade.

`service/mod.rs` now declares `application`, `client`, `maintenance_store` and `queries_store` in addition to native leaves. Consistency supplies application construction/dispatch; lifecycle/IPC owns the client; product clients own read/maintenance handlers. A declaration whose leaf is still being implemented remains incomplete implementation, not a reason to create a second composition. `InvocationContext::capture` is callable; use it only at originating client entry, or map an existing effective runtime snapshot.

`InvocationContext::launch_context` carries an optional serde-defaulted existing launch snapshot captured before IPC. The client owner has a bounded release to refine only the capture method/add a launch-specific capture method together with `agents/binding.rs` extraction. The old capture helper spawns git/tty and consumes a terminal-ID handoff file; generic TUI/read-model context capture must not consume that one-shot metadata. Launch/session initialization attaches its originating snapshot explicitly; the daemon cannot recapture git/TTY/terminal state. Other context/authority edits remain architecture-owned.

General PTY delivery policy and typed consumer contracts belong to consistency, while runtime adapts the PTY/process shell and real I/O. Hook delivery preserves prepare/Issuing → actual write and flush → exact receipt. Runtime requests PluginStart/Stop through participants rather than inventing DB or argv operations.

Consistency's source-owned additions include `InboxOperation::HasPendingAfter` / `InboxOutcome::HasPendingAfter` in `messaging/service.rs` and `FinalizeLaunchExit` in `messaging/delivery_service.rs`. Use those native declarations for exact inputs and outcomes. A source release does not authorize dropping required lifecycle writes: if a required mutation fails, the use case rolls back rather than returning a partial success. Independent acceptance retains actual execution results and fault cases.

Standard HookSession/StopSession remain participant operations. Consistency extracts session binding, exact descendant teardown and required lifecycle mutations from legacy hook helpers; runtime preserves OMP/Antigravity/Copilot/Claude and other Provider-specific input/output policy while executing frozen post-commit effects. The [state/transaction model](../../.docs/model/state-ownership.md#transaction-boundaries) owns stop atomicity and retired-process evidence. No generic hook argv request, arbitrary patch DTO or daemon signal/wait loop is released.

System cleanup is source-released under `agents::service::{SystemCleanup,cleanup_system,CleanupOutcome,tracked_process_state}` with daemon-only `agents/cleanup_store.rs` and shared `hook_store::cleanup_stop/retire_tree`. Exact current row/PID/stored-incarnation admission, independent-child deferral, retained complete plans and successor fences remain domain-owned; no self actor or kill ticket is fabricated. Actual carriers are Listing/Diagnostics cleanup, Maintenance Cleanup with pure Summary, ResumeResolution with one retained full result, and Hosts LaunchStatus result/cleanup/frozen diagnostics. Binding switches now call DB-only KeepRunning `soft_retire_switched` after PID/endpoint migration. Follow the [source closure](../../.docs/model/storage-boundary.md#released-system-cleanup-boundary) and owning consistency/client/runtime Tasks for exact declarations and authored cases. Source release does not establish independent execution or close remaining router cutover.

The [current storage disposition](../../.docs/model/storage-boundary.md#provider-hooks-bundles-and-operator-admission) records source-ready Claude producer/actual host, Copilot/Bundle/operator consumers, their selected fixed-s8 cases and later-source helper gates separately. Bundle's former exact transcript client helper and old borrowed renderers/stop/kill functions are test-only; file warnings no longer run in daemon semantic validation. Actual stop and standalone kill keep the original Session/Client. ClaimOrphans uses the exact fallible `try_adopt_orphans -> try_owning_instance/adopt_orphan/attach_runtime_state` borrowed closure, while native Start uses read-only `try_claim_orphans_deferred`; sidecar deletion stays on the host after retained committed rows. Clients removed the router's managed-open/reaper/build-context tail, permitting consistency's legacy lifecycle gates and runtime's complete borrowed common-stop gates. The [complete reset/router slice](tasks/clients.md#active-reset-and-final-router-cutover) is now atomically released after Relay's [scoped worker-stop port](tasks/relay.md#scoped-worker-stop-for-reset); host process effects and existing daemon runtime-cleanup transactions retain their separate owners, with no new native operation or storage allowance. Exact later-source [helper dispositions](tasks/consistency.md#legacy-helper-guard-disposition) retain their source owners; the operator core cannot substitute missing rows for retained outcomes, fabricate self authority or bypass Hermes disconnect. These releases do not change preserved fixed-s7/s8 evidence or establish final guard acceptance.

### Relay control extraction

The client owner released all relay source to the dedicated [Relay Task](tasks/relay.md). The native `Receive` extraction keeps authenticated peer validation, durable import/acceptance and domain decisions inside daemon handlers; action-specific real effects execute in the relay worker after the handler returns. Pure daemon reads/mutations call domain handlers directly in process. No handler calls its own IPC client or waits for a worker that must reenter it. Remaining action-specific host consumer dependencies and independent execution stay recorded in the Relay Task; source extraction does not close their support claims.

The Relay owner refines its existing native leaf without adding a top-level aggregate. A durable control lookup is scoped by database generation, relay group, verified source and stable request identity; action, target and normalized input are compared as retained intent rather than included in a key that would permit changed-intent replay. Existing one-way actions retain their authenticated envelope/freshness semantics. Persist a fenced claim/issuing boundary before mutating external work; completion validates generation and exact claim/worker authority. Lost replies, expired ownership and missing completion do not authorize repeating an effect that may have happened. These are selected obligations pending the owner's native source/implementation release, not a claim of universal exactly-once remote control or a new generic effects framework.

The selected retention policy bounds active work and operation/payload/result sizes, retaining compact completed-request bindings for the database generation. Do not add an arbitrary total lifetime count cap or prune tombstones so a fresh-timestamp retransmission can execute again. Result-event consumption is separate from deduplication; if large retained answer bytes are pruned, surface completed/result-unavailable without repeating the action. Active admission saturation leaves completion/recovery and pure daemon reads available. Exact quotas and declarations belong in [Relay design](../../.docs/architecture/relay.md) and its native control leaf.

Relay Receive and Backfill now return frozen allowed wake ports; the worker's bounded notifier executes `runtime::notify::wake_ports` after dispatch returns. `snapshot_all_wake_ports` is the daemon-only borrowed projection. Preserve the existing finite broadcast kind allowlist and durable cursor polling; a lost hint is not lost accepted work. Shared event/subscription post-commit effects retain their domain owner and are not implicitly rewritten by this release. Source release and authored no-handler-connect cases are distinct from independent execution evidence.

## First complete contract slice

`Participants::Lookup { name }` returns exact `ParticipantRef` identity. `Messages::Submit(Submission)` accepts normalized recipients/body/native envelope using the validated invocation actor and stable `CallerContext.request_id`. Its outcome reports a durable event, accepted recipients and whether the result was replayed. `Messages::Acceptance { request_id }` queries durable acceptance. The consistency owner implements atomic normalized-input/actor/request binding plus event/acceptance commit; changed input under the same identity must conflict. Admission is distinct from inbox claim, issuing, external input and exact receipt.

Existing `AttachmentStore` and `PendingInbox` declarations are authoritative and cross IPC through domain-owned typed variants/adapters. Do not reproduce their fence/evidence types. The attachment persistence adapter receives `AttachmentOwnerProcess` from verified caller or registered runtime-host evidence; the daemon's own PID must never be recorded as the Provider controller.

## Resolved lifecycle choices and open limits

The initial local binding is a private Unix stream with length-prefixed serde frames, existing standard-library/libc mechanisms, one request per connection, bounded frames/deadlines/concurrency, and same-user process evidence. Canonical data scope determines singleton ownership; endpoint hashing may avoid Unix socket path limits. Readiness follows successful application construction, not spawn success.

Daemon instance changes on restart. Database generation is durable across restart and changes on reset/replacement. SQLite key `service:database_generation` is the sole persistent authority; lifecycle's `DatabaseGeneration` is an in-memory mirror. Application construction publishes before readiness; reset commits clear + new key + event atomically and publishes before another dispatch. Any post-commit publication failure invalidates the mirror and stops admission. Maintenance fences pending requests and stale clients around replacement; clients cannot reopen an old file after IPC failure. Protocol major, package version, native build-cohort identity and database schema version are independent compatibility values. The [source-released correction](../../.docs/model/state-ownership.md#native-build-compatibility) replaces per-process image hashing with an embedded generated `native-build-v1:<uuid>` stamp in the existing Hello/DaemonInfo build_id field. Full-file SHA remains independent artifact audit. Daemon owns [build.rs](../../build.rs) and compile-time validated wire identity; integration supplied the existing-graph manifest binding and owns Cargo invalidation/cache/process/performance execution. Source readiness is distinct from verified behavior. Standard Cargo inputs and the explicit direct-rustc/compiler-wrapper support boundary apply; package version alone and metadata-derived identity remain insufficient.

Existing event/archive/participant `--sql` predicates are a constrained named read-model compatibility surface only. The owning read-model domain enforces projection restrictions in the daemon. `events::filters::resolve_filter_names` is a named borrowed lookup; `build_sql_from_flags` is pure expression generation; `events::predicate::read` is a scoped SQLite authorizer adapter. Their [kind-scoped disposition](../../.docs/model/storage-boundary.md#named-helpers-in-mixed-modules) grants no arbitrary query, write statement, unrelated table or database-path capability.

The [qualified transport/performance decision](../../.docs/model/state-ownership.md#measured-transport-cost-and-accepted-residuals) accepts the bounded lifecycle implementation and independently corrected material hash/listener regression, retaining measured cold/start costs. It selects no further tuning cycle. Final combined-source performance, guard, package/cutover and native-platform acceptance remain integration/Delivery-owned.

The daemon owner has materialized Windows named-pipe transport with current-user access control and authenticated process identity; Windows/macOS runtime acceptance remains independently unverified. A fail-closed unsupported branch on a required platform would remain a Delivery gap rather than accepted reduced behavior. Old direct-SQLite clients/hosts are not excluded by a new daemon lock; the [supported maintenance cutover](../../.docs/model/state-ownership.md#legacy-process-cutover) and isolated old-process evidence remain required before exclusivity is claimed.
