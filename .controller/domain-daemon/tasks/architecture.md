## Working conclusions

- Current CLI dispatch, runtime failure handling and relay workers can open SQLite directly. Existing wake sockets do not form a centralized domain service.
- Per-client identity and effective environment cannot be inferred from a shared daemon's startup environment.
- One database owner process does not require one connection or serializing external provider I/O.
- Provider runtime hosts and the database owner have different lifetimes. Restart/reattachment and fenced late results need explicit treatment.
- A file lock used only by new code cannot exclude old processes that still open SQLite directly. Cutover must account for existing clients and hosts.
