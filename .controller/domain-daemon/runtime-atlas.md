# Interactive runtime atlas

The user needs one navigable picture of process boundaries, contained modules, transports and event handling. Deliver a source-grounded explanatory artifact, not a live dashboard or runtime redesign. Existing completed product Deliveries remain completed; this request authorizes the bounded documentation outcome.

The controller owns semantic data/source references, deterministic scenario state, standalone generation and actual browser acceptance. One fresh UI specialist owns layout and interaction against that model. Parallel frontend composition benefits from isolation while the controller preserves backend lifecycle context. No nested delegation, Provider execution, Cargo build, dependency install or existing service mutation is needed.

## Design and outcome

Canonical JSON models processes separately from modules, persisted stores and native threads. Modes are foreground PTY, detached headless PTY, tmux, shared Codex app-server and browser workbench. The main screen contains a selectable process/module map, named communication edges, local inspector and scenario player. Steps identify actor, handler, transport, actions, changed facts and source basis. Playback covers launch, turn/status, durable mail, close/disconnect, crash and resume. Unknown native continuity remains explicit; all states are illustrative behavior rather than live observations.

A small Python builder embeds model/CSS/JS into portable `index.html`; no framework/CDN/runtime API is required. Validate model references and lifecycle invariants, then exercise actual browser mode switching, inspection, step reconstruction, keyboard and narrow layout. Retain desktop/narrow screenshots with user-intent assessment. Hand over the HTML and a new scoped read-only LAN URL; protect all existing runtimes.
