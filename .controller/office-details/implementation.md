# Technical design and skeleton

Title is optional individual responsibility text, independent of name, Role, prompts and workspace. Persist `launch_context.title` in the existing SQLite record, with JSON null for omitted titles. No SQL migration or backfill: old missing values read as absent. A small participant-owned `launch_title` module validates and reads this value. Input is trimmed, nonblank, single-line without control characters, at most 160 Unicode scalars; CLI and daemon reservation/API admission enforce the same rule. Preserve the normalized string verbatim after admission.

Skeleton chain: optional `AgentxLaunchFlags.title` → `LaunchParams.title` → serde-default `Reserve.title` → validated durable context. Add a native `TitleSupport` capability probe before title-bearing reservations so old daemons cannot silently drop the field. Existing recapture paths preserve this launch-owned key. `ResumeSnapshot.title` reads both current and stopped context; resume and fork inherit it unless a valid explicit title overrides it. Disk-only adoption has no title. Shared Codex app-server stdio uses a different reservation path and remote Relay does not carry title: reject title there explicitly before effects rather than silently lose it.

HTTP `LaunchInput.title` defaults to absent; safe `AgentView.title` returns nullable normalized text on current and stopped reads. Worker forwards it to the same launcher. Regenerate management TS through the existing native derivation command; Space stores the title separately from display identity and preserves safe adopted Role descriptions. Scene disclosure/crown/name/geometry follow zila's forthcoming design.
