The user selected the verified first snapshot for project `.bin/agentx`. It passed the packaged Web and both Transcript layout smoke checks and 10 CLI target selection cases. [Adoption](../.artifacts/project-release-20261120-134940/adoption.log) records the executable checksum and its rollback. In-flight direct/native Codex recovery changes were excluded.

Both old and new client binaries received Busy from the original project daemon. The user authorized a project-scope restart. Its command reported a readiness deadline, but the child subsequently reached authenticated Ready with the installed candidate and retained the original database generation and Management listener. The old process exited; no Agent hosts or other daemons were restarted. See the [pre-restart incident samples](../.artifacts/project-release-20261120-134940/daemon-incident-before.json), [restart output](../.artifacts/project-release-20261120-134940/daemon.restart.log) and [post-restart status](../.artifacts/project-release-20261120-134940/daemon.after-restart).

The restart did not resolve saturation. A [native runtime sample](../.artifacts/project-release-20261120-134940/busy-runtime.json) on the new daemon showed 16 queued jobs, one executing job, and 20,872 lifetime admission refusals versus 824 queue admissions. The retained Codex traces include successful callbacks and Busy before business execution. Large numbers of delivery snapshot retries amplified demand; the host retries a refresh failure after the existing 250 ms delay. The host machine also showed high I/O pressure and the daemon dispatcher in disk sleep. The first trigger of the incident and its share of external I/O remain unproven.

Two kinds of long application calls were measured on the single dispatcher. Management calls took up to 63.964 s; normalized slow HTTP routes included Agents, workspaces, office activity and the human mailbox. For one 27.036 s ObserveModelRequest call, the timing directly attributed 16.249 s to subscription candidate lookup and 10.729 s to request-watch work; SQLite commit was 0.740 ms. The process had neither the indexed subscription selector nor asynchronous observer hints enabled. Source presence alone did not activate them.

A focused follow-up should evaluate the indexed selector against this call family's measured phases, then attribute Management read time separately. Measure admission and hook results for the same scope. The restart already showed that switching the executable alone does not clear recurring queue pressure. No feature switch, restart loop, database cleanup, or forced process stop was performed.

## Default activation audit

The user requested a read-only inventory before changing defaults. The running project daemon still loads project `.bin/agentx`; both `AGENTX_INDEX_EVENT_SUBSCRIPTIONS` and `AGENTX_ASYNC_EVENT_OBSERVERS` were absent from its process environment. [Daemon startup](../src/service/application.rs#L22) requires explicit `1` for each. These are rollout gates for transparent optimizations. The [original proposal](../.docs/proposals/daemon-postcommit-performance.md#验收取舍与后续判断) retained the old paths for first index creation on existing databases and for separate observer wake adoption/rollback. Existing parity and isolation evidence does not include an exercised default rollout. Promote the index first after a scoped before/after comparison; keep an explicit rollback. Evaluate the observer hint worker separately because it only affects advisory event refreshes and did not account for the measured 27-second call. Record the effective paths at daemon startup.

The mailbox route projection starts automatically and falls back until suitable coverage is established. The managed Unix Codex PTY hook path is automatic for eligible new launches; daemon replacement does not rewrite declarations in existing sessions. The separate verified automatic direct Codex terminal follow-up is absent from the deployed first snapshot by user choice. Management HTTP, Inspector history collection, and automatic recovery are explicit capabilities with listener, persistence, or action semantics, outside the transparent optimization rollout. This audit changed no runtime settings or code.

The user then selected default indexing across all scopes without a preliminary project-only rollout. [Daemon startup source](../src/service/application.rs#L25) now selects indexed reads when the environment variable is unset or `1`; `0` retains old selection, and index setup or lookup failure still falls back. Async observer hints retain their independent default. This source change needs a new executable before it applies to new daemon processes.

## Project rollout of default indexes

The user explicitly requested replacing the project binary and daemon. The [first project restart](../.artifacts/project-index-release-20261120-151035/indexed.restart.log) used the previously released binary with the index environment override enabled. All three indexes were present, and the first two observations admitted 4,163 requests without Busy. A later sample recorded 14,300 refusals; a Management request occupied the dispatcher for 43.681 s, while an observed model request took 886 ms (request-watch 140 µs). These are production samples at different loads, not an isolated performance benchmark.

The [optimized release](../.artifacts/project-index-release-20261120-151035/package.log) passed [default and rollback verification](../.artifacts/project-index-release-20261120-151035/index-fixture.log), [embedded Web and TUI smoke](../.artifacts/project-index-release-20261120-151035/smoke.log), and [ten CLI target selection scenarios](../.artifacts/project-index-release-20261120-151035/cli-target-selection.log). The [input delta](../.artifacts/project-index-release-20261120-151035/inflight-diff) includes concurrent recovery and delivery edits and prevents claiming this package exactly matches the later worktree. The verification applies to the adopted candidate bytes only.

[Atomic installation](../.artifacts/project-index-release-20261120-151035/adoption.log) replaced project `.bin/agentx` with SHA-256 `91678faade5fc49c93609740d5fea718bd0db5da738ef2fb5bf13369addbce19`. The original image is retained at `.bin/agentx.before-project-index-release-20261120-151035`. The [project daemon restart](../.artifacts/project-index-release-20261120-151035/default.restart.log) succeeded; authenticated PID 732102 loaded that build with no index environment override, the same database generation, and the same port 38023. Live `list --dir . --names` returned 51 Agents. The [new runtime sample](../.artifacts/project-index-release-20261120-151035/runtime.final.json) showed 1,299 queue admissions and 37 Busy refusals; default index rollout is complete, but intermittent daemon saturation is still open. No other scope, Agent host, or PATH install was switched.

The [request isolation proposal](../.docs/proposals/daemon-request-isolation.md) owns the subsequent root-cause analysis and implementation plan. It connects the retained queue evidence to the confirmed mailbox/history query, first-page write maintenance dependency, and PTY retry amplification. It distinguishes deployed behavior from the overlapping read isolation and PTY work already in the checkout, and records what the current diagnostic labels cannot attribute. No production code or service was changed during the planning follow-up.

The implementation and selected-scope rollout are recorded in [Project adoption](daemon-io-isolation.task.md#project-adoption). The bounded read lane, cached file-binding views, nonwaiting diagnostics, and reduced Web poll work are in the project daemon's packaged build. An initial post-release clean window is evidence of usable adoption, not a guarantee against saturation under every workload.
