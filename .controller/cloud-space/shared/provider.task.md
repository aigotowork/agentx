[Host composition](../../../src/cloud/client/host.rs) keeps responsibility for the exact Provider turn. It requires the current scope and actor, reuses the recorded mailbox correlation and checks the saved items of the exact successfully completed Codex turn in order. A turn with another user input does not qualify. Only visible final `agentMessage` text can be forwarded; an unphased terminal assistant item is accepted for legacy providers. The [claim journal](../../../src/cloud/client/mailbox.rs) retains the thread/turn binding and freezes the bounded UTF-8 body before sending through the normal host port. A restart can recover terminal status and items from the provider; an ambiguous send repeats the same request ID and body. Backoff and a finite attempt budget prevent persistent output failures from blocking all subsequent mail.

The [cloud store](../../../src/cloud/communication/store.rs) retains existing explicit send semantics. An automatic send checks the exact original request and returns an already persisted explicit reply from that Agent rather than inserting a duplicate. The [additive index](../../../src/cloud/communication/store/message-history-indexes.sql) bounds that lookup. Existing hosts must launch or recover with the new executable to gain forwarding. The cloud deployment needs the updated store for explicit-reply suppression; the browser wire schema and the Provider sandbox stay unchanged.
