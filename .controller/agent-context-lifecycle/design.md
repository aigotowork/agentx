# Selected design

Status: implementation selected by user. Parent: [lifetime proposal](../../.docs/proposals/agent-context.md#follow-up-instruction-lifetime-and-runtime-snapshots). Sources of truth are the forthcoming native declarations.

Two typed contribution ports (InstructionContributor, ContextContributor), three preparation entries (instructions, initial context, compact context). Fixed text is frozen with a participant identity and stored by native lifecycle capabilities. Current dynamic snapshots are generated in the originating host from typed domain facts; no commands or template execution. The existing source loader remains the common bounded implementation. Source IDs and deterministic order are retained. No prompt-role fields on contribution ports.

Configuration: add `instruction_sources` / `AGENTX_INSTRUCTION_SOURCES` / `instructions.sources`. With it explicitly configured, its list supplies frozen instructions (empty string means builtin), and `context.sources` supplies dynamic snapshots (absent/empty means none). With no new selector, compatibility selection partitions the previous `context.sources`: builtin entries become fixed instructions; literal/file entries become dynamic context. Thus previous absent/empty selector keeps the builtin, `[]` disables both, and file-only sources still replace the guide. To freeze a file, select it explicitly in instructions.sources. Configuration stays caller-owned. Fixed snapshot is recovered before evaluating changed source config or files.

Native plugin contract: `*-start` returns `{name, session_id, instructions, context, bootstrap}`. instructions is frozen; context is the initial dynamic snapshot; bootstrap remains combined for compatibility only. `*-context --session-id ID` returns `{instructions, context}`; instructions is the same frozen content, context is freshly generated after compact. No user-turn/status/mail side effects. Missing/foreign sessions fail. Native startup resumes must reuse frozen instructions; a new fork with different identity must not inherit another Agent's identity text.

Plugin worker: consume instructions/context separately; do not put snapshots in user input. Prefer native append-to-system for frozen instructions where supported (never replace base), and hidden/model-context channel for current dynamic state. Plugins may restore frozen instructions after compact through that channel if no persistent native instruction API exists. Context snapshots replace the plugin-held previous snapshot and refresh from RPC; no stale late-response overwrites. Keep existing identity/mail receipts. Retain bootstrap fallback only for old binary compatibility. Preserve empty snapshot clearing. Dynamic snapshot formatter belongs to Rust; plugins should not implement domain rendering.

Codex: launch args contain only fixed developer instructions. SessionStart injects initial dynamic context and compact injects fresh dynamic context; shared initial hook retains exact attachment/first-request fallback. Codex retains fixed native instructions across compact. Claude/Qoder and other hooks that do not have a retained native instruction slot restore frozen + dynamic text through their native context channels. Providers with no context delivery channel must reject selected nonempty dynamic sources with an explicit diagnostic rather than silently append a user prompt. Current native limitations must be documented individually.

Persistence: use a small typed native lifecycle request set and existing kv storage, no schema migration. Always validate participant incarnation and authenticated actor/launch identity. Cache fixed content per participant, bind a tool/session alias after native session attachment, retain for same-name resume. Initial-context receipts are distinct from old name_announced/bootstrap receipts; a previous fixed bootstrap must not suppress initial dynamic delivery. Compact refreshes bypass the initial once gate, maintain active state and never wake or synthesize a user turn. No cross-session fallback based on a process name alone.

Acceptance: native/fake-provider launch shows only fixed text in developer instructions, dynamic initial before first request, changed dynamic and unchanged fixed text after compact; instruction file removed after first read still restores; explicit empty/current state clears earlier facts; repeated first-context callbacks do not duplicate; stale/missing sessions cannot mutate/output; resume retains fixed snapshot; all plugin protocols preserve user message count. Use exact disposable resources and candidate digest. Unsupported channels remain explicit.

Implemented exception handling: same-session initial output has one live process-owned grant; generation errors release it and a dead process allows recovery. Adapters without a native compact event restore frozen text plus fresh state at their existing next model-visible input boundary. Grok explicitly rejects dynamic sources. Historical six-hook Codex test preflight was updated only in the new fixture to reflect native PreModelRequest/PostModelRequest hooks added concurrently.
