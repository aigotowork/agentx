# One-shot reminder discoverability

The installed v0.7.33 help and [Agent bootstrap](../../src/runtime/bootstrap.rs) are sufficient to schedule a reminder without source inspection. The bootstrap supplies a complete GitHub-build example; the general AgentX help only says events queries and subscriptions. Both `events --help` and `help events sub` put the time mode under ordinary event matching, and their examples omit a timed reminder. A caller who knows the subcommand can act; a caller who starts from the task “wake me later” must infer the entry point.

A bounded next change should add “schedule reminders” to the general events summary and group a copyable setup command, default target, status and cancellation under a dedicated “One-time reminder” heading in the two Events help paths. Agent workflow guidance should say to schedule before ending a turn on external work, verify the pending receipt, and schedule another bounded check if the operation is still running. Distinguish a pending or enqueued reminder from an actual resumed turn, and keep the existing command grammar. This is evaluation feedback, separate from the frozen v0.7.34 release.

The documentation entry follows the same discovery rule: use `agentx docs` to read the shipped CLI, config and script authoring references; use `agentx run` to list or execute workflows. The operator explicitly chose to remove the former `run docs` special case rather than keep an alias. Help pages own the reminder examples, and the [Events contract](../../.docs/architecture/event-subscriptions.md#一次性时间提醒) owns the delivery semantics.

The Linux source-built CLI smoke check passed: the former command is an unknown script in a clean Scope, bundled workflow help still works, and `docs --scripts` prints the authoring reference. The regenerated offline command catalog has the top-level docs page and both reminder sections, with no compatibility entry. This follow-up is separate from the frozen v0.7.34 release and installed runtimes.
