# Flow Atlas target design

Read the parent tool entry and [README](README.md). This directory owns product/semantic design and earlier declaration sketches, not a second implemented viewer. [contracts.ts](contracts.ts) owns shared foundational vocabulary and earlier design-only interfaces; [api.ts](api.ts) remains the earlier API sketch. Current domain-workbench contract authority is [domain/contracts.ts](../domain/contracts.ts), reached through its [Delivery](../../../.controller/domain-daemon/flow-atlas-workbench-implementation.md). Do not update old sketches as a second normative implementation surface. [technology.md](technology.md) owns source evidence and unverified integration probes. [The earlier design Task](../../../.controller/domain-daemon/tasks/flow-atlas-platform-design.md) owns its historical checks and limits.

For the domain-model workbench, read [workbench.md](workbench.md), [its design Task](../../../.controller/domain-daemon/tasks/flow-atlas-workbench.md) and [accepted implementation](../../../.controller/domain-daemon/flow-atlas-workbench-implementation.md#accepted-local-outcome). The model owns domain/context/identity/rule semantics, control versus data dependencies, state ownership, scenario expectations and the source-first workbench path. Native contracts/compiler/checkpoints and five linked views are implemented for the documented finite subset. Do not create a competing hand-maintained graph model or infer wider support from this design document.

Keep Definition, Process, Scenario and Layout independent: types/ports are definitions; instances/events witness one trace; layout cannot mutate business state. Schema-derived implementation exports must replace these handwritten shape sketches rather than fork a second contract. Never execute business handlers to generate explanatory input. Keep upstream oRPC v1 stable and v2 beta evidence distinct.

The targeted command is `node_modules/.bin/tsc -p tools/flow-atlas/design/tsconfig.json`. It checks design declarations, examples and negative structural cases only. Cross-reference/runtime/schema/routing support requires real implementation and its own scoped outcome cases. Do not install dependencies, rewrite the accepted viewer or operate the existing runtime listener merely to complete this design.
