# Management console

For the active compact UI Craft design, read the [latest compact design pass](../../.controller/management-ui-craft/task.md#compact-design-pass) and [operator scenarios](../../.docs/web-product-design/management.md). `navigation.tsx` owns destinations and scope; `console.tsx` owns cross-destination composition; `dialog.tsx` owns common modal focus and dismissal; `styles/interaction.css` owns its compact typography, geometry and motion. `use-management.ts` and `use-offices.ts` own dataset-fenced read and selection state. The [UI Craft brief](../../.ui-craft/brief.md) retains the user's rejection of bulky controls and visual framing.

Read [UX and file ownership](design.md), [native HTTP design](../../.docs/agent-management/design.md) and [Task](../../.controller/agent-management/tasks/web.md). `api/native.ts` contains aliases derived from public `ManagementTypes`; native Service → emitted OpenAPI → generated `@agentx/client` owns DTOs and codecs. `api/client.ts` exposes the named SDK instance and app-intent dispatch, not a generic endpoint transport. SDK long integers remain bigint; journal/raw result views use public lossless JSON helpers. IDs/cursors remain exact strings. Durable browser recovery saves the identical write before sending; lost replies must be looked up before explicit same-ID replay. Unknown operations are never replayed automatically. Current cross-module SDK/build ownership is defined by the [Web adoption Task](../../.controller/web-sdk-adoption/web.task.md); native behavior remains separately owned.

Build: `node web/management/build.mjs /absolute/new/disposable/directory`. The output uses the workbench's finite `manifest.json` format. Development server port is 18749. See design verification notes for fixture versus native evidence.

For a self-contained synthetic preview, run `node web/management/tests/browser.fixture.mjs BUILD_DIRECTORY 18792` after the build. The fixture serves the actual Management entry and an isolated mock listener, visibly marked as demo data. To update the preview without forcing an open tab to reload, point the server at a stable symlink and move the symlink to the next successful build; the user's next reload reads the new source. Run `node web/management/tests/browser.mjs BUILD_DIRECTORY` and `node web/management/tests/labels.browser.mjs BUILD_DIRECTORY` for the isolated browser paths.

For the [interaction refinement](../../.controller/management-ui-craft/task.md#interaction-refinement), use `dialog.tsx` for modal focus and dismissal, `styles/interaction.css` for timing and surface states, and `conversation.tsx` for scroll anchoring, quote navigation and the composer. Verify meaningful changes with `node web/management/tests/refinement.browser.mjs BUILD_DIRECTORY`; it checks actual transition events, focus, drafts, short-screen reachability, reduced motion and newly appended messages.

Office capabilities: follow [office design and skeleton](design.md#holistic-office-extension--layout-and-skeleton), [native office contracts](../../.docs/agent-management/offices.md) and [current Web Task](../../.controller/office-management/tasks/web.md). `use-offices.ts` owns generation-fenced finite discovery/effective catalog reads; `offices.tsx` owns adopted fact disclosure, effective posts and directory preview/contact. Directory sends reuse `model.ts`/`use-management.ts` journal recovery; generated types remain integration-owned.

Current role catalogs expose `RoleDefinitionView.profile` as nullable; display the launch-default label without inventing a concrete profile. Adopted facts remain `RoleView` with a concrete profile. Both formats come from the native resolver; no browser filesystem scan. Regenerate the public package from actual emitted specs; do not run historical derive.py over the alias entry.


Labels: follow [consumer composition/state](design.md#scalar-labels--management-consumer), [canonical classification](../../.docs/agent-classification.md) and [Web Task](../../.controller/agent-labels/tasks/web.task.md). `labels/` owns editor/selector/grouping; existing management journal owns all writes and recovery. Read `Descriptor.supports_labels` explicitly; missing is unsupported. Keep native filtering before pagination and grouping limited to loaded rows. Never edit generated contracts here. For synthetic preview/check use `node web/management/tests/labels.fixture.mjs OUTPUT PORT` and `node web/management/tests/labels.browser.mjs OUTPUT`; real native evidence remains separate.


## SDK consumer setup

Install the locked root and `packages/agentx-client` dependencies, then build the public package before standalone Web typechecks/builds. Cargo builds the SDK once before its five browser asset batches. Embedded apps default to their own management listener; explicitly hosted pages may select `?managementUrl=http://HOST:PORT` without a proxy. Independent Workbench/Observation listeners use their own URL selections. See [package usage](../../packages/agentx-client/README.md#web-consumers) and [whole migration/evidence](../../.controller/web-sdk-adoption/web.task.md). Existing stored receipt paths are compatibility metadata only; dispatch uses retained intent kind and named SDK methods. No automatic replay or descriptor refresh is introduced.

## Cloud deployment entry

On the cloud listener, open `/deployment` and enter the admin bearer for that origin. See the [operator guide](../../.docs/architecture/cloud-scope.md#从本地管理) and [Web task](../../.controller/cloud-scope/web.task.md). `deployment/` is separate from the local Management console. `console.tsx` owns the session; `workspace.tsx` owns paged scope and inventory selection, including the exact host filter; `write-dialog.tsx` owns create, rotate, and original-input recovery. `model.ts` is the browser binding for the public Cloud Admin SDK. The selected scope header links to [Cloud Space](../../.docs/architecture/cloud-scope.md#在-cloud-space-工作) with an access hint and independent sign-in. Keep both bearers in memory, keep mutations pinned to their original request, and use explicit same-request recovery for uncertain outcomes. Save the communication token before leaving the dialog; the service cannot return it.

For [native daemon administration](../../.controller/cloud-daemon/consumer.task.md), `deployment/control.tsx` owns the selected host catalogue, launch and exact stop confirmation, and the original receipt lookup in each scope. Use named public SDK calls; a live control lease gates mutation independently of inventory heartbeat. Keep original inputs in memory for explicit recovery and show queued, running, failed and uncertain receipts separately from successful Agent effects.

After the regular Management build, run `node web/management/tests/deployment.browser.mjs BUILD_DIRECTORY [EVIDENCE_DIRECTORY]` for isolated Chrome coverage. To inspect the same bundle manually, run `node web/management/tests/deployment.fixture.mjs BUILD_DIRECTORY 18797` and open `http://127.0.0.1:18797/deployment` with the synthetic token printed by the fixture. The fixture accepts no production credential. It does not establish native router or remote host acceptance.
