# Product clients and daemon capabilities

[Native service declarations](../../src/service/mod.rs) own the callable contract. This document records consumer responsibilities and retained observable behavior; the [Task](../../.controller/domain-daemon/tasks/clients.md) owns implementation progress and unexecuted acceptance cases. The [accepted proposal](../proposals/domain-driven-agentx-daemon.md) owns the target; this inventory is not a claim of completed cutover.

Actual transcript view/search/timeline now consume the [canonical transcript reference model](../../src/transcript/AGENTS.md). Inventory preserves live-first/latest-stopped ordering; disk search correlations use exact path and Provider session, so two sessions in one Provider database keep distinct names. Required native read failures cannot become successful empty searches. Provider contents and search tools remain at the originating host. Remote mirrors use the same Client for control dispatch. Historical borrowed renderers and Bundle's former exact transcript helper are test-only.

Actual configuration entry distinguishes file-only work from durable state. A ConfigHost carries originating scope/environment and an optional original Session. TOML validation/locking uses config/file and permission effects use runtime/config_effects. Instance changes select an exact participant and use existing Lifecycle operations, whose wakes run after commit; scoped default timeout never comes from the daemon environment. Dev-root reads/writes and rendered bootstrap use native projections. Pure help, file/editor/terminal actions bypass acquisition. The historical borrowed instance helpers remain test-only.

## Invocation and effects

Clients capture canonical data scope, effective cwd/environment, participant/process identity and Provider session provenance before connecting. The daemon environment must never choose identity or project. Clients parse CLI grammar and own stdout/stderr, terminal state, local script execution and observation cancellation. Capability handlers own durable queries, invariants, transactions, reset generation and receipts. IPC failure is an error, with no direct database fallback.

Public caller selection uses `--iam NAME`, with no `--name` caller alias. Ordinary managed commands use injected process/session identity automatically; `start --name NAME_OR_AGENT_ID` is a separate registration input. Send/listen preserve failed binding resolution instead of treating an expired caller as an unidentified terminal. Identity-free queries remain usable without a resolved actor. [CLI ownership](../../src/cli/AGENTS.md#caller-identity) owns the parser, bootstrap, script and source-case boundaries.

## Ownership and migration decisions

Client projections are capability-specific read models, not database access proxies. Existing SQL-heavy TUI/event/relay helpers must move into daemon-owned adapters behind native operations. Provider transcript database files are external read-only input and are not the managed AgentX database. Durable effects use existing participant/attachment/output-claim fences rather than inventing parallel client policy.

The first real CLI slice routes list/start/send/events through native calls before the remaining legacy router branch. [`cli/client.rs`](../../src/cli/client.rs) captures invocation and identity, [`cli/output.rs`](../../src/cli/output.rs) binds successful host output to exact mailbox receipts, [`listing_store.rs`](../../src/service/listing_store.rs) supplies the canonical listing projection, and [`events_client.rs`](../../src/cli/commands/events_client.rs) owns pagination and stream lifetime. Their current implementation limits and independent verification remain in the Task; this slice does not establish complete client migration.

The [post-s9 Events continuation](../../.controller/domain-daemon/tasks/clients.md#events-compatibility-continuation-after-s9) closes the explicitly recorded archive, filter-warning and observer source gaps as one producer/consumer release. [`events/history_store.rs`](../../src/events/history_store.rs) owns scoped read-only archive manifests and tuple continuation; [`observer_store.rs`](../../src/events/observer_store.rs) owns exact temporary endpoint admission and postcommit wakes. Waiting, interruption, output, cleanup and explicit reset observation stay in the originating CLI. Their authored cases await integration's fixed-input receipt; earlier s9 evidence does not cover these bytes.

## Native launch, operator kill and resume consumers

The fresh-launch CLI is `agentx launch --tool TOOL [--count N] [options] [-- native-args...]`. Selectors and defaults are declared in [`LaunchArguments`](../../src/cli/commands/launch.rs); shared flags and the strict native boundary are declared in [`LaunchOptions`](../../src/runtime/launch_options.rs). Bare tool and numeric-prefix entry points are removed. `run` still executes workflow scripts. Resume/fork use the same `--` boundary. TUI and bundled workflows construct this grammar; configured native defaults bypass outer parsing. Existing live hosts are not rewritten by a source/package update.

The actual launch entry uses one captured invocation and scoped configuration before acquiring `cli::client::Session::for_launch`. Local runtime launch and remote Relay dispatch retain that Client generation; human attribution labels do not create participants, and shared Codex callers retain their qualified attachment. Help, preview and the existing stdio version probe bypass daemon acquisition. `report_launch` observes native participant/readiness projections, and launch tips mark only after successful originating output flush. Main reports PTY spawn failure through the exact native launch fence.

Operator kill uses `agents/lifecycle_service` tickets through `runtime::kill_client`: a one-time issuance grant precedes signal/pane I/O; completion retains canonical child-first retirement effects. A concurrent hook/PTY stop is recovered only from the exact canonical killed-retirement record. Native results and host cleanup remain separate facts. Resume/fork uses `runtime::resume_client` and a typed ResumeFence carried through actual native launch reservation. Pinned historical sessions keep latest cursor metadata; source changes, namesake replacements, new live session bindings and changed fork reservations fail closed. Provider transcript discovery stays in the originating host, and the captured environment/cwd must agree with that host. CLI presentation uses the same native plan; borrowed legacy scenario helpers are test-only.

These are source-callable migrations. Integration owns the immutable snapshot, process and failure evidence; this section does not claim verification beyond the acceptance record. System retirement cleanup carriers remain an active domain refinement tracked in the client/consistency Tasks.

## Cleanup and diagnostic projections

Listing, status diagnostics, the TUI maintenance sweep and resume selection now carry the participant domain's frozen CleanupOutcome to their originating hosts. CLI/TUI apply runtime stop effects only after receiving the committed result; lost-reply reconciliation reuses the same request identity. Resume retains selection and cleanup together before its original row can disappear, while its actual launch reservation only validates the selected source. The daemon uses stored-only status/finalization; original records allow host log/terminal evidence enrichment. Summary is a pure read and needs no cleanup carrier. Runtime's ObserveLaunch owns the corresponding launch observation carrier.

Actual relay/status commands acquire typed sessions before the remaining legacy router branch. Relay uses native queued/peer snapshots and keeps all short aliases for remote shutdown notification. Status consumes the dedicated bounded Diagnostics projection, including canonical counts, five recent launch failure rows, persistent dev_root and cleanup. Tool/Provider file checks and rendering remain local. Configuration and preset validation share the invocation's explicit scope. These paths no longer borrow or open managed storage; full cutover and independent evidence remain tracked in the [client Task](../../.controller/domain-daemon/tasks/clients.md).

## Listen lifetime and output

The actual listen route uses [native event lifetime operations](../../src/events/service.rs) before the legacy router branch. [The daemon adapter](../../src/events/listening_store.rs) binds a unique listen ID to generation, authenticated peer, captured invocation and exact participant. Begin atomically checks a recent filter match or installs a once subscription after adhoc listening status; a replay returns the frozen setup result without recreating a fired subscription. Pulse changes only last_stop. End removes only that subscription and matching endpoint port and cannot overwrite a successor/new listener's status. Persistent user subscriptions remain distinct.

[The originating host](../../src/cli/commands/listen_client.rs) owns TCP wake waiting, timeout/SIGINT/SIGTERM, ordered JSON/text, bounded backlog drain and late hints. It writes and flushes the existing frozen mailbox batch before confirming its exact receipt. Hooked participant status remains hook-owned; adhoc timeout remains inactive without an exit marker. A transport/generation/identity error never selects local storage. [Native event context](../../src/events/AGENTS.md) links meaningful authored cases; independent execution remains with integration.


## Context bundles

[Bundle CLI](../../src/cli/commands/bundle.rs) preserves implicit list/show plus list/show/cat/chain/prepare/create grammar through the original Session. [Native Bundle](../../src/messaging/bundle_service.rs) nests in Messages; [bundle_store](../../src/messaging/bundle_store.rs) owns required SQL, fixed context categories and generation/peer/invocation/exact-actor retained Create. Same-ID lost-reply recovery returns the original event/result; changed input or participant incarnation rejects, including replacement before first create. Referenced-event pages evaluate JSON intervals without expanding IDs and stream through 1000-row/2 MiB bounds with a frozen watermark. List/context requests preserve caller counts across descending pages. File metadata, warnings and Provider transcript parsing stay on the originating host. Source-only scenarios live in bundle_store/tests.rs and native_bundle_tests; independent integration owns execution.

## Reset and storage ownership

[Reset](../../src/cli/commands/reset/mod.rs) retains hooks/all grammar, the AI --go preview and originating file scope. Hook-only removal bypasses acquisition. Conversation/all reset uses the original native Session for summary, exact participant stops and scoped relay-worker shutdown. Maintenance owns the consistent standalone archive, atomic managed-state clear, generation rotation and reset event; the client never deletes live database files or reopens SQLite. Stop or worker-shutdown failure prevents the reset request. A lost reset reply is an unknown outcome: the client does not replay it or infer success from generation observation, and full-reset file/config deletion does not follow. After a confirmed response, an explicit connect_existing must match the returned generation before relay notification. The router suppresses post-reset mailbox delivery through its retired actor/generation. Scoped temporary/integration/config effects remain host-owned. Historical raw reset and router context/status/output adapters are test-only. Actual host cases and current source readiness stay in the Task; this architecture does not imply independent execution.
