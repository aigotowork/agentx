# Observation contracts

## Authority and support

Shared value declarations and pure validation/clock behavior are now native in [`src/observability/context.rs`](../../src/observability/context.rs); that source is their sole exact authority. They have authored unexecuted cases, not an executable observation acceptance receipt. Runtime, configuration and events retain their offered operations, payloads, errors and limits in their owning native modules/designs, with actual work/evidence tracked by the [implementation Delivery](../../.controller/observability/implementation.md). A native shared type does not establish working instrumentation, passive IPC, CLI or Web support. The [engineering map](engineering.md) owns source homes and dependency direction.

Reuse native [`RequestId`, `CallerContext`, `CallerProcess`, `RequestContext`](../../src/service/context.rs), [`ParticipantRef`, `ExecutionId`, `BindingId`, `AttachmentOwnerId`, `ActivationTarget`, `ProviderSessionKey`](../../src/agents/attachments.rs) and domain message/receipt/event identifiers by reference. These values do not become interchangeable because their current encoding is a string. An observation reference is never an authorization capability, deduplication key or proof of liveness.

## Shared references

Import shared values from [`crate::observability::context`](../../src/observability/context.rs): `ScopeRef`, `DaemonRef`, `ObservationEpoch`, `ClockId`, `ObservationTime`, `UnixMillis`, `MonotonicMillis` and `DurationMillis`. Their native serde mapping and declarations replace the former design signature copy. [`Module guidance`](../../src/observability/AGENTS.md) defines allowed imports and maintenance ownership.

| Type/field | Construction and equality | Lifetime/cardinality/absence |
| --- | --- | --- |
| `ScopeRef.canonical_scope` | Exact canonical data root selected by the existing scope resolver; never a Provider home, archive label or browser-supplied pathname | One canonical root has at most one live managed-storage owner. Aliases share identity. A pre-acquisition client may know only an uncanonicalized selector and must not manufacture this ref. |
| `DaemonRef.daemon_instance` | Nonempty opaque value from the actual daemon lease; equality requires scope and instance | Fresh each process incarnation. Independent of PID, native build cohort and database generation. |
| `ObservationEpoch.database_generation` | Nonempty exact committed generation copied from the application's durable key through its validated mirror | One daemon can observe successive epochs after reset. Restart creates a different epoch even when the same DB generation remains. Unknown/unpublished generation is not an empty string epoch: runtime returns only `DaemonRef` plus explicit unavailable generation evidence. |
| `ClockId` | Nonempty UUID v4 generated per producer process clock origin; equality is a clock-domain comparison, never authority | A producer measures monotonic milliseconds from one retained `Instant` origin. Restart/re-exec changes clock ID. Child processes do not inherit comparison authority. |
| `UnixMillis` | Unsigned milliseconds since Unix epoch, used for human chronology and external deadlines where the existing contract requires them | `None` means wall time unavailable/unrepresentable; wall time can move backward and cannot establish causal order. |
| `MonotonicMillis` / `DurationMillis` | Unsigned whole milliseconds; duration uses checked subtraction only within the same clock domain | Zero is valid. Cross-clock elapsed time is unknown, not negative or zero. Checked overflow makes the affected facility unavailable; the owner can replace it only without reusing references. It never rotates the durable generation itself. |

`ScopeRef` identifies local data scope, not a machine-global registry. References from another local host require that host's explicit consumer boundary; equal path text on two machines does not establish shared scope. Scope, daemon, database, attachment and stream fences must all be checked where their owner requires them; one cannot substitute for another.

The daemon composition supplies one shared process clock origin/ID to runtime, configuration and journal producers. Originating clients have their own clock domain. Re-encoding a timestamp cannot transfer clock comparability. Application-owned generation is a committed UUID in the existing native implementation; the wrapper retains its exact string and never generates a replacement generation itself.

### Valid construction and failure

[`Native context`](../../src/observability/context.rs) owns `ObservationValueError`, `ScopeRef::from_canonical_scope`, `DaemonRef::from_lease`, `ObservationEpoch::from_committed_generation`, `ClockId::parse` and validation, plus checked duration/deadline arithmetic and `ObservationTime::elapsed_since`. Constructors and native deserialization apply the same boundary validation. Exact signatures/errors are maintained only there.

The first constructor validates an absolute value already resolved/canonicalized by the passive scope adapter or actual lease; it does not create directories, canonicalize by I/O or prove scope ownership. `from_lease` requires the actual nonempty lease instance; it cannot authenticate a caller-provided claim. `from_committed_generation` rejects an invalid/empty UUID; only trusted composition supplies the committed generation. Boundary mapping validates deserialized values equivalently. No constructor or elapsed calculation has storage, process-control or network effects. `elapsed_since` returns `ClockMismatch` for different IDs and `TimeOverflow` for reversed/unrepresentable monotonic subtraction. Domain contracts own their mapping of these validation errors to actionable read errors.

`ObservationClock` retains one local `Instant` origin and random ClockId; composition supplies clones to all daemon stores. `now` returns checked monotonic time with best available wall milliseconds. `at_instant` maps a retained local instant/deadline to that same clock and leaves wall time unknown rather than inferring it. Construction of a second clock is a different comparison domain, even within the same process. Originating clients keep their own retained clock; no process-global clock or daemon environment substitutes for it.

## Evidence and time

[`Native evidence declarations`](../../src/observability/context.rs) own `EvidenceOrigin`, `UnknownReason`, `EvidenceStamp`, `EvidenceValue<T>` and `Evidence<T>`. The former design-only Rust block was promoted; retain the following semantic obligations alongside the native source, not a second editable signature copy.

The stamp describes when and how the producing boundary captured or attempted the observation; each domain record retains its actual source reference and derivation inputs. `EvidenceOrigin` expresses provenance class, not authentication. An OS-observed PID/incarnation and a caller-reported environment are different evidence even in the same request. `Derived` values link their input refs in their owning domain, and do not receive stronger certainty than those inputs.

`Present` means the value was observed at the stamp; it does not promise current truth forever. `Absent` is a positive, complete lookup with no matching value within the exact lookup scope/frontier. Domains may use `Present(None)` when `None` itself has native meaning, such as an observed process whose incarnation could not be obtained. `Unknown` means the producer cannot establish the fact; `Withheld` means it deliberately does not disclose the fact or value. A missing optional correlation ref is not automatically an `Absent` domain fact.

Freshness is a domain-owned query interpretation of the stamp, clock comparability, fences and its stated validity budget. Immutable invocation captures remain historical facts; a current-health interpretation may become stale without changing that capture. A consumer can compare monotonic ages only when clock IDs match. A remote consumer uses returned producer ages or its own receive-time estimate and labels the latter; it never subtracts independent clocks. Do not install a universal TTL or delete durable business evidence because a volatile observation expired.

The catalog indexes sole authorities rather than editing another copy of their fields. The daemon aggregate embeds the owners' finite operation types and preserves their typed errors inside the response; transport/authentication/compatibility failure remains distinct. A missing local stage or lookup cannot be turned into an empty successful server result.

Exact input/result/error types and limits are linked above rather than recopied here. Contract compatibility means matching field meaning, units, identity, absence, read/write/effect and lifecycle guarantees, not just successful serialization. Domain transport loss remains [`DaemonError`](../../src/daemon/mod.rs); application failure remains [`ServiceError`](../../src/service/error.rs). Each observation offering owns its errors, including generation-unavailable, stale epoch/cursor, unsupported capture, disclosure and pressure. A consumer must not collapse those into “daemon down” or “operation failed.”

## Shared composition rules

1. Validate each returned `DaemonRef` against the selected existing daemon. For dataset-bound joins require exact `ObservationEpoch`; reject/label old epochs instead of silently joining them. Missing generation permits process diagnosis only.
2. Domain owners allocate and validate their local sequences and references. Existing `RequestId` groups a logical operation only where that domain supplies reconciliation. A new client attempt means a transport send, never a permission to repeat a business effect.
3. A successful native result, a server write attempt, OS socket write completion, client receipt and an observed external effect remain separate facts. Missing telemetry cannot negate a durable commit or external effect.
4. Observation reads are bounded and passive. No new owner of DB/event history, Provider resources, runtime hosts or reset policy is created. All writes mean bounded volatile instrumentation only unless an explicitly linked existing domain operation is invoked.
5. Diagnostic disclosure must be safe under joins of all exposed fields/families. Omitting a field from one record is insufficient if another field/record reconstructs the complete native mutation token or receipt. Export non-authorizing observation refs/projections; retain native mutation evidence under its existing owner's authority.
