# Runtime and originating-client observation

## Authority and source basis

Runtime declarations and registry behavior are now implemented in [runtime.rs](../../src/observability/runtime.rs) and [registry.rs](../../src/observability/registry.rs). Those native declarations own exact types/signatures; the semantic rules below remain the design authority. This source release has not been compiled or executed by the runtime owner. Passive endpoint/client/source instrumentation belongs to composition, and executable acceptance belongs to independent integration; neither is established by this registry release. Shared scope/era/time/evidence declarations are imported from [contracts](contracts.md). Configuration [capture/snapshot refs](configuration.md#capture-and-snapshot-references) and the event [sink/stream](events.md) remain owned there. The [implementation Task](../../.controller/observability/implementation-tasks/runtime.md) owns current execution state; the [completed design Task](../../.controller/observability/tasks/runtime.md) retains earlier design evidence. The completed [daemon acceptance](../../.controller/domain-daemon/delivery.md#accepted-local-outcome) remains the implementation baseline.

## Runtime identity contract

Native authority for runtime-owned values, reader/reporter and producer contracts: [runtime.rs](../../src/observability/runtime.rs). The finite `InspectionRequest`, `InspectionResponse`, `InspectionCall`, `InspectionResult` and passive scope/client entry functions belong to `src/daemon/observation.rs`, composing public leaf contracts without making them import the daemon. Imported native references retain their own definitions; no existing identifier is replaced.

Exact implemented declarations: [native runtime contract](../../src/observability/runtime.rs).

`ClientInvocationId` is fresh before originating capture for one client invocation/binding lifetime. Clones retain it. Configuration owns immutable revision allocation through a shared checked counter; different `with_invocation` branches cannot accidentally reuse a revision. `ClientAttemptId` is fresh for each Acquire, Probe or Call attempt, allocated before its first fallible local step. Discovery retries inside one Acquire can open multiple connections with the same attempt; each possible business Call write has a distinct attempt. No attempt ID licenses retry. `RequestId` remains the existing domain reconciliation key and can correlate several attempts/observations only under that domain's rules.

Server IDs start at 1, increase monotonically and never recycle within a `DaemonRef`, including across reset. Allocate a RequestObservationId only after fully decoding one Call, even if admission later rejects it. One connection has zero or one decoded business Call. A client attempt can have zero server evidence. Every server ref includes the daemon; naked sequence numbers, PID, names and wall time are never sufficient joins. Checked sequence overflow makes that observation facility unavailable until a fresh daemon incarnation; it does not wrap or stop otherwise valid business operations.

`AcceptedPeer` is constructed only by the authenticated local transport adapter from native `CallerProcess`; it is not deserializable from report bodies. A returned safe projection can be serialized for consumers. It captures PID/incarnation at that connection, not perpetual process liveness. Known `(pid, incarnation)` may share a PeerObservationId within one daemon. If incarnation is missing, allocate a fresh peer observation per connection; two `None` values never establish sameness. Origin UUIDs are caller claims; two authenticated peers claiming the same UUID remain distinct. Configuration/report storage uses `AcceptedPeer` as intake evidence, never UUID equality alone.

## Passive inspection and structured local failures

The ordinary `Client` and CLI Session are unsuitable for passive diagnosis because they can create directories, start a daemon or perform participant/mailbox behavior. The planned observation adapter has a separate existing-scope resolver and a separate authenticated endpoint under the same lease. It performs no mkdir/chmod, startup-lock acquisition, daemon spawn, configuration mutation or managed-database construction.

Exact implemented declarations: [native runtime contract](../../src/observability/runtime.rs).

The following finite adapter aggregate and passive client entry functions have their planned declaration home in `src/daemon/observation.rs`, separate from the runtime values above:

```rust
pub enum InspectionRequest {
    Runtime(RuntimeRequest),
    Configuration(ConfigurationRequest),
    Events(ObservationRequest),
}
pub enum InspectionResponse {
    DaemonChanged { expected: DaemonRef, actual: DaemonRef },
    Runtime(Result<RuntimeResponse, RuntimeReadError>),
    Configuration(Result<ConfigurationResponse, ConfigurationError>),
    Events(Result<ObservationResponse, ObservationReadError>),
}
pub struct InspectionCall { pub expected_daemon: DaemonRef, pub request: InspectionRequest }
pub struct InspectionResult {
    pub ready: InspectionReady,
    pub response: InspectionResponse,
    pub received_at: ObservationTime,
}
pub fn resolve_existing_scope(input: ExistingScopeInput) -> ScopeLookup;
pub fn inspect_existing(scope: &ScopeRef, expected: Option<DaemonRef>, request: InspectionRequest)
    -> Result<InspectionResult, LocalFailure>;
```

`ConfigurationRequest/Response/Error` are exact imports from the released [configuration facade](configuration.md#retained-lookup-and-comparison); `ObservationRequest/Response/ReadError` are imports from [Events](events.md#stream-identity-and-read-contract). These are not new schemas. The daemon wire adapter embeds these finite native declarations; it cannot offer arbitrary service/SQL/argv dispatch or externally publish RuntimeEvent/DomainCommitted. `AcceptedPeer` accompanies each server-side call as transport context, never an input field. The common adapter validates selected scope and expected daemon before routing. A stale expected daemon yields route-neutral `InspectionResponse::DaemonChanged { expected, actual }` **before any leaf operation**, including Events::Describe and Configuration::Head(None) which have no old epoch to construct a leaf error from. Consumers handle this branch before matching the requested response family and explicitly rebind only when desired. Leaf epoch/stream mismatches then retain their owner's exact outcomes. Transport failures remain structured `LocalFailure`/native `DaemonError` at the adapter and are never routed through `service_error`.

`inspect_existing` performs one short Hello and operation within the absolute inspection budget. `expected=None` binds the first query to the actual authenticated Ready daemon; `Some(D)` retains the supplied selection and sends that D in InspectionCall after handshake, so a replacement returns DaemonChanged instead of silently following it. `received_at` belongs to the local consumer clock; ready/snapshot stamps remain the daemon clock. Later queries use the previously selected DaemonRef; dataset cursors/configuration refs remain independently fenced. These functions do not construct an ordinary Client/Session or retry a business operation.

Existing scope lookup expands an already-selected relative path against the supplied originating cwd, calls read-only canonicalization, checks directory/private-owner constraints without repairing them, and derives the endpoint from canonical scope and current user. Home/tilde/default selection stays with [`resolve_agentx_dir_from_env`](../../src/paths.rs); lexical selection does not fabricate a ScopeRef. Missing/unreadable/invalid paths yield the exact lookup branch and origin evidence without creating `.agentx`, `.daemon` or `/tmp/agentx-*`. Alias paths produce the same ScopeRef. Missing endpoint or refused connect means that this inspection attempt failed; it does not prove the daemon is stopped. Retained earlier snapshots remain historical with their original stamp.

Inspection uses the existing framing and OS-peer validation mechanisms with a scope-keyed endpoint discriminator: `/tmp/agentx-{uid}/{scope_digest}.observe.sock` on Unix, using exactly the existing canonical-scope digest and per-user base; on Windows append `-observe` to the existing scope-keyed pipe name. A fixed user-wide `observe.sock` is invalid because it would collide across scopes. Passive lookup does not create or repair the base directory. Private ownership/DACL, endpoint-inode cleanup and scope/build/protocol checks match ordinary IPC. The inspection Hello is distinct from business Ready: it can return `DaemonRef` and explicit unknown generation during application initialization or fail-closed shutdown. It never converts unknown generation to `""` in an ObservationEpoch. Client validates kernel daemon PID and compatibility before using the response. No runtime image hashing or OS process census is added.

Resource contract: one inspection admission thread constructs/drops its own platform listener and owns at most **two** short workers, independent of the business 32 workers/16 jobs and of the Application dispatcher. Accept a single native query/report after Hello, then close. Each inspection connection has an absolute **1,000 ms** accept-to-close budget, max **64 KiB request** and **512 KiB complete response**, enforced by capped serde framing before allocation beyond that bound. The client uses an independent 1,000 ms whole inspection-call deadline; there is no cross-clock deadline subtraction. CPU steps have fixed input/work bounds and recheck the local deadline before writing; scheduling is not forcibly preempted by the API. There is no inspection job queue, subscription, held follow connection or additional DB owner. When both workers are occupied, close a newly accepted inspection connection immediately; if a bounded Busy frame can be written without waiting it may be sent, otherwise the client retains the connection-stage failure. Same-user flooding/OS scheduling can still prevent a read; bounded resources are not a hard availability or latency guarantee.

Inspection worker bodies copy bounded snapshots, call domain-owned reader/report ports on already-published in-memory state, release locks, then serialize/write. They never call Application, run a resolver, access SQLite, inspect arbitrary process/environment/files, wait on Provider I/O or perform a business retry. Events follow is short Describe/Read polling in the consumer. Configuration report validation is its own restricted intake, not arbitrary source resolution.

## Request, connection and host facts

Exact implemented declarations: [native runtime contract](../../src/observability/runtime.rs).

Every row is a stamped historical observation, not a replacement domain entity. `OperationLabel.variant` is a **closed source-derived literal** such as `Submit`, `Acceptance` or `RegisterNativeRoot`, at most 64 ASCII bytes, selected by a native exhaustive request match; never user text/argv or serialized input. Domains retain sub-operation meaning. RequestId/string refs retain exact values only within row size limits; oversized correlation becomes unavailable whole, never truncated into a different identity. Ordinary request validation is unaffected by telemetry admission.

`generation_at_decode` is the nonempty generation captured by the business Ready used for that Call; dispatch records its actual current validated generation. `generation_after_return` is Present(nonempty generation), Unknown(GenerationUnavailable), or Unknown(NotCaptured) before return. A resetting request can enter under G1 and return under G2. Its observations do not claim one atomic snapshot across reset. Effective deadline is Present(server-clock instant) derived from the minimum of the connection budget and converted caller wall deadline; caller absolute milliseconds remain claims, not a cross-clock duration. A decode-time rejected expired deadline uses `NotRun(Admission(Deadline))` and `effective_deadline=Unknown(NotCaptured)`; no valid budget is invented for it.

`ReturnedOk` means native Application returned `Ok(Response)`; it says nothing generic about commit, delivery or completed work. `ReturnedError(OutcomeUnknown)` remains an unknown native result even though the function returned. Execution and reply are independent: Running/Returned can coexist with an abandoned reply wait and a failed write. Reply wait and reply write are also independent: after a wait is abandoned, the worker may attempt to write OutcomeUnknown, and that separate write may succeed or fail. `ReplyObservation::Pending` is only the initial state before a worker starts waiting or writing; thereafter `Observed` preserves both dimensions. `ReplyWriteObservation::Finished` means the server write completed locally, never that the client read it. Runtime records no receipt or generic external completion. A dropped client connection does not withdraw an admitted job. Actual negative execution evidence requires the dispatcher/admission `NotRun` edge; a missing row cannot supply it. Enqueued/dequeued stamps remain after later transitions so a retained completed detail can explain its actual queue wait; the Queued state's stamp must equal `enqueued_at`.

`ConfigurationTrace::NotEvaluated` means no instrumented resolution point has reported for this request yet; it cannot establish that no configuration was used. Keep at most **8** actual resolution records in source order per request, including explicit skipped reasons, then increment `omitted_uses` with checked arithmetic. Refs do not pin snapshots. Capture failures do not change resolution/business behavior. Source-stage and snapshot identity remain owned by configuration; multiple actual load points are not collapsed into one daemon-wide configuration.

Host projections are emitted only after successful committed owner results for RegisterNativeRoot/RenewNativeRoot/ReleaseNativeRoot/RegisterProcess and validated later process operations. Internal owner registration tokens distinguish replacements but are never disclosed or retained in telemetry; a successful replacement allocates a new HostObservationId. `target` is Present only for native root attachment; process hosts retain their exact ParticipantRef and independently observed child evidence. No projection is inferred from an invocation name, claimed process_binding_id or transient connection count. Zero open IPC connections can coexist with many observed registered hosts. A host with no new observation is “last validated at T,” not proven stopped or presently active. Native lifecycle/heartbeat policy, positive exit evidence and attachment fences remain authoritative. After restart an untouched durable host may have no runtime projection until an actual owner operation publishes one; coverage explicitly excludes a full census.

## Snapshot, metrics and read contracts

`admission_busy` counts both a full native connection pool (before decoding a Call) and a full dispatch queue (after decoding a Call). A pre-decode rejection does not create a request row or increment decoded calls.

Exact implemented declarations: [native runtime contract](../../src/observability/runtime.rs).

Snapshot is process-only when generation is unknown; no dataset is fabricated. Gauge bounds are worker-associated business connections 0–32, queue 0–16, executing 0–1 and inspection 0–2; an immediately rejected over-limit accept does not occupy a worker gauge. Current progress time updates when the dispatcher checks/accepts/dequeues/returns, not from an independent heartbeat pretending Application made progress. Admission tick is independent. A live Running operation's elapsed time is `sampled_at - started_at` within the server clock; an old dispatcher tick while it runs cannot establish a deadlock. Consumers may present a **slow** indication at 5,000 ms queue/application age, clearly a diagnostic threshold, never failure/kill/retry authority. Initializing and Draining retain the current work; unknown or stale evidence stays explicit. Host “last validated” age may be shown, but no universal runtime host TTL decides domain liveness. `full_host_census` is false for this selected projection design.

Connection handshake success establishes observation reachability and compatibility at that time. `RuntimeSnapshot.lifecycle`, activity, queued age and progress provide application/pressure evidence. A separate health boolean that would equate these dimensions is deliberately absent. Consumers retain receive time and label cached evidence; a snapshot older than 2,000 ms by **consumer receive-age** is stale for a live view. This display policy is not a TTL on source facts and cannot use subtraction across clocks.

Lifetime counters start at daemon lease acquisition and survive generation reset; restart zeros them. Recent metrics use **60 one-second server-monotonic buckets**, include only the current generation (or initialization without an epoch), and clear on committed generation change. An old-generation job's late return/rejection still increments daemon lifetime counters, but never adds a duration or operation count to the new-generation window; the resetting request's own cross-generation sample is likewise excluded from that new window. `from` is the actual retained window start; `through` is this sample, so the first partial minute is not a full-minute rate. Queue wait is successful enqueue to actual dequeue/rejection; Application latency is actual `handle` entry-to-return only; server-to-reply is decoded Call to local write completion only. Abandoned/no-return calls have no completed sample. Histograms use ms upper bounds `[1, 5, 20, 100, 500, 2000, 10000, infinity]`; report counts only, without fabricated percentiles. No source-time reordering or user-selected metric labels; per-operation aggregation, when needed, uses the closed native variant set. No timer increments successful-call counters. If checked counter/time/revision arithmetic cannot advance, Snapshot returns Unavailable rather than a wrapped or silently zeroed metric set; business behavior is unchanged.

List `limit` is required 1–64; invalid values fail. Sort by descending local ID, exclusively below `before`, with no retained per-reader cursor. Pages are live samples: intervening updates/expiry can alter later pages; refs and revisions expose this, and absence is not complete history. Scan at most the finite registry capacity, never arbitrary SQLite. `next_before` is the last scanned ID when more retained candidates remain. Detail lookup returns DetailUnavailable(NotCaptured/Expired/Evicted/Pressure) where known, otherwise NotCaptured; it never claims “request did not happen.” Unknown/excessively large IDs, malformed UUID/ref/label and wrong-scope refs are input errors; same-scope old daemon is DaemonChanged. Read-lock contention returns Busy without changing any cursor or business outcome. There is no negative cache retaining one tombstone per lost request.

## Originating attempts and report admission

Exact implemented declarations: [native runtime contract](../../src/observability/runtime.rs).

`LocalFailure.at` is optional because even diagnostic time capture can fail. A known independent transport failure retains its original stage, kind and OS code with `at=None` when the clock cannot supply a timestamp. A failure of the diagnostic clock itself is `ClockUnavailable` with `os_code=None` and `at=None`. Missing time establishes no ordering, duration or age; never substitute a sentinel, a new clock origin or inferred wall time. Terminal report start/end/span times remain required. If those cannot be captured, decline the report rather than synthesizing time; an available local failure can still be returned. Report validation checks same-clock/range only for a present failure timestamp and rejects a timestamp or OS code attached to ClockUnavailable.

The origin freezes a terminal report after one attempt, with at most **12** stage spans and a whole encoded report at most **4 KiB**. Span clocks must equal the origin clock, each end must be at/after start, and spans are recorded in local execution order; source wall time is optional. Repeated acquisition probes may exceed 12 spans; increment `omitted_stages` rather than allocating more. The report contains codes, allowed paths and refs only: no environment, input/output body, launch JSON, actor/registration token or raw error strings. If a valid exact ref/path makes the report exceed 4 KiB, retain/report the failure without that optional evidence using Unknown(Pressure), or decline the whole report; never truncate identities. `last_ready` is the safe shape of actual observed readiness, normalized by the client adapter for business or inspection handshake; it is client-reported when later ingested, never re-authenticated historical server evidence.

Allocate the attempt before capture, so failed cwd/scope/environment capture has local evidence even with no invocation revision. Normal client failures preserve stage/cause before existing ServiceError conversion. Local acquisition duration includes startup-lock/discovery/spawn where actually performed; local call duration includes connect/Hello/write/read. These use only the local clock and cannot be subtracted from server timestamps to manufacture network latency. Caller request wall deadline remains native input; telemetry cannot extend it.

Before the first Call write begins, knowledge is NotWritten. Once writing might have delivered data, knowledge becomes MayHaveBeenWritten and remains so after write/read timeout unless an exact terminal reply is decoded. Receipt of a server failure distinguishes a pre-execution rejection only for the documented native failure boundary; generic outcome-unknown/error text cannot prove non-execution. A native Application result is recorded exactly by class, with domain receipts still separately required for effects. DiscoveryOnly never claims any business Call.

The origin keeps at most **32 reports/128 KiB** in process memory, oldest completed first on pressure; no disk spool or background report retry. It prints/exports safe evidence only through an explicit consumer outcome. If the process exits before output/reporting, that evidence is lost. An unreachable daemon has no report and cannot claim complete visibility. On later compatible inspection reachability a caller may explicitly submit **one terminal ClientAttemptReport**; submission never starts the daemon or repeats the business request. Report transfer/inspection self-traffic has no nested attempt report or detail event.

Intake receives AcceptedPeer from this **current** connection and the original terminal report as separate data. It validates bounds, clocks/enum/ref shape and safe disclosure, stamps current receive time and keeps source origin ClientReported. It constructs the Events-owned `ClientReportObservation { report, submitted_by: AcceptedPeer }` wrapper before calling the sink; the submitting peer stays visible and is not accepted from a body field. It cannot assert that the submitting peer was the historical process or that a claimed old daemon/scope existed. A report from another source era remains historical payload; it is not joined to a current server request by UUID alone. An exact live join requires the original accepted connection/request's OriginRef plus matching authenticated process incarnation; otherwise show a claimed correlation only. Configuration reports use the same AcceptedPeer contract and their own safe producer port.

Server intake retains at most **256 reports/1 MiB**, age **5 min** by receive monotonic time. It may reuse an exact duplicate report from the same authenticated known incarnation/attempt only when bytes match; differing input is InvalidInput and no overwrite. Unknown incarnation is connection-local and cannot deduplicate across connections. There is no durable/exactly-once report promise and no automatic retry after lost acknowledgement. `ClientReportReceipt.retained` is true exactly when `reference` is Some; that server ref can be read using ClientReportDetail, and ClientReports uses the ordinary bounded page contract. The referenced RetainedClientReport includes the current intake AcceptedPeer and original report. Runtime retention and event RecordDisposition are independent: one may succeed while the other drops. Intake fails with Busy/InvalidInput/Forbidden where appropriate; bounded retention pressure may return retained=false with explicit event disposition. A successful report receipt never changes knowledge about the underlying operation.

## Native producer and report ports

These implemented crate-private contracts are consumed by actual daemon/client/domain composition; they are **not** deserializable producer commands. The ordinary finite RuntimeRequest envelope routes reads to RuntimeReader and ReportClient to RuntimeReporter using transport-constructed AcceptedPeer. A facade may implement RuntimeReader over this dispatch, but a report cannot be processed without that trusted peer argument. Domain code receives these ports rather than private registry imports.

Exact implemented declarations: [native runtime contract](../../src/observability/runtime.rs).

Each `at` is captured at the actual named source boundary on the daemon clock, never supplied from a body. `Tracked { detail_retained:false }` preserves the finite active reference and aggregate updates while omitting an oversized detail; it is not proof of an available lookup payload. Skipped means instrumentation could not establish a ref, and updates with None still account the actual aggregate boundary where the recorder remains usable. IDs/slots are allocated before sharing context with queued work. Recording failures never fail an otherwise valid operation. Producer callback replay is not supported: native hooks call once at each actual boundary, and tracked transitions reject/ignore an impossible duplicate without incrementing gauges twice. Untracked hooks still have their native per-job/worker RAII guard to prevent duplicate accounting.

The implementation must order queue publication, not append instrumentation after a racing `try_send`: prepare the slot/stamp and nonblocking queue insertion in one short registry transition gate; a dequeuing thread can receive a Job but must acquire that gate before recording Dequeued/DispatchStarted. A failed `try_send` records AdmissionRejected before releasing the gate. No Application/transport/serialization occurs inside it. This prevents a fast dispatcher from making a request appear Queued after it already Returned. Dispatch entry and queue exit are owned by the sole dispatcher; connection/reply edges by its worker. Worker/dispatcher guards independently release their pin, so a timeout cannot prematurely reclaim a queued/running slot. Connection guards account Closed on normal/error/unwind exits; no per-request worker is spawned by recording.

`previous` on host publication is only the existing native owner's positively established same-registration projection; a new/replaced registration or unavailable previous projection passes None and allocates a new HostObservationRef. A missing previous projection never causes registration/renewal rejection; two observation refs may describe the same native host after retention loss. The owner derives this relationship from its native fenced result and never passes control tokens to the recorder. Host publication occurs after successful commit and cannot roll it back. Invocation/OriginRef claims and configuration refs enter DecodedCallInput only from the actually decoded native context; none is reconstructed from daemon-global environment or name lookup.

Inspection callbacks allocate ConnectionRef for AcceptedPeer and maintain the separate <=2 gauge, but do not publish business connection/request detail or events/counters. Passive adapter scope lookup and client stage failure capture happen outside the registry using the concrete ExistingScopeInput/ScopeLookup/LocalFailure types. RuntimeReporter validates and binds the peer, constructs ClientReportObservation, attempts bounded runtime retention, and only then calls the event sink without a registry lock. Its return separately reports runtime and event retention. Configuration's ConfigPeerBinding is exactly an alias of AcceptedPeer; its facade binds the same value and its selected expected epoch before report admission.

## Runtime event contract

The exact native event payload is imported by the [event envelope](events.md#envelope-payloads-and-correlation). Shared ObservationTime replaces any preliminary RuntimeMoment sketch. Runtime owns these stage meanings; Events owns collection order, streams, loss and retention.

Exact implemented declarations: [native runtime contract](../../src/observability/runtime.rs).

`epoch` is the exact era captured by this producer boundary, not blindly the current generation at later append. Epoch/daemon/ref mismatch fails event admission. Process-only startup facts with no epoch remain available in RuntimeSnapshot, but do not enter the dataset stream. A queued G1 request rejected after reset retains its request reference and original generation in runtime; an old-stream event may drop RetiredEpoch. Only an explicit post-reset transition carrying the current epoch can enter the new stream, and it cannot relabel the original Call as new-generation work.

Instrumentation updates the registry/counters first, releases its lock, then calls ObservationSink::record best-effort. Sink failure never changes lifecycle, gauges, native response or business result. The sink constructs server source stamps from RuntimeEvent.at and producer provenance; external report intake constructs ClientReported source stamp from report.ended_at, retaining original clock. External callers cannot supply Runtime/DomainCommitted event variants. Native commit/receipt facts use the Events owner's typed postcommit producer, not ApplicationReturned. All inspection query/report infrastructure is suppressed from detail collection; accepted report payload publication is the single intentional reported-origin event, so recording does not recurse.

## State transitions and failure meaning

| Current state | Trigger / guard | Next fact / behavior | Evidence limit |
| --- | --- | --- | --- |
| No lease | Existing-scope observation connect fails | Origin terminal report only | No daemon state is inferred; no scope/startup side effect. |
| Lease acquired | Before Application initialization | Initializing; inspection lane may bind, generation Unknown | Observation Hello is not business Ready. Failure before lane binds is origin-only. |
| Initializing | Application publishes committed generation and business listener binds | Serving, epoch available, dispatcher Idle | Producer construction/order must not race a false Ready. |
| Accepted | Peer/Hello valid, Ready written, peer closes before operation | Closed(HelloOnlyEof), no RequestObservationId | Could be a readiness probe; not a failed business request. |
| Call decoded | Stop/invalid deadline/full/disconnected queue | NotRun(Admission(reason)); attempt failure reply | Only explicit successful Call decode is correlated; undecodable bytes create connection failure only. |
| Call decoded | `try_send` accepted | Queued; queue gauge increments | Admission is not execution/commit. |
| Queued | Dequeue plus stop/deadline/ownership/instance/generation fails | NotRun(Dispatch(reason)); queue gauge decrements; native rejection | A queued expired job is never invoked, even if its worker already abandoned waiting. |
| Queued | Dequeue validates | Running; queue gauge decrements, executing=1 | Dispatch time and validated generation captured immediately before handle. |
| Running | Worker deadline/disconnect/stop before reply | Execution stays Running; Reply becomes WaitAbandoned | No cancellation or replay permission; Application may still commit. |
| Running | Application returns | Returned(native class); executing=0; observe returned generation | Error class is distinct from a transport failure; exact effect remains domain-owned. |
| Returned / NotRun | Server reply write completes or fails | WriteFinished / WriteFailed | Completed local write does not prove client receipt. |
| Serving | Graceful stop | Draining; business admission stops and queued jobs reject; current handle continues | Inspection can show Draining while handle is held; current native handler has no promised hard stop deadline. |
| Draining / Failed | Application returned/dropped and business workers joined | Stopping; close inspection listener, finish/join <=2 bounded workers, drop registry, release lease last | Crash/unwind need not publish terminal rows/events. A permanently hung handle can retain lease/lane until process termination, matching baseline ownership. |
| Any dataset state | Reset commits and generation mirror publishes G2 | Same daemon; new epoch/metric window/config/journal; old admitted jobs still fence G1 | Retain process-level request chronology with exact before/after generations; do not join old refs into new data. |
| Process restart | New lease instance with same durable generation | Fresh DaemonRef, IDs, clock, counters and volatile registry | Old client reports are historical; no runtime/stream continuation survives. |

Snapshot and short read cancellation close only observer resources. They cannot cancel a business request or release a host claim. A connection may disappear while its queued job or Application invocation remains; keep that request observation pinned until dispatcher resolution and reply-wait termination. If the process crashes, no fabricated Interrupted/NotRun result can establish what the previous process committed. `Interrupted` is emitted only when this process positively observes its dispatcher unwinding; recovery into a new daemon does not edit vanished predecessor rows.

## Bounded state maintenance and concurrency

Use one in-memory runtime registry, built under ScopeLease and owned by daemon composition. A short Mutex protects compound row/gauge transitions; it contains **no** SQLite, resolver, Provider, transport I/O or allocating response serialization. Business producers hold it only for bounded transition/size-accounting work. The capped counting serializer may count at most the selected row/report byte budget while this lock is held; it emits no payload buffer and performs no external I/O. Full response/event serialization remains outside the lock. This concrete implementation refinement keeps exact encoded-byte admission without introducing an unbounded copy or a second publication race. Readers use `try_lock` and return Busy instead of waiting on an executing Application or building a queue of readers. An owned bounded copy is serialized after unlock. Mutex poisoning makes native reads return Unavailable; it does not turn observation faults into business failure or claim a clean request result. No separate poison counter is exported. OS scheduling remains outside a wall-clock bound.

| State | Selected bound | Update / reclamation |
| --- | --- | --- |
| Active connections | 32 business rows; inspection has 2 counters/context rows, no self-telemetry | Accepted/drop RAII guard updates exact open gauge even on ordinary error/unwind. Peer evidence is captured once per accepted business connection. |
| Active requests | 64 slots, each request detail <=8 KiB; at most 32 worker-associated plus 16 queued and 1 executing can require them, union <=49 | Pin from decoded Call until both dispatcher resolution and reply observation stop changing. Never evict executing/queued rows for completed history. Oversized/unrecordable detail increments drop coverage while aggregate execution tracking remains. |
| Completed request/closed connection detail | Combined 1,024 rows AND 2 MiB encoded-size-equivalent, request detail <=8 KiB, closed connection detail <=2 KiB; age 5 min from terminal completion | Oldest completed first; TTL measured by server monotonic clock. Detail loss does not alter business outcome or logical RequestId. |
| Peer projections | 256 rows AND 256 KiB; each <=1 KiB | Pin open connections; evict unpinned least-recently-observed rows after 60 s or count/byte pressure. Host references may later be unavailable; no hidden pin graph. |
| Host projections | 256 rows AND 256 KiB; each <=1 KiB | Keep last validated projection up to 5 min from native observation; evict oldest on pressure; released/reset rows are historical, not liveness claims. Native registrations are untouched. |
| Server client reports | 256 AND 1 MiB, each <=4 KiB; 5 min receive age | Validated admission only; oldest first. Same-peer exact-byte duplicate check is bounded by this table; no permanent dedup/tombstones. |
| Origin reports | 32 AND 128 KiB; each <=4 KiB | Process-local only; oldest completed first, released on process exit. Explicit output/report owns transfer. |
| Metrics | One lifetime struct, one current-era 60-bucket window, fixed histograms | Fixed native operation labels only; no immortal per-request/PID/path metric labels. Checked overflow marks metrics unavailable; never wraps or resets business state. |

Request detail uses one finite 8 KiB encoded budget at decode, every lifecycle/configuration update, and completed-history insertion. Scoped daemon identity repeats in the request, connection, peer and configuration references; chronology and up to eight configuration uses add further legitimate bytes. The former shared 2 KiB cap dropped ordinary real CLI rows in the [LAN follow-up](../../.controller/observability/lan-usability.md#real-use-blocker-ordinary-request-rows-exceed-detail-cap). The separate connection cap remains 2 KiB. Combined history still evicts at 2 MiB/1,024 rows; larger request rows consume that same budget, while active request payload is bounded by 64 × 8 KiB (512 KiB). Oversized rows still lose detail explicitly without truncating evidence or changing business results. The owner-authored regression `observability::registry::tests::ordinary_long_scope_request_retains_full_lifecycle_and_configuration` covers a demo-shaped long scope, real-shaped peer/origin, successful queue/dispatch/reply completion, all eight retained configuration refs, and nonempty completed reads; execution and real-product acceptance remain controller-owned.

Runtime steady retained payload is at most **4 MiB**, plus the fixed active-slot/gauge/metric arrays and <=2 capped response buffers. Size admission uses the actual selected serde representation with a capped writer; do not allocate unlimited strings/decoded copies before deciding a row is oversized. Existing business Call frames retain their native 8 MiB bound; telemetry retains only safe bounded labels/refs. Registry detail admission failure cannot block an otherwise accepted operation. Finite active dispatch/queue references and scalar gauges survive detail eviction, and activity exposes missing detail through coverage rather than inventing an idle state.

Insertion and periodic cleanup occur on native transitions and a bounded inspection control tick, at least once per second while the daemon is scheduled. Scan fixed capacities only; no cleanup task per row or dynamically spawned timer. Metrics use monotonic buckets. Event/config stores retain their independent [budgets](events.md#retention-state-transitions-and-resource-ownership); a ref from one store does not pin another. Readers copy at most 64 rows; page serialization stops before its 512 KiB complete reply bound. Snapshot revision increases under the registry lock for each successful compound transition; separately collected configuration/events/domain results are not an atomic multi-owner snapshot.

Reset does not reuse sequence IDs or zero daemon lifetime counters. Old request/connection chronology may remain for its normal TTL and is visibly G1; host projections are marked InvalidatedByReset and excluded from current-host interpretation. New-generation detail cannot acquire old ConfigSnapshotRef/stream identity. Configuration/journal rotate only after committed mirror publication and reject old producer handles; while composition rotates, dataset reads return unavailable rather than stale data as current. Business admission/dispatch continue their native generation checks. No observation-only reset/mutation API is selected.

Inspection starts after lease acquisition and can remain useful during initialization and graceful draining. Its adapter receives reader/recorder ports, never private stores. Listener binds/drops on its owning thread (including Windows handle-affinity rules); stop/drop guards close listeners, terminate bounded worker I/O and join before lease release. An initialization failure records Failed when possible, closes inspection cleanly and drops Application before lease. The design does not promise a postmortem endpoint after process exit. No worker or registry can outlive ScopeLease.

## Native implementation release and composition instructions

The runtime owner implemented [runtime.rs](../../src/observability/runtime.rs), [registry.rs](../../src/observability/registry.rs) and [13 authored state cases](../../src/observability/registry_tests.rs). Import `RuntimeRegistry` through `observability::runtime`, never the private store. `RuntimeRegistry::new(daemon, ObservationClock, Option<Arc<dyn ObservationSink>>)` returns a cloneable shared handle; `clock()`/`now()` use the actual daemon-supplied origin. `RuntimeEvent::validate()` and `ClientAttemptReport::validate()` are the sole runtime payload invariant helpers. UUID wrappers implement serde locally without changing dependency features. `OperationLabel::of` supplies a safe outer-domain label; composition can supply a source-owned static native sub-operation label where available, never user input.

| Existing source insertion owner | Actual native runtime call / ordering obligation |
| --- | --- |
| `serve_with_stop` / composition | Construct one clock and registry after lease, before application initialization; pass clones into lane/server/application producers. The selected runtime limits and independent-fact semantics remain unchanged. Source-level refinements are explicit: WorkerFinished releases the reply-worker pin separately from wait/write facts; exact byte-budget counting is capped while holding the short registry lock, with full response/event serialization outside it; duplicate reports use typed equality without serializing payload copies under that lock; malformed/overflowed observation state becomes unavailable rather than inventing successful idle metrics. Request events retain the source request generation after reset and are rejected by a new stream instead of being relabeled. RuntimeEvent validation includes optional client-attempt UUID shape, including direct native construction.

All thirteen native cases are **authored and unexecuted** by this owner, including the missing-time versus required-report-clock validation case added for the concrete clock-unavailable adapter incompatibility. The owner ran no Cargo, Node, formatter, test, build, package or platform/runtime probe. The independent native integration filter is `observability::registry::tests`; composition/integration still own the real held-Application/32-worker/16-job transport-isolation case, passive filesystem behavior, correct insertion coverage, platform endpoint cleanup and fixed-candidate evidence. No installed/live support claim follows from this native source release.
