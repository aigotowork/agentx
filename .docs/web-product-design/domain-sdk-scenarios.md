# First Web paths over the AgentX domain SDK

**Space:** A collaborator chooses a known office, finds an exact Agent in the Office or Conversations list, reads its AgentX messages, and returns to the same draft and place after changing presentations. **Management:** An operator chooses a known workspace, reads today's effective Roles alongside observed members, and checks what an exact execution actually adopted. These are task situations inferred from the [Space](space.md#first-usable-path-contract) and [Management](management.md#scenario-anchors) targets. The [Space delivery](../../.controller/space-domain-sdk/delivery.delivery.md#independent-verification) records the implemented host-configured slice and isolated browser evidence. The Management path below remains a design.

## Shared source and scope

| Boundary | Existing source | Selected use |
| --- | --- | --- |
| Native authority | [Management Service](../../src/management/service.rs), [office facts](../agent-management/offices.md), [message store](../../src/management/store.rs#L265) | Native scope, generation, exact identity, saved membership, current Role resolution and message history remain authoritative. |
| Named HTTP SDK, already used by both Web apps | [Web listener/client composition](../../web/management/api/client.ts), [public HTTP client](../../packages/agentx-client/src/management.ts), [Web adoption outcome](../../.controller/web-sdk-adoption/delivery.delivery.md) | Retain the existing client for paths and commands outside this slice. These are the same Management listener and underlying DTOs, not a new transport. |
| Public domain SDK, implemented separately | [Package export](../../packages/agentx-client/src/index.ts#L34), [public contracts](../../packages/agentx-client/src/domain/contracts.ts), [scope binding](../../packages/agentx-client/src/domain/index.ts), [workspace projection](../../packages/agentx-client/src/domain/workspace.ts), [exact Agent implementation](../../packages/agentx-client/src/domain/agent.ts) | Use package imports for `selectAgentXScope`, `workspaces`, `Workspace.roles/members`, and exact `Agent.snapshot/messages` as mapped below. Repository-internal SDK files are reading references. |
| Application and presentation | [Space controller](../../web/agent-space/src/offline/controller.ts) and [Management hooks](../../web/management/use-management.ts) | Share SDK values, structural address comparison and listener selection policy where useful. Space owns an Office, roster, conversation, draft, return point and scene; Management owns its workspace selection, independent catalog/member reads and inspection. No shared selection store, app model or scene library. |

For the first implementation, the consuming host supplies the existing listener URL plus an independently configured exact `expectedScope` (for a disposable run these are fixture inputs). Provide these as an explicit initialization value at Web composition; reuse the existing fetch timeout/cancellation policy. Current embedded defaults select a URL, and `managementUrl` can override it; neither provides an expected scope. A separately hosted or embedded deployment can opt into the object path only with its configured pair. A query link or unverified descriptor is not that configuration. Hosts without the pair keep their current entry; a configured but failed selection shows the failure and Retry for that pair. It never falls through to another listener or the HTTP path. This requires no new service. General adoption is a host configuration task.

Pin the returned `AgentXScope` for the session. The address is normalized listener URL + native scope + generation; workspace adds its canonical path or literal `global`; Agent adds name + current incarnation **or** stopped event. Keep native discriminators as strings. Use value equality, not JavaScript object identity. Space's existing routes preserve native exact references; only map to a domain address after matching the pinned listener and route scope/generation. Route format and default view stay as shipped. All-offices, legacy and unavailable are existing application scopes, not additional SDK workspace keys. Never reuse a draft, cursor, pending view or a retained operation in a different selected scope. A stale specific read leaves an unavailable exact subject; a confirmed selection reset requires explicit reconnect/reselection and a fresh app session. An exact `StaleReference` alone need not distinguish a gone Agent from a stale generation; report the exact read as unavailable and offer a same-generation workspace read or explicit reconnect. Never refresh the pin silently.

**Bounded reads.** For discovery use `scope.workspaces()`, preserving catalog sources and discovery cap/error information. An unlisted workspace was not observed. Each selected Workspace starts with one `members({limit})` (use `min(20, descriptor.max_page)`; use 1 for the sparse fixture). An explicit **Load more members** passes the unchanged `coverage.next` to the same Workspace. One click reads one page; stop at null. Accumulate first-seen exact keys for this exploration, update observations for repeated exact keys, and reset on workspace change or explicit refresh. Retained rows are observations, subject to exact revalidation. Abort superseded reads and check session + workspace + request revision before applying; deduplicate only exact addresses. Empty + next: “No matching members in this page” and retain continuation. End with no matches: “No matching members observed in this scan.” Errors keep prior successful pages and offer retry of the same page. Show loaded counts, the exhausted/continuable distinction, and legacy/unavailable scan counts as coverage, separate from known membership. `currentComplete` is the global feed's current-section signal, not workspace completeness; pages are not a stable multi-page membership snapshot. Explicit Global is an adopted membership, not a bucket for missing facts. Native/SDK owners would need a genuinely membership-filtered cursor if a later path promises complete or proportional workspace scans.

## Space · one conversation in Office and List

This binds [SP-01 and SP-02, plus the identity checks of SP-03](space.md#first-usable-path-contract). Enable the first SDK path for one selected known workspace (or explicit Global) at a time. The existing all-offices/legacy/unavailable paths are outside this adoption. Use the existing Office chooser, scene/list switch and conversation Blocks. Desktop keeps discovery and reader in one workspace where they fit; narrow shows the reader in the same body with a clear contextual Back. Keep exact subject, status and composer together; row/actor selection must be available by keyboard through the existing semantic controls and directory. No canvas-only gesture is required.

| Step / control | Binding and observable next state |
| --- | --- |
| **S1** Office chooser → choose workspace → **Load more members** if needed | `scope.workspaces()` → chooser; `workspace.memberPage()` → one roster. Both scene and list project this same set. Workspace change closes the old reader and preserves its exact draft; the destination gets its separate camera. Partial data never prunes saved seat capacity. Current rows have actors; stopped rows are selectable in the History list/cabinet, with no active avatar. |
| **S2** Select a current actor, directory entry or list row | Each sends `openConversation(exactKey, origin)` to the same page controller. Validate the key in the current roster, or use the existing exact route restoration seam with `scope.agent(address).snapshot()` for an addressed, unpaged target. The selected address must belong to the focused workspace for this path; a cross-office link remains an explicit navigation, with the existing route rules. Validate snapshot correspondence and membership, then bind `Agent.messages({limit})` to that address. Present loading, readable empty, records or read failure separately. Do not wait for an actor position to open the reader. |
| **S3** Read Messages → edit → switch **Office / Conversations** → **Back** → reopen | Existing page controller owns `selectedKey`, `reading`, channel, draft slot and edit revision; keep reader scroll as a view value keyed by exact subject + channel, and discovery return context keyed by workspace + mode. Editing increments the addressed draft's revision, including same-text edits. Presentation change alone changes no selection, channel, draft or message checkpoint. **Back** closes the reader and returns to the active presentation's exact anchor or row, else the directory/workspace control; restore scroll, focus and the user's existing camera zoom. Reopen the same key to get that draft. A changed workspace or another execution gets its own state. Drafts remain page-local. |
| **S4** Continue, lose access, or encounter a namesake | SDK message paging is forward in native history order ([store query](../../src/management/store.rs#L290)). Use `checkpoint` and `hasMore` for **More messages**; do not label the initial page “latest” or the continuation “older.” Append unseen message IDs without jumping the scroll position. One history read per explicit initial/continuation action; existing passive new-message refresh can use the same checkpoint once backlog is caught up. A late response after close, target change or reconnect is discarded by exact address + view revision; a mode change preserves the revision. After failed exact read keep visible identity and draft, show Retry/Back and disable send. On definitive stale/unavailable target never select the successor. History stays read-only and a loaded current namesake cannot inherit its state. |

Use [SpaceApp composition](../../web/agent-space/src/App.tsx#L30), [the existing controller](../../web/agent-space/src/offline/controller.ts), [navigation resolver](../../web/agent-space/src/navigation/browser.ts) and [controlled reader](../../web/agent-space/src/conversation/Conversation.tsx). Put the domain adapter at [LiveSpace](../../web/agent-space/src/live/controller.ts) and adapt values at [the existing projection seam](../../web/agent-space/src/live/projection.ts). Choose the active roster source once per navigation: domain projection for the selected workspace, existing feed for All Offices/legacy/unavailable. Publish the scoped roster atomically with its coverage and any separately resolved exact reader subject; that pinned subject does not inflate member counts or acquire a seat until observed in the roster. Run only the selected provider for the roster and exact Messages read. Keep the session controller the single owner of conversation/draft state. Reuse current app key serialization at the route boundary; the domain bridge must additionally be partitioned by pinned listener so a legacy key cannot be reused across endpoints. A page/supply refresh or a closed reader cannot grant a stale callback permission to mutate a different draft.

**Send boundary.** This slice adopts reading and draft continuity. A deliberate existing Send still belongs to the Web journal/capability path, with the same pinned endpoint/scope/generation and exact current target reverified; if correspondence or capability cannot be established, block it. The SDK's `CurrentAgent.prepareMessage/send` and `scope.operation(address).observe/wait` exist, but moving writes or old receipts to those ports is a separate migration. Stopped records have no SDK send port. No admission, delivery, reply, or receipt action is inferred from selection, draft editing or a scene effect. Keep uploads, Provider records, bound work, launch relations, office activity and human mailbox at their existing owners.

### Scene objects and ports

Use an immutable semantic projection over the existing scene values. Each mount has one authoritative latest presented frame tied to the input revision it depicts. Use the following projections and ports without introducing per-sprite classes, a graph runtime or a Contract Canvas dependency.

| Proposed object / properties | Owns or refers to | Port and existing owner |
| --- | --- | --- |
| `OfficeRoster`: workspace address, observed rows, coverage. Each `ActorCard`: exact Agent address, name/title, observed status, adopted Role fact and source. | Office wraps one SDK Workspace; each card refers to one observed execution. Adopted Role is a saved value, not a link proved by a name in today's catalog. | `projectRoster(page)` in LiveSpace/projection; selection dispatch uses a card's exact key. |
| `SceneProjection`: revision, world bounds, rooms. `RoomNode`: room key, workspace reference, bounds and ordered child IDs. `ActorNode`: scene object ID, exact card key, home/rest anchors and layout/navigation data. `PropNode`: ID, kind, room/scene owner, anchor, optional local affordance. | Scene contains rooms; each room contains zero or more actor and prop nodes. The same loaded current card has at most one scene actor in the focused view. Cabinet is a local archive affordance; stopped rows belong to its list, not the room's actors. Human anchor belongs to the scene/scope and is not a Workspace member; furniture and animation effects have no Agent reference. | `projectScene(roster, layoutMemory, viewport)` through [`projectHall`](../../web/agent-space/src/scene/model.ts#L30) and [seat memory](../../web/agent-space/src/scene/population.ts). Structural IDs are based on mounted scene/room identity and exact card or named prop slot, never coordinates or display names. The [debug projection](../../web/agent-space/src/scene/debug/objects.ts) can keep its existing compatibility IDs separately; neither ID is a route or mutation address. |
| `SceneInput` / `SceneFrame`: semantic projection + visible keys, selected anchor, camera, viewport, pause; sampled poses, world/screen positions and transient effects. | A frame depicts one input revision. One actor can present a canvas sprite and DOM target in the same frame. Filter/hover, zoom and animation change view state, not membership or authority. Layout memory belongs to the workspace session; frame/motion state expires on unmount. | Existing [runtime contracts](../../web/agent-space/src/scene/runtime/contracts.ts), [SceneSpace camera and return](../../web/agent-space/src/scene/SceneSpace.tsx), [HallScene frame fanout](../../web/agent-space/src/scene/HallScene.tsx#L39). Renderer, DOM positions and retained diagnostic facade consume that same presented frame; preserve the existing runtime clock and disposal. |

**Input → intent → state → projection.** The named `ActorAnchor` button (pointer or keyboard) translates an actor node into the exact card key; list/directory translate their rows to the same key. `SceneSpace` forwards that input to the controller with its local focus/return context. Revalidate against the active roster and scope; ignore a removed or prior-mount target, with focus returned to the directory control. Commit selection/open once, start bounded exact reads, render both the reader subject and corresponding actor/list highlight from that state. Pan/zoom and pointer hover stay on scene ports; cabinet and mailbox dispatch only their existing local disclosures. The same semantic facts can be explained in Contract Canvas as declaration relationships. [Space's current diagnostic facade](../../web/agent-space/src/scene/debug/README.md) still inspects mounted presentation values through its own boundary.

## Management · today's catalog, observed membership and saved adoption

This binds the workspace inspection portion of [MG-02.a](management.md#acceptance-and-flow-bindings) and exact detail of **MG-01.a**. Use the existing **办公室 / 岗位** tab: workspace picker + compact discovery status above two named regions, **当前岗位** and **已观察成员**. Selecting a member opens a compact read-only detail within the tab. On narrow use one internally scrolling list/detail surface with **Back to members**, preserving focus, loaded pages and catalog context. Keep directory preview, launch/lifecycle, labels, journals and the main Agent workspace's selection and draft with their current owners. This inspection does not initiate, target-prefill or authorize a command.

| Step / control | Binding and observable next state |
| --- | --- |
| **M1** Open workspace tab → choose discovered workspace or **Global** | `scope.workspaces()` → canonical selection and discovery sources/bounds. Run `workspace.roles()` and first `workspace.memberPage()` independently. If Roles returns a different canonical workspace for a selected key, do not merge it with the previous membership list; show the resolved key and allow explicit reselection when available. Catalog error and member error are local, with independent Retry. |
| **M2** Expand a current Role / continue **Loaded members** | Show current name, namespace/source and configured profile (null is launch default, not a concrete name). Member rows show exact current vs stopped kind and observed adopted Role or explicitly none. Two regions are siblings under Workspace. Role selection discloses definition facts only; no implicit name-based join, member filter or grouping by file equality. Even the same path is not a revision match. |
| **M3** Pick exact member → inspect → return | Resolve the row's handle and call `agent.snapshot()`. Display exact discriminator in local identity disclosure; membership workspace and cwd separately, reported status/tool, saved Role source and adopted profile. Use “no adopted Role” only when membership is adopted with null Role; legacy/unavailable remain distinct. If fresh data no longer confirms the selected workspace, show that in place without moving the user or implying current membership. Loading/empty/error/stale have separate states; a late old result is ignored. Back goes to the exact row or members heading. Workspace switch invalidates old requests and clears the inspection. |

Split responsibility at existing seams: [console](../../web/management/console.tsx#L16) supplies the selected scope to [`useOffices`](../../web/management/use-offices.ts#L27) and the [`OfficeWorkspace` / membership facts Blocks](../../web/management/offices.tsx). Scope this workspace inspection state to that tab; reuse its Role and membership presentations with typed projections. Preserve the separate [global Agent/label pagination, polling and journal](../../web/management/use-management.ts); the global rail is neither the source nor the result of the SDK workspace page. Directory route preview/send remain named HTTP ports with independent selection and recovery. Neither native classification predicates nor lifecycle/launch are supplied as object layer operations.

## Acceptance and handoff

Use one disposable fixture: configured listener + exact expected scope; two known workspaces; an off-workspace first row at limit 1; a selected workspace current Agent with cwd elsewhere and an exact stopped namesake; an adopted Role whose current definition/profile has changed; two exact history pages with distinct message IDs; and explicit Global distinct from legacy/unavailable. Use fixture responses to control coverage caps/errors and delayed responses if the native fixture cannot seed those states. Exercise the actual Web adapters via the built public package, retaining exact request assertions and UI outcomes. No real participant or installed service is needed.

| Criteria | Decisive observable result and existing runner seam |
| --- | --- |
| **S1–S3** | Sparse first page shows continuation in Office and List; next click makes one bounded request. Select via a named actor button; switch to List and back with the same Agent, channel, draft text/revision and history position. Contextual Back restores a usable focus target and camera zoom; reopen via the other presentation. Inspect at 1440×900 and 390×844, including keyboard directory/Back. Bind to [Space browser acceptance and camera cases](../../web/agent-space/tests/README.md). |
| **S4** | In a delayed/read-failure case switch exact targets while the old request is pending; no late history or draft crosses. Exact stopped namesake stays read-only and never has an avatar. Failed/stale exact read shows recovery and preserves its draft; no name fallback. Forward message continuation carries the same exact checkpoint and appends once. Selection, resize, draft editing and Back make zero writes. Use the same Space browser runner, with one focused projection/runtime check for a unique actor, shared frame and partial-seat preservation via [scene tests](../../web/agent-space/src/scene/AGENTS.md#verification-route). |
| **M1–M3** | Current definition/source/profile and saved adoption are clearly separate even with a matching path; cwd mismatch does not alter membership. Empty projected page offers continuation; exhaust it or inject an independent catalog error/cap and observe distinct states. Switch workspaces during a delayed read; only current selection's facts render. Inspect current/stopped identities, then return to the same row/page at desktop and narrow sizes; network trace is read-only for the selected path. Extend the [Management browser runner](../../web/management/tests/browser.mjs). |
| **Both / fence** | Wrong configured scope refuses before catalog or Agent reads. Same-URL generation reset leaves the old selection unusable until the user reconnects; neither canonical workspace position nor old exact key/draft is attached to the new generation. Confirm via fixture request trace and, once through a disposable native listener, actual generation and exact-address behavior. |

[Independent SDK verification](../../.controller/typescript-domain-sdk/tasks/integration.task.md#independent-outcome) already covers isolated native scope, empty projection with continuation, changed catalog vs adoption, exact lifecycle and original request recovery. This paper handoff reuses that evidence for SDK capability only. The receiving Web implementer owns branch binding, disposable browser replay, representative rendered density/continuity and evidence; host integration owns trusted initialization; native/SDK owns any new read capability such as workspace-filtered paging or a latest-window/backward message cursor. User acceptance, real Provider behavior and installed/live adoption remain separate.
