# Current product baseline

Management answers “what exists in this scope, what happened to the action I took, and what can I safely do now?” Space answers “where is the Agent I need, what did we exchange, and how do I return to this conversation?” Both use the same scoped native Management supply; they make different parts of it primary. The [browser evidence index](../../.controller/web-product-design/evidence/baseline/README.md) records which states were actually viewed, with a reproduction script. The following inventory describes current source, not adoption on any particular listener. Friction points are expert findings and hypotheses, with no interview or user-acceptance claim.

## Management: follow evidence from subject to operation

| Operator job | Current browser path and constraints | Authoritative source |
| --- | --- | --- |
| Find a runnable participant, a failed execution or its history | Header identifies the configured project. Agent rail has office, current/history, loaded-text search, label selectors and grouping. Narrow layout collapses the rail into a chooser. A “current” record can be idle, failed or inactive; only stopped history has a stop-event reference. Loaded list search/grouping and native label selection have different coverage: label predicates run **before** paging, for current rows only, with descriptor capability and revision checks for edits. A partial or filtered roster cannot prove absence. | [Console](../../web/management/console.tsx), [rail and actions](../../web/management/resources.tsx), [classification contract](../agent-classification.md), [view and page DTOs](../../src/management/contract.rs) |
| Diagnose and act on one exact Agent | The selected Agent toolbar shows effective status/tool and independent adoption facts; exact references and session are disclosed. Messages, Provider model records and Offices/Posts are tabs; start is a header dialog; stop confirmation and resume are local, gated by capabilities. AgentX messages are bounded to the exact execution interval. The model snapshot is an explicit operation, may include earlier work of a resumed Provider session, and can be unavailable. Neither is a terminal mirror. | [Current console](../../web/management/console.tsx), [actions](../../web/management/resources.tsx), [native management design](../agent-management/design.md#http-contract) |
| Understand a team or contact its default endpoint | Saved member/adopted Role facts, current effective Role catalog and directory routing are three sources. A member's cwd does not define their office; adopted global/roleless, legacy and unavailable are distinct. Known empty offices exist; catalog discovery is finite. A Role can inherit the launch default without a declared profile. Directory preview is GET only and resolves canonical directory → selected workspace → declaring default Role → endpoint state. Bound endpoint is not synonymous with send-ready. Explicit directory send re-resolves, can adopt/create a recipient, and returns the actual exact recipient and creation fact. | [Office/native contract](../agent-management/offices.md), [Management office view](../../web/management/offices.tsx), [workspace discovery](../proposals/workspace-discovery.md) |
| Recover an uncertain action | Header drawer shows this browser's original operation receipts, separate from selected Agent. Record chosen command and body before sending. Receipt status Accepted/Running/Succeeded/Failed/Unknown differs from transport error or absent lookup, and from Agent/task state. A lost reply or reload must first query the original request ID against its original endpoint/scope and generation. Only an eligible confirmed-missing request can be explicitly replayed with its **same** ID and command. Unknown forbids automatic or same-receipt replay. Native generation is a fence; the Management journal stores the original generation but no explicit endpoint or scope, an important gap if a separately hosted page changes its managementUrl. Stop result may be a request sent; successful send admission does not prove delivery or a reply. A local empty journal does not establish that no operations happened. | [Recovery controller](../../web/management/use-management.ts), [receipt view](../../web/management/operations.tsx), [native journal semantics](../agent-management/design.md#configuration-and-lifetime) |

An Agent target is selected scope and generation, canonical name and exact incarnation or stopped event (some stopped records can retain both fields); retain record kind, and compare the exact stopped event where supplied. A Provider session ID, display title, Role, workspace and cwd are different facts. Preserve original precision: IDs and cursors stay opaque strings, and numeric wire fields covered by the SDK's integer codec remain exact. Ordinary restarts can preserve receipts; generation changes fence the old dataset. The browser apps accept explicit `managementUrl` for an isolated selected listener; it does not own daemon selection, authority or identity.

| Resource or relationship | What exists and where the boundary is |
| --- | --- |
| Core set | Current/local executions and bounded stopped history, effective/stored status and context, request error, opaque paging, directory/cwd, title, Provider session and capability flags. Native owns status and action eligibility; a green/red badge alone does not. Pending Agent deliveries reflect native cursor, not human or model read acknowledgment. [DTOs](../../src/management/contract.rs), [read projection](../../src/management/store.rs). |
| Activity and relationships | AgentX communication records link sender/recipients, optional reply/thread/intent and attachments. Direct launch provenance supplies one upstream relation and paged downstream relations with exact availability and failed-start information; it does not infer Provider children or a global topology. Space exposes this under Agent facts, while the current Management console does not compose that relation reader. Project/cwd, role adoption, membership and launch lineage must remain separate. [Native relation contract](../../src/management/relations.rs), [Space facts](../../web/agent-space/src/conversation/Conversation.tsx), [provenance Delivery](../../.controller/agent-launch-relations/delivery.delivery.md). |
| Catalogs and file bindings | Descriptor offers profile/tool launch choices; effective Role definitions are read supply with separate adopted facts. Role/profile file maintenance, Skills inventory/use and filesystem configuration are not current management controls. Task/Delivery binding is a read projection with checked/last-success time, diagnostics and observed status; the external file is authoritative and the projection is periodically refreshed. It does not imply Task CRUD or equivalence to Workbench Work. [Bindings](../file-task-bindings.md#read-model-and-refresh), [public boundary](../api-panorama/README.md#7-全项目边界哪些能力还不能从当前-openapi-生成). |
| Available HTTP vs current screen | Generated Management exposes kill, stop participation, fork, relations, attachments, mailbox/activity and Inspector where capability/contract permits. The Management rail toolbar currently composes resume and stop (dispatches native kill); Space composes its own contextual action set. The existence of an SDK method does not make it an existing browser path. Workbench and Observation have their own listeners and contracts. Native daemon status/restart/reset, process/PTY/tmux access, live terminal I/O, relay administration, raw hooks, backend tickets, generic shell and raw SQLite are outside the product's current Management HTTP boundary. [SDK adoption](../../.controller/web-sdk-adoption/web.task.md), [actual browser dispatch](../../web/management/api/client.ts), [API inventory and boundaries](../api-panorama/README.md). |

**Management friction to test:** office discovery and Role browsing live under a selected-detail tab, although an operator can be investigating an empty office before choosing a person. A lost-reply task starts at a target and continues in a separate header drawer; a redesign must keep both original target and request readily traceable even after selection changes. The resource count says loaded, but the adjacent “运行中” filter selects every non-stopped row, so a failed or inactive current member could look like a process-health statement. Tell the user which set they are scanning and separate lifecycle, delivery and receipt results.

## Space: locate, converse, disclose, return

| Human task | Actual path and continuity | Boundary |
| --- | --- | --- |
| Find someone and open their conversation | Switch 场景 / 聊天 in one shared app. Choose all offices or exact office; use members, stopped history, posts and Skills tabs, or filter by query/status. The scene presents current membership spatially and has a directory surface; a click opens the exact conversation in the scene reader and changes camera focus. Chat exposes list + reader. History is a resource view, not a second entry for the current namesake. Post detail lists members who adopted that source and in live mode can offer a deliberate launch. Skills can be unavailable. | [App](../../web/agent-space/src/App.tsx), [posts](../../web/agent-space/src/OfficeResources.tsx), [Space source ownership](../../web/agent-space/AGENTS.md). |
| Read and compose with context | AgentX 消息, 模型记录 and 本页笔记 are different sources. Source/provenance, nested record disclosures and Agent facts are local disclosures. Provider read is deliberate and bounded; its records may predate the current incarnation. Exact drafts, local notes and pending context are page-owned. Draft options include intent, reply and thread where supplied. Native sends use exact, capability-gated operations; unknown outcome needs lookup. Local notes are not messages. Attachments can be registered and sent as durable references. | [Reader and composer](../../web/agent-space/src/conversation/Conversation.tsx), [live actions](../../web/agent-space/src/live/Actions.tsx), [context usage](../agent-management/web-context.md#query-and-compact-layout). |
| Resume a place after going elsewhere | URL models office, layout, resource tab/filter, exact selected record and channel, post, facts, scene directory/mailbox and mailbox cursor. Back/Forward restores meaningful navigation; typing filters replaces history, deliberate navigation pushes. Supply can arrive late; unavailable exact targets retain bounded feedback, never select by name. Close removes the URL reader target while retaining that exact local draft. Switching layout does not create a new conversation. Per-office camera, draft text, pending context, disclosures inside records, and already loaded model data do not become shareable route state. | [Route contract and verified cases](../agent-space/routes.md#lifecycle-and-history). |
| Read or handle incoming letters | Native exact activity drives scene flights; an animation or admitted send does not prove a reply. Human mailbox uses scoped native unhandled total and bounded pending/history pages. Reading a letter, marking it handled and Agent pending delivery are separate. Opening the mailbox or restoring its URL only reads; handling is explicit. | [Mailbox contract and limits](../../.controller/office-details/bigboss-cat.task.md), [route table](../agent-space/routes.md#design-and-responsibilities). |
| Embed with an exact target | Complete responsive app in browser, sidebar or iframe. Legacy layout hints remain compatible; the route carries exact reference, while parent hello/ready/context uses selection revision to reject away/back stale delivery. Adding text or file context requires exact validation and does not send. Layout and compact disclosures must remain reachable in short frames, including receipt and attachments. | [Bridge protocol](../agent-management/web-context.md#parent-wrapper-protocol), [independent route browser evidence](../agent-space/routes.md#verified-source-outcome). |

**Space friction to test:** the user finding an Agent in a rich canvas must distinguish the office directory, the chat list, and the selected reader. “聊天” opens a layout; it need not mean a message was sent or that the selected thread changed. Narrow users pay for any repeating navigation chrome above the reading/composing area. A deep link can faithfully restore the view while the draft is local and disappears on refresh; preserve clarity around what is retained. Keep the useful return target (same office/camera or list context), and test with duplicate names, stopped history and wrong generation so a return never changes the intended Agent.

## Which decisions have honest data?

| Decision | Justified display and source | Limit |
| --- | --- | --- |
| “Which loaded current Agents need attention?” | Compact current-state counts or bands from the Agent list snapshot, with exact scope/filter, paging and current-complete indicator if deliberately wired through; the current Management rail shows loaded count and presence of a next page. Link directly to affected rows; show request-error details when supplied. | Current mix only; no trend, heartbeat timeline, elapsed uptime or completeness under partial/filter coverage. “Failed” need not be a Provider failure. |
| “Is this office known, empty or unknown?” | Known-office source and explicit discovery coverage + current membership breakdown from native office catalog and roster. Directory preview can show state and exact recipient at time of read. | Finite discovery; distinguish unexamined/unavailable from empty, legacy and adopted global. No inferred team from cwd, no promise of later delivery from preview. |
| “Should I act again?” | Original receipt's status/result/errors and separate live exact target state. For troubleshooting include response `x-request-id` when available and original operation ID; these are distinct from native dispatch/request IDs. Logs are operator-local diagnostics with bounded retention. | Public Management is not a global or time-series receipt browser; don't chart local receipts as daemon throughput or infer action outcome from logs alone. [Diagnostics and retention](../architecture/runtime-diagnostics.md). |
| “Do I have pending work to read?” | Explicit Agent pending cursor/unread source or native human mailbox unhandled total, plus page/coverage status. Use message/activity timestamps for record chronology. | Never substitute page length, animation, admitted send or lack of a reply for unread count, delivery, SLA or task completion. |
| “What changed across time or deployments?” | No source in this redesign supports broad uptime, response latency, tokens/cost, per-Agent performance trends or fleet health. Bring time-series/retention/coverage requirements to a separate decision and contract if needed. | Optional Observation/Inspector collection has separate scope, time and settings; deferred. Do not elevate mock data or bounded latest logs into a historical dashboard. |

Prioritize comparable candidate evaluations: Management exact subject → capability → original receipt lookup after lost reply; office → preview with ambiguous/unavailable/empty outcomes; Space scene/list → same exact reader/draft → disclosure → return, then repeat with a stopped namesake and in a narrow frame. Use the same viewport, record type, disclosure state and coverage wherever possible. Remaining unknowns are user frequency and priority between these tasks, how often scopes change, desired draft persistence across reload, and desired local operational evidence. These require user validation and, where applicable, explicit new contracts.
