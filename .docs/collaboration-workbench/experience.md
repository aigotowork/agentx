# AgentX 资源工作区

## 当前细化入口

用户已认为修订后的资源工作区整体方向大体合适，当前在该方向上细化，不重新选择根布局。资源/控件清单、具体入口与返回、重要状态、组件合同、tokens、适配与新增组合图由[资源、操作与组件细化](interface-details.md)统一维护；本文件继续拥有 S1–S5 场景与整体布局依据。旧版同四项比较保留其历史绘图口径，但其中 #022 的“已保存却未分工”已被发现与原生 CreateWork 不一致，现按控制者决定修正为无原生编号的本页草稿：主图为 5 项已载入工作 + 1 个独立草稿，草稿不进入来源/资源计数。不是新增原生无角色工作能力。

## 设计依据与此次改变

用户否定了第一版的实际界面：解释文字占用过多空间，核心工作资源及关系没有在主屏展开。本次修订依据[原始反馈](../../.controller/collaboration-workbench/controller.md#user-feedback-and-design-revision)与[共享界面标准](../../.agent-guides/scenarios/interface-design.md)，重新推导信息架构。第一版保存在 `/tmp/agentx-workbench-v1-916r6l2m/preservation.json`；它的无碰撞截图属于历史观察，不代表用户接受了该布局。

唯一推荐方向改为“资源工作区”：上半屏是来源分组下的工作矩阵，任务、实现者、独立检查者、结果、检查和下一动作横向对应；下半屏是选中资源的局部操作。左侧提供来源、关联资源视图和真实参与者入口。当前问题仍是工作内容，但不再独占整个中心，也不另设重复解释实现/检查/接受的接力栏。

此处服务于[Delivery 的任务分派到接受结果](../../.controller/collaboration-workbench/delivery.md#用户结果)。`atlas-cli`、五项持久工作与一个本页草稿、四位 Agent、源路径、版本、时间与检查均为设计示例；图内仅保留一处小型示例标识。静态设计不表示这些目标能力已实现，真实语义与边界以[能力设计](capabilities.md)及其未来原生声明为准。

## 用户问题与资源模型

使用者是一位对仓库改动负责的人。他需要同时知道“这项来源下有哪些工作、由谁承担、结果和检查到哪一步、哪里需要我动作”，然后深入一项工作并返回。单一聊天、看板列或大幅关系图都不能自然满足这里的对齐比较和就地处理，因此使用有明确对象列的分组表格加局部详情。

| 可见结构 | 关系、身份与来源 | 操作范围 |
| --- | --- | --- |
| 工作区 `atlas-cli` | 启动时固定项目/数据作用域 | 当前范围的安全查询与有限协作；顶栏不提供任意项目/机器切换 |
| 交付 / 来源 `cli-1.4`、`install` | 按已有工作记录的原始引用路径前缀分组，标题就是路径段；显示真实路径 | 选择/折叠分组、过滤当前已载入工作；不是新的 Delivery 持久化实体，也不是仓库目录浏览器 |
| 任务 `#024` 等 | 稳定工作身份、标题与源引用；选中后连接目标、条件和问题 | 编辑、安排已有 Agent、显式派发、答复、结果/检查与接受 |
| 实现者 / 独立检查者 | 每行连接精确角色绑定，名字是可读入口，身份局部可查 | 查看绑定/当前可用性、任务内补充或更换角色；不提供全局进程控制 |
| 结果 `r1/r2` | 版本在所属任务内有稳定身份，连接不可变来源与产物引用 | 点版本打开局部产物；版本名相同不代表跨任务同一个结果 |
| 检查 `C1/C2` | 指向确切任务结果、条件依据和独立检查者 | 查看逐项报告、要求修改或有理由地重新检查 |
| 待办 / 接受 | Q1、待派发、待检查、已接受版本等明确业务事实 | 就近答复、派发、请求检查、要求修改或显式接受；与 Agent 运行状态分开 |

来源缺失的工作归入“未关联来源”；外部引用用其可识别来源分组，无法可靠分组则保留原引用，不猜测它属于某个交付。路径是已保存的参考信息，界面不声称读过或同步了文件。筛选、资源透视、计数只覆盖“已载入 5 项”；未来分批查询时必须保留已载入范围与继续读取入口，不能伪装成全库聚合。

任务行的结果、检查、角色和动作就是关系表达，不需要再写“先实现、再检查、最后验收”的常驻说明。左侧 Agent 的空闲/工作中是运行事实；表内等你/检查中/已接受是工作事实。缺项用 `—` 或可操作的加号，未知状态用“未知”，不是自动通过。

## 主屏结构与布局责任

桌面保持和第一版相同的 `1440 × 900`。顶栏 48 px，左资源导航 216 px，主工作区 1224 px。工作工具栏与分组矩阵占 y=65–531，选中资源操作占 y=548–870。五个持久工作行高 48 px，另有独立本页草稿带；主要正文 13–14 px、来源/辅助元信息 12 px，主标题 21 px，桌面上下文控件 32 px。密度来自对齐、共用表头和移除重复叙述，未用微小字体或十几像素的命中区域充数。

| 区域 | 同时可读的事实 | 操作及局部展开 |
| --- | --- | --- |
| 左导航 | 两个真实来源引用分组、已载入任务数、四个 Agent 与运行状态 | 来源过滤、资源透视、Agent 身份/关联工作、诊断；不打开新产品流程 |
| 工作矩阵 | 五项工作标题、每项两个角色、现有结果、检查与当前待办/接受；本页草稿独立显示 | 点任务选择；点角色/结果/检查就地展开；关键动作短标签；来源/补充/更多采用一致图标 |
| 下方详情头 | 选中任务身份与四个局部视图 | 任务 / 产物 / 检查 / 消息、编辑、复制链接、收起；切换保持同一任务和草稿 |
| 任务详情 | 目标、b1 三项条件、来源、Lin 的 Q1 与建议答案 | 答复、自定义答复、普通补充；主动作仅“回复 Lin” |
| 分工编辑器 | 标题、目标、来源、条件与两个角色选择器 | 保存、关闭、明确派发；未保存时尾部显示保存，图 02 停在已保存状态 |
| 结果详情 | r2 来源、产物引用、C2 的目标/检查者/逐项发现/报告 | 引用详情、报告、有理由重查、要求修改、接受确认 |

初始数据较多时矩阵在自己的区域滚动，表头与来源组保持可辨认；下方详情只在内容超出时局部滚动。不会制造左队列/中聊天/右解释三块互相抢空间的页面。收起详情后矩阵可扩展至底部，筛选/选中不丢失；此操作改变可见容量，不改变工作状态。

### 紧凑图标与信息揭示

| 位置/标记 | 可访问名称与含义 | 到达步骤与返回 |
| --- | --- | --- |
| 行内来源文件图标 | `查看 #024 的原始来源与执行依据` | 1 次打开当前详情的来源小面板，Esc 返回原图标 |
| 行内对话图标 | `给 #024 的参与者发送补充` | 1 次展开目标角色与输入；没有角色时不可发送，提示先安排，不伪造接收者 |
| 行内更多 `···` | 当前任务低频操作 | 1 次展开复制链接/编辑/历史记录；再选一项为 2 步 |
| 实现者/检查者 | 角色列已给语义；名字可点 | 1 次看精确身份/分工/关联工作；改变角色在编辑器内确认 |
| `r1/r2` | 此任务结果版本 | 1 次切到同一任务产物面板，不先打开另一个任务路由 |
| `检查中` / `通过 · C1` / `失败 · C2` | 当前检查状态或具名报告 | 1 次切到对应版本检查；不能把已接受任务的状态当报告细节 |
| 信息图标 `i` | 当前来源/能力/保存与派发/报告归属等解释 | 焦点、点击或触摸均能打开短说明；不常驻占一行 |
| 详情编辑/链接/关闭 | 编辑目标条件分工 / 复制任务链接 / 收起详情 | 1 次；关闭后焦点回选中行，不清空草稿 |

SVG 为静态状态，图标分组保留中文 `aria-label` 和 `<title>` 作为设计用途标签；真实实现必须用语义 button/link、可见焦点、可键盘打开的 Tooltip/Popover，不能把浏览器 hover title 当成可访问性实现。关键状态、版本、作者、目标、问题、检查结论不移入 Tooltip。主要语义不明确的操作保留短文本，如“答复”“请求检查”“派发”。

图中不再常驻“检查后由你决定”“等待结果后发起检查”“运行空闲不代表完成”等段落。前两者变成列关系、状态与对应动作；后一条技术区分在运行状态或投递回执的信息说明中按需出现。原稿底部多处示例免责声明合为一个小“设计示例”标签。错误与实际操作后果仍在受影响控件旁出现，不为了密度隐藏。

## 工作效果、状态与恢复

原生意义沿用[能力契约方向](capabilities.md#operations-effects-and-recovery)；布局修订没有新增计划、自动调度、文件读取、通用命令或身份权限域。

| 操作 / 事实 | 正确反馈与寿命 | 失败或未知时 |
| --- | --- | --- |
| 新建并保存 | 首次原子保存目标、条件、来源及两个有效角色；成功才获原生身份并显示“已保存/待派发” | 无效字段就近提示；未保存的是本页草稿，不占工作计数；来源只存引用 |
| 编辑已有依据 / 更换已有角色 | 分别保存 UpdateBrief 或单角色 BindParticipant；前者新 b、后者新 assignment，随后显式派发 | 不承诺既有依据与换人的跨命令原子保存，局部成功/失败分别留存；详见[具体编辑合同](interface-details.md#s1新建编辑分工保存与派发) |
| 显式派发 | 留存工作派发与原生消息接收，投递回执可局部查看 | 已保存工作不丢；未知结果按原命令身份查询，不自动重发，不写成已开始 |
| 作者提 Q1 / 用户答复 | 结构化问题稳定关联作者/分工；答复和原生消息接收原子留存；显示“已答复，等待 Lin 更新” | 接收失败则整体不存并保留草稿；后续外部投递失败/未知保留已存答复及该回执状态 |
| 普通补充 | 只向该工作绑定角色发有限消息 | 不自动回答 Q1，不从消息文本推断完成或进展 |
| 发布 r2 / 请求检查 | r2 不可变来源与产物引用；显式检查请求固定 r2/b1/检查者 | 文件引用不是在线预览；未检查、资料不足、失败都有明确局部状态 |
| Moss 上报检查 | 逐条件结论、依据引用、观察到的来源与 r2 对齐；通过有署名归属 | 上报不是平台自己跑测试；源不一致、角色不独立不能通过；重查同版本保留理由和新请求 |
| 接受 / 要求修改 | 接受写明 r2/C2/b1；服务比对当前依据与未答问题；修改理由关联具体结果 | 新版本/新条件使旧确认失效，提示查看更新；超时查询原命令，不自动再次提交 |
| 切任务/视图/来源 | 保留选中对象、分组、滚动、草稿、固定证据版本与焦点返回点 | 源不可读/未检查新鲜度只是引用状态；不擅自更换选中对象或重写历史 |
| 只读/服务不可用 | 显示短原因，保留已知资源、历史与时间，禁用写入 | 不引入登录/令牌/浏览器解锁；直接 LAN 的范围由启动模式固定 |
| 空/加载/读取失败 | 空资源区给新建入口；搜索空集保留条件；刷新只替换未知区 | 读取失败就近重试，保留最近资源；读重试不触发派发，不以空数组伪装失败 |

同一个任务可以有多个未答问题；默认打开当前选中的 Q，详情头显示未答数量与切换入口，不能让后来的问题覆盖已有问题。角色重绑后保留提问者历史，将实际答复发给当前角色并明确接收者。结果、检查和接受均保留旧版本历史。所有效果由原生持久事实支撑，前端不靠表格选择或 Agent 空闲推进工作。

接受前的正常动作区包含“要求修改”和“接受 r2”；图 03 展示点击接受后的确认条，确认才提交，取消回到前一动作区。必要后果“记录接受，不执行合并或发布”只在此时出现。通过检查的报告者始终显示，接受记录使用“操作者”含义，不宣称 LAN 上存在已认证的个人批准。

## 窄屏与键盘连续性

`390 × 844` 保留同一资源结构：来源分组 + 四条当前可见工作，行内压缩为任务标题、实现者→检查者、结果/待办摘要；`install` 保留折叠入口与真实记录数。箭头表示这项工作中的实现/检查角色关系，不表示消息已经送达或检查已经执行。图中用完整名字而非不可解释的字母缩写。具体产物/检查报告通过同一行详情切换，不把桌面每列变成一张大卡片。

下方保留 `#024` 与任务/产物/检查/消息标签，当前 Q1、两个建议答复、自定义答复与提交同屏；目标、条件、来源和角色详情经底部文件/参与者按钮一次打开。来源菜单、行内更多和主要输入命中高度至少 44 px；交互变长时局部面板滚动或拉高，选中任务/返回点不丢失。回复区出现时仍保留上方几项资源，不以全屏教程取代工作上下文。

键盘按“来源/资源导航 → 工作工具栏 → 行选择与该行操作 → 选中详情 → 当前表单”组织；表格使用原生 table 与行内按钮，避免无必要的复杂 grid 键盘协议。详情 tabs/单选组选项支持方向键；抽屉、Tooltip/Popover 可经焦点或点击打开，Esc 关闭并返回触发对象；确认条不会让焦点跳离当前任务。窄屏菜单是局部模态层时需约束焦点并恢复位置。动态只播报新问题、操作结果或冲突，不逐条朗读 Agent 工具日志。以上是实施合同，静态图不声称已经验证键盘/触摸行为。

## 历史修订：同视口、同数据的前后比较

## 决策、边界与交接

本次不是删除副标题式微调：取消旧右接力栏与稀疏左任务队列，重建为跨工作关系矩阵和选中资源面板。拒绝用巨型关系图、装饰数字卡片或任意堆数据代替同类对象的可比性；不扩展成通用项目管理、机器调度或文件浏览平台。所有视图透视是当前已载入工作和参与者的本地投影；若未来发现真实跨库查询需求，先交能力 owner 明确合同，不能从图标推导新服务。

本轮没有新的未决原生语义要求，无需唤醒已释放的能力设计者。实施仍需[能力设计](capabilities.md)的不可变结果/检查/接受、命令恢复、精确角色/当前条件与有限 LAN 作用域。真实独立验收必须提供实际不可变产物与报告；SVG 不提供文件预览、测试运行或批准身份。

用户已广泛选择“上方资源关系、下方局部操作”的组合；当前任务是依照[细化入口](interface-details.md)检查资源、操作、组件与关键状态，不再要求对相同根布局重复选择。控制者以新增组合图及 S1–S5 讨论具体行为，若出现实质反馈继续原始 Task，不增加另一套候选或审批阶段。

[draw.py](visuals/draw.py) 是可复用作者源，四张 SVG 保留原生文字/形状/语义分组、内置样式与图标用途标签，无外部图片/字体/网络依赖。直接在矢量编辑器修改 SVG 时应同步作者源或明确停止重新生成。实施时把颜色、尺寸和间距收敛为语义 CSS tokens，组件按资源导航、工作矩阵、所选任务、问题/分工/证据和操作反馈划分；不要把 SVG 坐标复制为前端架构。
