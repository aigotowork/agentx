# Production storage boundary

This model answers where the final ownership guard may permit storage operations. The [production inventory](db-access.md) records current source dependencies and scanner provenance. [Independent acceptance](../architecture/acceptance.md) retains historical migration evidence and owns fixed candidate scans, process descriptors and actual cutover results. The paths below describe inspected source and accepted placement, with unresolved call edges identified separately. They do not certify a final guard pass or equality with a preserved candidate. Integration's [strict fixed-s7 scan](../../.controller/domain-daemon/tasks/integration.md#kind-scoped-storage-guard-checkpoint) predates later source releases; its unclassified findings are disposition candidates, not a count of executed client defects.

## Permission dimensions

| Operation | Permitted production owner | Restriction |
| --- | --- | --- |
| Construct the live managed database | Exact daemon application initializer in [`main.rs`](../../src/main.rs), using `AgentxDb::open_at(&database_path)` after `daemon::entry_scope`, inside `daemon::serve` | This is one composition site, not permission for every function or branch in `main.rs`. Client acquisition cannot open storage. |
| Open a managed read-only connection | Exact daemon-owned [`read_application::Reader`](../../src/service/read_application.rs) using `AgentxDb::open_reader` on the writer's already selected path | One bounded Management/FileBindings lane. No migration, writer fallback, caller-selected file or client-side DB construction. |
| Implement managed construction, migration and persistence | [`db`](../../src/db/AGENTS.md) | Persistence's constructor implementations do not authorize new callers. Preserve the daemon-only composition root. |
| Borrow managed storage or use `rusqlite` | Application adapters and named domain helpers in the tables below | A borrowed connection never grants managed or raw SQLite constructor permission. Actual production callers must remain within daemon composition. |
| Read managed archives | `maintenance_store::open_archive` and `events::history_store::{capture,query}` | Permit only these three `SQLITE_OPEN_READ_ONLY` constructor sites. Events capture validates scoped `archive/session-*` directory entries; continuation uses only its retained source manifest and verifies file identity/generation. Native callers supply selectors/cursors, never database paths. |
| Read external Provider storage | Existing OpenCode/Kilo/Hermes transcript/session readers | Keep the [per-site Provider decisions](db-access.md#boundary-decisions). A read-only AgentX KV access is still managed storage. |
| Perform client/host work | CLI, TUI, hooks, plugin RPC, PTY/stdio hosts, relay worker and service client | Use native capabilities. No managed connection, constructor, SQL fallback or database-shaped client facade. File-only configuration, Provider files and host process/terminal I/O retain their own owners. |

[`service::application::SqliteApplication`](../../src/service/application.rs) receives the already constructed database. Its `handle` supplies borrowed storage to Participants, Messages, Hosts, Events, Queries, Maintenance, Relay and Collaboration. [`daemon`](../../src/daemon/AGENTS.md) transports native requests and observes caller authority; being under `src/daemon/` is not a storage exemption.

## Native Inspector supply

`service::application::SqliteApplication` dispatches `Request::Inspection` exclusively to `inspection::store::handle` on its daemon-owned connection. The store borrows that connection for generation/revision-fenced sampled ledger retention, pinned deterministic report jobs and atomic episode-continuation/message/audit transitions. `inspection::recovery::eligible` is the exact store-only borrowed helper for current episode, stored status and process evidence; its module does not open storage or signal a process. `runtime::inspection` obtains typed native projections through Client and reads Provider transcript files on the host; it never opens managed SQLite. Public HTTP excludes internal Collect and RunAnalysis. [Live model](../inspector/live-model.md) owns domain and host boundaries; the integration Delivery owns executable evidence.

### Released system cleanup boundary

[`agents::service`](../../src/agents/service.rs) publishes `SystemCleanup`, `CleanupOutcome`, `cleanup_system` and `tracked_process_state`; [`cleanup_store`](../../src/agents/cleanup_store.rs) owns internal Listing/DeadProcesses/LaunchPlaceholders and exact Resume admission. It calls `hook_store::cleanup_stop -> retire_tree` with current row/PID/stored-incarnation checks and defers unsafe cleanup when an independent tracked child survives. `stop_session` still requires its real self actor and `stop_killed` still requires exact kill authority; neither is fabricated for system work. The [state model](state-ownership.md#transaction-boundaries) retains atomicity, lost-reply and successor fences.

| Actual native carrier | Consumer and recovery boundary |
