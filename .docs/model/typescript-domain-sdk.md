# AgentX TypeScript domain objects

An application selects a Management listener, finds or restores an exact Agent address, reads AgentX message history or a Provider Transcript, follows direct creation provenance, and deliberately dispatches a command it can recover by its original ID. This package consumes the [native Service → OpenAPI → generated TypeScript chain](../api-panorama/service-contract-design.md). It adds typed object handles and correspondence checks; the [Management Service](../../src/management/AGENTS.md) owns identity, history, policy, and effects. The [earlier audit](typescript-domain-sdk-review.md) is the pre-extension baseline; [public contracts](../../packages/agentx-client/src/domain/contracts.ts) own exact names and [the package Task](../../.controller/typescript-domain-sdk/tasks/contract-completeness.task.md) owns verification limits.

| Object | Identity and usable observations |
| --- | --- |
| Selected scope | `selectAgentXScope({ baseUrl, expectedScope })` pins listener, trusted native scope and observed database generation. `verify()` explicitly reads a fresh descriptor and checks scope and generation. A failed verification leaves the original selection, descriptor and addresses untouched. A caller chooses whether to reselect. |
| Workspace | A canonical saved host path or literal `global` (represented as null in the native adopted fact). The bounded discovery catalog has explicit coverage; absence proves no definitive membership claim. An explicit Workspace handle does not register or establish a path. Effective role resolution may return a different canonical Workspace; the original handle stays pinned. Working directory and directory route are independent. |
| `RoleDefinition` and `AdoptedRole` | A current catalog definition has origin, canonical source and optional default profile. Adoption is an exact Agent's historical launch fact and includes the concrete profile selected then. Current definitions can change without changing adoption. No revision or digest is exposed and there is no equality inference by name or source path. Workspace launch pins the workspace selector and native resolves the requested role name at admission/execution. |
| Agent and snapshot | An address is scope + name + exactly one current incarnation or stopped event. A snapshot binds fresh facts and `adopted`, `legacy`, or `unavailable` membership to that address. A current row can be offline and observed capabilities can expire. Both exact variants read and can be used where native permits resume/fork; send, kill, stop participation and label writes require current. Native checks actual admission. |
| AgentX messages | Read bounded event history through an exact Agent checkpoint. Event IDs belong to the database generation. Sender and recipient display names do not carry sufficient identity for exact navigation. Message admission or observed event history does not establish Provider delivery or a reply. |
| Provider Transcript | `prepareTranscript` captures a bounded-read request on either exact variant; `requestTranscript` submits once per explicit call using the operation journal. On success the original target must match the retained reference. `available: false` carries an empty exchange list and reason; `available: true` can be empty or have a qualification, including native truncation. Native offers no Transcript continuation. Exchange positions are observations, not cursors. |
| Direct creation provenance | `launchRelations` reads one page of direct relationships. Origin is Agent, external, or unknown. The upstream and downstream rows retain creation name/incarnation independently of `launchFailure` and the optional navigable snapshot. Unavailable rows provide no address; available historical rows use the native stopped event selected through the stored creation, which the SDK cannot independently correlate to its incarnation. An available current row must match the creation name and incarnation. The cursor belongs to this exact subject, generation and resource. |
| Labels and lifecycle | Label revision is an opaque native CAS token. Patching preserves set/remove, omission and the supplied precondition without merging or rebasing. Kill reports the process stop outcome; stopping participation reports the separate native participation outcome. Resume and fork never change or rebind their source handle. A succeeded launch, resume or fork can carry diagnostics and partial failures. `result.agentAddresses` projects the exact incarnations durably recorded by native, in the same order as `result.agents`. The SDK checks agreement and never looks up names to fill missing addresses. Old receipts keep their diagnostics and report `agentAddresses: null`. A retained address can become stale even when the receipt is valid. |

## Commands and receipts

A prepared command is an inert, detached, retainable value with its kind, original scope and UUID, and exact target and inputs when applicable. Preparation performs no network I/O. Keep the value before dispatch if recovery must survive loss of the response or browser reload. `scope.operation(prepared).observe()` and `.wait()` only address the recorded journal entry, independent of whether the target still exists. Address-only `scope.operation(prepared.operation)` still returns the raw original receipt, and existing `prepareMessage` / `send` are unchanged. A retained `PreparedMessage` can also be passed directly for typed sent recovery. An older application journal with native fields can reconstruct the prepared value from its original listener, scope, generation, ID, target and body; reconstructing it never submits the command.

| Evidence | Meaning and continuation |
| --- | --- |
| Local validation or structured Management refusal | That call did not get a usable admission. Inspect the error code; a stale address never triggers a new generation, target or request ID. A stale read cannot retroactively establish the effect of a prior submission. |
| `Accepted` or `Running` | A native journal observation with no terminal result. Continue observing the original request if needed. |
| `Succeeded` | The typed receipt contains the compatible result for that command. A Transcript can remain unavailable; a successful send means acceptance; a launch can report failed starts. The raw native `.receipt` is kept for diagnostics and existing journals. |
| `Failed` or `Unknown` | A distinct native status with no success result. Native `Unknown` may be reconciled later; `.wait()` returns that observation so the caller can decide when to check again. |
| Lost response, wrong identity, malformed or incompatible receipt | The original command remains the recovery address. Observe its receipt without replay. `OutcomeUnknown` or `MutationOutcomeUnknown` retains write input when response knowledge is lost. `ProtocolError` and `ReceiptError` preserve malformed wire or incompatible journal evidence. |
| `ObservationStopped` | Signal/deadline ended local waiting only. It carries the original identity and last native receipt when present. |

## Coverage and independent resources

`workspace.memberPage` and `agent.messageHistory` check their own capability on the pinned descriptor. A missing capability or an explicit unsupported refusal for that operation rejects with `UnsupportedCapability` and identifies the affected method. Other resources remain callable. `scope.agents` is the scope-wide inventory, including old and unavailable membership observations. `workspace.memberPage` uses [native membership filtering](../api-panorama/service-contract-design.md#workspace-membership-and-launch-identity) before applying the limit. It returns exact adopted members, current names ascending then stopped events descending, with `currentComplete` scoped to the selection. Repeat `currentOnly` (default false) on subsequent calls and use the cursor bound to the scope, workspace and selector. No multi-page read promises a frozen snapshot.

Attachments belong to the scope: upload registers bytes and returns metadata and `AttachmentAddress`. Download is by that exact scoped address; message composition deliberately uses its retained ID. Upload does not send, and a lost upload response does not provide a journal ID. The human inbox is a separate resource: list uses a descending, scope/filter bound cursor and exposes the total unhandled count; handle marks explicit IDs and returns a fresh unfiltered head. Viewing or navigating an exact recorded sender does not mark an item. Office activity seeds a watermark and subsequently observes bounded accepted addressing; its checkpoint does not track delivery or handling. Directory inspection can canonicalize the supplied path without creating an Agent; submitting a text message explicitly re-resolves the route. A successful receipt carries the actually selected exact recipient, which may differ from the preview.

Scope handles are immutable browser-safe consumers. Browser journals, UI projections and policy for caller polling/caching live with the caller; native operation state lives in the journal. Independent Inspector, Workbench and Observation services keep their existing APIs. Use the [public package examples](../../packages/agentx-client/README.md#scoped-domain-objects) for the exact calls and [prior Delivery](../../.controller/typescript-domain-sdk/implementation.delivery.md#accepted-first-slice-outcome) for historical first-slice native evidence. The [current Task](../../.controller/typescript-domain-sdk/tasks/contract-completeness.task.md) records evidence for the extension separately from installed or live adoption.
