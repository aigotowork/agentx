# AgentX 网页上下文侧栏

侧栏直接打开**同一个完整 AgentX Space**：办公室、场景／列表切换、成员导航、会话和附件都在 Space 内操作。外层只提供服务设置与网页选区、正文、截图采集。内容加入当前成员的待发送草稿，由你检查后在 Space 内发送。

默认服务 `http://192.168.2.178:38023`；右上角“连接设置”可修改。服务需要提供支持当前选择桥的新版 `/space/`，旧版仅有显式目标 `addContext` 的服务会显示“不支持当前成员上下文桥”，不会猜测目标或自动转投同名成员。

## Chrome / Edge 安装

1. 下载 `agentx-browser-context-1.2.1.zip`，完整解压并保留目录。ZIP 不是可直接安装的 CRX，无需签名或商店发布。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`；开启“开发者模式”，点击“加载已解压的扩展程序”，选择**包含 manifest.json 的目录**。
3. 点击工具栏的扩展程序按钮，打开 AgentX 上下文侧栏，可固定图标。建议快捷键 `Alt+Shift+A`；浏览器可能没有注册该组合，请到 `chrome://extensions/shortcuts` 或 `edge://extensions/shortcuts` 自行设置可用组合。真实宿主已观察到默认快捷键为空、手动设置后的动作可以打开真正侧栏；不要把快捷键失效当成服务故障。
4. 展开“连接设置”，输入服务 IP 和端口并点击“连接”，连接只配置 iframe 地址，不再请求服务主机权限；进入 Space 后使用它自己的办公室／成员导航选择当前成员。

更新时使用新版解压目录加载／重新加载扩展。会话草稿不跨关闭或重载持久化，先完成已有草稿再更新。Chrome 最低声明版本 116；Edge 需要支持 Chromium sidePanel API。两者共用同一 MV3 包，实际执行过的浏览器版本与当前验收状态以交付证据为准，不把可安装说明当成两种浏览器的实机验收。

## 添加网页内容

打开普通 HTTP(S) 网页，点击扩展图标授权当前标签页；在完整 Space 内选择可接收消息的当前成员，再点击外层采集按钮。

| 操作 | 加入当前成员草稿的内容 |
| --- | --- |
| 选区 | 当前网页主文档选中文字、标题、来源 URL |
| 正文 | 主文档可见正文，最多 24000 字符、标题和来源 URL |
| 截图 | 当前标签页可见区域 PNG、标题、来源 URL；不滚动、不截整页，最大 10 MiB |
| 图片／文件 | 使用 Space 原有编辑器的附件入口；不再重复提供外层附件选择器 |

采集前绑定 Space 当前精确成员和选择版本。期间如果成员、办公室、频道、会话或服务发生变化，Space 在接收与提交前拒绝旧采集，即使切走又切回也不会静默重定向。场景／列表表现切换本身不替换成员草稿。添加成功会显示原目标名称，不会自动发送或创建 Agent。

被拒绝或结果不确定时，会保留最近一次采集副本，可展开复制文字或保存截图，直至你丢弃、关闭侧栏或后续采集成功；不会因选择变化自动重新绑定。确认原草稿后，若需要向新成员添加，明确重新采集。

## 故障与恢复

- 普通采集操作和同一服务的再次连接保留 iframe、成员选择、摄像机与草稿。更换服务或明确重新打开未就绪文档可能丢失原未发送草稿；先处理草稿。
- 浏览器内部页、商店、PDF 等页面可能不允许读取。换普通网页或在 Space 内添加本地文件。跨站导航后再点击扩展图标重新授权；正文和选区不读取跨域子框架、封闭 shadow DOM 或画布。
- Space 内原生接口报 `HTTP503 / Unavailable / daemon is busy` 是服务暂时繁忙，**不是缺少浏览器权限**。查看 Space 显示的实际接口和错误，稍后使用其重试。扩展不重复轮询 Agent、不启动或重启服务，移除重复查询不代表原生拥塞已解决。
- “未响应上下文桥”：检查配置地址和服务可用性，再在连接设置重新连接。该提示不假定 HTTP 状态或权限原因。当前选择查询超时／不可用时，不会开始截图或向未知目标添加。
- “结果尚未确认”：先看 Space 草稿；可点击“重试原请求”，在同一文档内复用原 ID 查询或重试，避免重复添加。原请求已经明确被拒绝时，不会自动重试。重载文档后子页面去重缓存可能丢失，原请求不再允许直接重试，必须核对草稿。
- 截图超过 10 MiB 时缩小浏览器窗口重试。Space 仍检查每条消息的附件数、大小和草稿文本限制。远程 Agent 是否能访问上传文件的宿主路径由 AgentX 服务与运行环境决定。

## 权限与数据

`sidePanel` 打开侧栏，`activeTab` 在用户调用扩展后临时授权当前页，`scripting` 按需采集主文档文字，`storage` 仅保存服务地址；不声明服务主机权限。完整 Space 通过 iframe 加载并由自身读取服务，网页采集仅使用用户手势授予的 `activeTab`。无远程扩展脚本、分析上报、后台页面采集、自动发送、用户资料或私钥打包。截图在侧栏中解码为 File，直接通过 iframe structured clone 交给 Space，不经过 Chrome runtime 的 JSON 序列化通道。

## 从源码复现

在 AgentX 仓库根运行：

```sh
python3 extensions/browser-context/package.py
```

仅依赖 Python 标准库，无 npm 或网络。输出版本化 ZIP、相同文件的 unpacked 目录和 SHA-256 清单到 `.artifacts/context-clients/`。ZIP 根目录包含 manifest。模块内 [design.md](design.md) 说明宿主职责与官方 API 依据，[AGENTS.md](AGENTS.md) 提供源码维护入口；仓库交付状态见 `.controller/context-clients/extension.md`，独立实际宿主证据由 `tests/context_clients/` 管理。
