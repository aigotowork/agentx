# Namespace control and Workspace catalogue

Start with the [v2 cleanup and current native formats](../../../.controller/cloud-namespace/cleanup.md), the [Namespace model](../../../.controller/cloud-namespace/task.md) and the [deployment storage decision](../../../.controller/cloud-namespace/deployment-workspaces.md). [Types](types.rs) are shared by the native uplink and both OpenAPI projections. [HTTP adapters](http.rs) compose into the existing Admin and Namespace bearer guards. [Store transitions](store.rs) use the existing communication database and transaction fence; [control tables](schema.sql) are provisioned with the fresh Namespace before it is published. [Workspace reads](workspaces.rs) page lease catalogues and invalidate the roster on expiry. Launch, exact process ownership, and local recovery live with the [uplink](../uplink.rs) and client.

Run `cargo test cloud::` for focused native tests. Export the two contracts with `agentx cloud-openapi admin` and `agentx cloud-openapi namespace`. The integration task owns SDK generation and isolated deployment acceptance.
