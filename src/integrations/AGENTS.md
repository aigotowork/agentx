# Provider adapters

Read root [AGENTS.md](../../AGENTS.md), the [source map](../README.md), [runtime-host model](../../.docs/architecture/runtime-hosts.md) and the current [runtime Task](../../.controller/domain-daemon/tasks/runtime.md). For native Codex internals also follow [Codex entry](codex/AGENTS.md); its earlier Delivery assignments are historical, not this team's runtime bindings.

`registry`/`tool` own the supported Provider catalogue. `launch_args`, hook installation and embedded plugins preserve each Provider's native contract. `hooks` owns payload normalization/Provider decisions/output formatting; AgentX domain lifecycle and mailbox transactions belong behind daemon capabilities. Provider-native read-only stores are distinct from managed AgentX SQLite.

Preserve explicit caller cwd/effective environment and separate AgentX participant, native Provider session and Paseo agent identities. Native protocol frames remain opaque outside the owning adapter. Never use daemon-global environment as caller identity or open the managed database after IPC failure. Stdio stdout belongs to protocol data; diagnostics use stderr.

The shared Codex bridge receives generic attachment/inbox ports and runtime `HostService`; it owns native I/O and exact input observations. Closing one bridge must preserve sibling connections and backend lifetime. Hook output preparation and post-flush receipts remain separate effects. Source evidence must distinguish fixtures, executed native tests and unavailable or unverified Providers/platforms.

Ordinary Qoder, Cursor, Kimi and Gemini/Antigravity dispatchers consume `hooks/client.rs::HookClient`. It prepares typed bootstrap and exact mailbox receipts, flushes Provider JSON in the originating process, then confirms durable effects. Observation-only Provider events must never prepare or confirm mailbox output. `hooks/output.rs` consumes domain-frozen text and distinguishes hook confirmation with delivery status from plugin/native receipt confirmation. Retained StopSession effects include exact process incarnation; signals and survivor sidecars remain host effects after commit.

Hermes gateway `hooks/hermes/registry_client.rs` consumes native `agents/hermes_service.rs` through the same scoped Client generation. Registry/token/incarnation changes belong to the daemon handler; profile canonicalization, Hermes CLI grants, plugin file refresh and bootstrap rendering remain in the originating host. Remove/ForgetHome execute the canonical returned child-first stop effects after commit. The old borrowed bridge/version helpers are test-only; production stored registry helpers live in agents, with no Provider effects in handlers.

Ordinary/native Codex hook entry delegates to `hooks/codex/client.rs`. Shared roots qualify the explicit home/execution/payload session through RemoteAttachments and supply the full current activation target; an early unbound hook never falls back to the process. Ordinary internal subagent/memory guards run before binding/capture. Position/tool activity use existing native participant operations. Shared bootstrap and ordinary mailbox output confirm exact receipts only after flush; shared hooks never claim native-input mail. Codex Stop is a turn boundary, not SessionEnd.

Copilot hook and extension entries delegate to `hooks/copilot/client.rs` and native `agents/copilot_service.rs`. The extension echoes its exact offered token on SDK/queue reports; enqueue acceptance never acknowledges mail. Native extension/hook ownership excludes competing output, and managed Issuing uncertainty cannot expire into another issuance. Only the actual same-session frozen prompt confirms delivery. Endpoint admission is process/session/attachment fenced; payload parsing, SDK calls, bootstrap rendering, hook stdout and post-flush confirmation stay host-owned. The old durable helper graph is test-only.

Ordinary Claude hook entry delegates to `hooks/claude/client.rs`, `poll.rs` and `render.rs`, consuming the authoritative `agents/claude_service.rs` actor, stop-claim and output contracts. The originating host reads bounded structured transcript evidence only after NeedsLineage, then submits it with a new request ID; owner selection remains in the daemon. Stop waiting/listeners, shell command injection and stdout stay host-owned. One ConfirmFlushed follows complete output flush and combines exact mailbox, bootstrap and independent Task-history receipts; non-PTY UserPromptSubmit requests bootstrap without preparing mail. Child Stop releases its native claim after confirmation. Existing borrowed ordinary-hook policy is test-only; native mod retains its separately named daemon adapter.

Every Copilot callback with a differing established session is neutral before position, status or output. The native Pending handler also fences both ToolResult and Stop, including retained reply replay; skipping a position update alone cannot authorize main-session mail.

Legacy shared mail/bootstrap/poll/lineage/stop helpers in common, PiFamily/OpenCode start/endpoint handlers and plugin_rpc DB handlers are test-only. Pure argv, permission and JSON helpers remain production. Claude actor's explicit-env capability/name checks are named daemon lifecycle helpers; its ambient resolver is test-only. Directory location grants no storage permission.

Codex PreModelRequest/PostModelRequest are synchronous observation-only hooks, routed through the participant model-request operation. They never pull mail or confirm delivery. [State/error design](../../.docs/model/model-request-errors.md) owns success/error semantics and native ordering limits.

Current identity adaptation uses native sender names in hook delivery status and omits retired metadata from stopped snapshots and PID records. Claude subagent allocation preserves the parent/session relationship through the current `SubagentAllocation` contract. Hermes activation uses the current binding-initializer signature. Codex `bridge::RootLaunch` contains explicit name, initial cursor, effective launch arguments and adopted profile provenance; root reservation keeps its existing execution/owner/session fences. [The metadata cleanup](../../.controller/agent-metadata/cleanup.task.md) owns independent integration validation; these bounded caller adaptations do not run Cargo/build checks.
