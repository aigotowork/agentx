# Codex shared runtime

Read the root [AGENTS.md](../../../AGENTS.md), current [runtime Task](../../../.controller/domain-daemon/tasks/runtime.md) and [domain contract handoff](../../../.controller/domain-daemon/contracts-handoff.md). The [earlier shared-runtime Delivery](../../../.controller/codex-shared-runtime/AGENTS.md) retains historical implementation and acceptance only. Production declarations in this directory own native-service, root qualification and protocol routing contracts; generic identity and mailbox contracts live in [attachments](../../agents/attachments.rs), [inbox](../../messaging/inbox.rs) and [activation](../../messaging/activation.rs).

| Work | Owner and source |
| --- | --- |
| Service discovery, compatibility, backend generation and framed client transport | Runtime; [service.rs](./service.rs), [topology](../../../.docs/codex-activation/topology.md) |

Use the [contract and file handoff](../../../.controller/codex-shared-runtime/contracts-handoff.md) for exact edit boundaries and effect ordering. Source dependencies flow from this integration to the generic contracts; generic agents/messaging must not import this module. The launcher chooses the integration for supported app-server inputs only. Closing a client connection never owns shutdown of the shared backend. Do not confuse backend execution identity with a per-proxy attachment controller token.

The callable runtime entry is [bridge.rs](./bridge.rs), composed from the native service and generic stores by `bridge/stdio.rs`. Its `session.rs` owns root qualification and native lifecycle, and `driver.rs` owns actual-input adaptation and receipts. Generic `ActivationPolicy` owns claim selection; the adapter validates/marks Issuing before a possibly partial write. History recovery may confirm an exact recorded input; absent or incomplete history cannot authorize replay.

[Terminal transport](./bridge/terminal.rs) adds a private Unix WebSocket frontend to the same actor. The explicit Linux pilot selects it on the shared app-server entry using `AGENTX_CODEX_TUI_SOCKET`; the socket address is consumed before composing thread or backend environments. Socket setup does not reserve a participant. One accepted connection owns one bridge controller, with the same attachment and inbox fences as stdio. This optional transport must stay outside ordinary foreground and headless terminal launches; see the [terminal-sharing Task](../../../.controller/codex-terminal-sharing.task.md) for the direct native route and its outage requirement.

[Direct terminal](./terminal.rs) keeps the launch reservation's configured root loaded while the TUI uses its own native connection. The worker sends AgentX mailbox input and [operator recovery](./terminal/recovery.rs) to that exact thread. The PTY neither registers a second controller nor exposes an injection endpoint; native `/new` remains unmanaged. See [terminal launch usage](../../../.docs/architecture/terminal-sessions.md#codex-agent-command-center) and the [Task](../../../.controller/codex-terminal-sharing.task.md) for the automatic selection boundary and verified versions.

[configuration.rs](./configuration.rs) classifies only the native command position and translates caller `-c`/feature overrides to thread config. Official managed daemon start ignores those process flags, so do not forward them while pretending hooks were applied. [protocol.rs](./protocol.rs) owns raw envelope routing, independent directions and connection handshake/subscription semantics; opaque nested JSON never goes through a reduced DTO. Shared hooks use explicit child context and payload session lookup; early unbound hooks do not create a participant. The exact callable source and current verification limits are linked from the [bridge Task](../../../.controller/codex-shared-runtime/tasks/bridge-composition.md) and [acceptance](../../../.docs/codex-activation/acceptance.md).
