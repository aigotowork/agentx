`ParticipantRef` preserves exact `created_at.to_bits()`. `AttachmentOwnerId` identifies one proxy; `ExecutionId` identifies its runtime generation; `BindingId` is fresh per attachment. All three meanings are distinct. The store has no Codex DTOs, home normalization or daemon lifecycle authority.

Daemon attachment writes receive authenticated `AttachmentOwnerProcess`. A matching exposed owner token also requires matching PID and nonempty OS incarnation to replace a live binding. Fresh registrations and native reservations retain request outcomes with their mutation in one transaction; reusing that request ID with another intent conflicts. Source support and executed evidence remain separate in the Task.

Hook StopSession is self-actor and incoming-session fenced. Freeze retired participants and stored process incarnations before deleting rows; retain the exact outcome with the transaction so a lost reply can recover cleanup without resolving a name again. Runtime rechecks a nonempty captured OS incarnation before every signal or survivor-tracking effect. A retired row does not prove completed host cleanup, and a successor never inherits a predecessor's cleanup authority. Preserve provider-specific soft/continued-process policy; do not call legacy signal/wait helpers from daemon transactions.

Launched HookSession callbacks require the still-current reserved process binding before unbound creation is considered. A missing/retired launched binding cannot create another identity or adopt a successor's session. Binding and ordinary Status callbacks reject the operator's `exit:killed` marker, retaining its authority through in-flight hooks. Unlaunched adoption, live session switches and explicit OMP soft-stop recovery keep their separate existing policies. The [management acceptance](../../.controller/agent-management/evidence.md) records the late-hook race that requires these native guards.

Operator completion shares the same hard-stop core after lifecycle ticket authorization and exact killed-marker validation. The internal helper requires an already-open authority transaction and uses a nested rollback scope; lifecycle retains ticket intent plus the whole cleanup plan so a lost reply can recover it before checking the now-deleted row. The target's hook/plugin or registered-host killed exit also retains that canonical plan by generation and exact participant. CompleteKill can recover it only after matching the original ticket, kill-owner token, PID/stored incarnation, initiator and marker time; absent rows alone remain unknown. Namesake successors reject recovery. Do not nest a second retained request under the same ID or duplicate descendant teardown in the operator handler.

ToolActivity and ObserveHookPosition require the exact resolved actor. Managed observations supply the full current activation target; the store obtains the qualified session from the current Attachment, since ActivationTarget contains only participant/execution/binding. An attached position observation must report that session, and an established different row session is stale. Position changes only explicitly supplied metadata and preserves omitted values; it creates no process/session binding or startup effects. Tool activity atomically records canonical first-detail status and every subsequent apply_patch file event. Same-request replay cannot reapply superseded metadata/status or duplicate file events; required-write failure rolls back the entire observation.

System cleanup has its own internal admission; it cannot impersonate a hook self actor or an operator kill ticket. Positive process exit/incarnation evidence beats clock inference, while unknown observation preserves ownership. A guarded parent is deferred if any descendant has its own PID. Listing retains wake grace and clock/live-PID protection; placeholder timeout keeps its placeholder event marker. Retirement and the entire returned plan commit together; the same originating request ID recovers a lost reply and namesake successors reject its effects. A new read or absent row is not evidence of completed host cleanup. The exact host carriers are Listing.cleanup, Maintenance::Cleanup, lifecycle ResumeResolution.cleanup and Hosts::LaunchStatus.cleanup; each uses runtime::stop_effects only after the native response returns.

Session-switch binding calls `hook_store::soft_retire_switched` under its existing binding transaction after moving runtime state and clearing the old PID. This DB-only soft retirement preserves the old cursor/row and required subscription snapshot while removing its old binding/subscriptions. The continuing process receives no stop/track action. Legacy mixed lifecycle/common helpers still have separately tracked legacy consumers; a pure stored helper does not grant their terminal/signal siblings daemon permission.

Stored status projection has no terminal/log evidence branch. The old evidence-capturing status/finalization wrappers, placeholder/stale cleanup, dead-process reaper/TrackedProcess and ambient/flock name allocators are test-only after removal of the client's borrowed router tail. Keep `names::{describe_generated_names,reserve_generated_name_with_timeout,allocate_subagent_instance_in_directory}` available for native BootstrapSnapshot, resume reservation and Claude child allocation respectively. Production cleanup uses the retained SystemCleanup boundary and explicit host effects. Exact per-function guard disposition and remaining sibling caller-removal dependencies live in the consistency Task.
# Launch profile history

Native `launch_service::Reserve` and `runtime::hosts::NativeRootReservation` carry optional adopted profile provenance. The daemon writes it with reusable launch args; `lifecycle_service::ResumeSnapshot` reads it from current/stopped records. Preserve the saved definition when editable config changes; do not re-resolve profiles during resume/fork. The claim is configuration provenance, never process authority. [Usage](../../.docs/launch-profiles.md) and [Delivery](../../.controller/launch-profiles/delivery.md) own behavior and evidence.

Model-request errors use [model_request.rs](model_request.rs) and [model_request_store.rs](model_request_store.rs); follow [the state model](../../.docs/model/model-request-errors.md). Ordinary status writes preserve unresolved errors; only matching successful request evidence clears them.

[Manual recovery](recovery.rs) and its [daemon store](recovery_store.rs) bind a failed request and a subsequent Codex Stop to an exact live PTY continuation. Discovery and admission check local participant, failure, workspace and label predicates; only the registered delivery host may claim and submit. This operation keeps its receipt separate from both the mailbox and the Provider's successful model observation. See [Delivery](../../.controller/agent-recover/delivery.delivery.md) for supported hosts and verification.

Office management adds `workspaces::checked_collaboration` for explicit missing/valid/unavailable saved-data observations without changing legacy workspace behavior. `Launch::EndpointInspect` is a pure read using the existing retirement/compatibility policy; only EndpointLookup/Reserve may adopt/bind. The [unified design](../../.docs/agent-management/offices.md) and [Delivery](../../.controller/office-management/delivery.md) own support/evidence.

Optional individual responsibility is owned by `launch_title.rs`: shared CLI/native validation and reads from durable `launch_context.title`, distinct from identity, Role and instructions. Reservation persists it; recapture preserves it; stopped snapshots and native resume/fork carry it. See [office implementation](../../.controller/office-details/implementation.md). Native created-event `participant` freezes the exact incarnation for read-only scene observation; legacy event names alone never establish an incarnation.

## AgentX creation provenance

[launch_relations.rs](launch_relations.rs) owns immutable creation records and exact incarnation aliases. [Feature design](../../.controller/agent-launch-relations/design.md#source-grounded-implementation-model-pivula-2026-11-15) owns semantics. Launch reservation records the original native resolved caller before Provider readiness; failed starts retain facts. Resume and canonical restoration inherit creation without reparenting; fork captures its actual initiator independently of Provider source. Legacy, shared-root and Relay evidence can remain unknown. Preserve Provider parent fields and exact generation/instance fences.


Native participant addressing uses the stored `name`; stopped-name lookup also uses that exact name. Provider agent IDs retain their explicit resolver. Identity display/alias helpers are removed: consumers read `InstanceRow.name` or `StoppedAgent.name` directly. `Registration`, launch `Reserve`/`Batch`, and `ResumeSnapshot` carry only their current native contracts; lifecycle configuration retains timeout/subagent-timeout/hints operations. `launch_title::pane_display(name, role, title)` decorates terminal presentation independently of addressing. Binding initialization and `SubagentAllocation` use only the declared participant/session fields. [The cleanup assignment](../../.controller/agent-metadata/identity.task.md) owns the bounded handoff; database upgrade guarantees live in [storage guidance](../db/AGENTS.md).


Historical managed-session snapshots are projected through `AgentxDb::project_instance_snapshot` before row restoration. This prevents retired stored fields from breaking canonical restore or recreating removed metadata while retaining the existing cursor, ancestry and fresh-incarnation policy. [Mailbox acceptance case A4](../messaging/inbox/acceptance_tests.rs) includes a historical-extra-field snapshot; Rust execution remains with the integration owner.

## Scalar labels

[labels.rs](labels.rs) owns `LabelSet`, validated scalar key/value and AND predicates, `PatchLabels`, exact snapshots and the `Participants::Labels` native leaf. [labels_store.rs](labels_store.rs) owns current-local exact admission, creation-owner mapping, retained patch results, revision/CAS, transaction-bound `labels_changed`, creation-time initialization and bounded selection/hydration. The [classification model](../../.docs/agent-classification.md) and [native Task](../../.controller/agent-labels/tasks/native.task.md) own accepted semantics and current evidence. Management/CLI consume this provider before expensive projection; do not reimplement selectors or overwrite whole maps.

Label owners are the existing immutable creation UUIDs. Native resume/canonical restore aliases retain the owner; fresh creation/fork/name reuse do not inherit labels. Read-only legacy participants have empty/revision `0` without creating history; their first changed patch establishes an unknown-origin mapping. Reserve commits explicitly supplied labels before first observation. No-op updates neither increment revision nor append a change event. Label fields never enter prompts or Provider arguments. `deserialize_unique` must annotate each external label map carrier so repeated JSON keys cannot disappear silently.
