# Same-pass configuration observation

Window selection uses `terminal`; background selection uses `headless_terminal` (`pty` or `tmux`). `tmux_socket` and `tmux_config` are scoped path declarations interpreted by the runtime host, not the daemon. Read [terminal sessions](../../.docs/architecture/terminal-sessions.md) for defaults, overrides and existing-session behavior.

[`profiles.rs`](profiles.rs) owns named tool argv definitions, default references and scoped CRUD using the existing `file.rs` lock/atomic editor. [Usage](../../.docs/launch-profiles.md) and the [Delivery](../../.controller/launch-profiles/delivery.md) describe selection and evidence. Profile file operations do not acquire the daemon; runtime owns effective launch composition, and native participant storage owns adopted provenance. Do not flatten profiles into the ordinary scalar FIELDS catalog or introduce a second source for Provider model settings.

[`roles.rs`](roles.rs) owns filesystem role/workspace discovery. File-backed prompts prepend their canonical absolute source path and parent-relative reference guidance before the unchanged UTF-8 body; inline prompts stay literal. The resulting text is adopted into existing launch history rather than reread on resume. See [role usage](../../.docs/roles-workspaces.md) and [Delivery](../../.controller/roles-workspaces/delivery.md).

[`roles/workspace.rs`](roles/workspace.rs) owns the shared workspace selection policy: explicit workspace, explicit-directory project discovery, inherited membership, cwd discovery, then personal `HOME/.agentx`. Git marker files/directories are searched before AgentX project markers. Passive discovery creates no directories; role lookup accepts an uncreated normalized personal anchor. See [accepted design](../../.docs/proposals/workspace-discovery.md) and [Task](../../.controller/roles-workspaces/tasks/workspace-discovery.task.md). Role namespace discovery remains independent of membership discovery; cwd is resolved separately by launch.

The existing resolver and field catalog live in [`../config.rs`](../config.rs); [`file.rs`](file.rs) owns file edits. Read the [native Configuration guide](../observability/AGENTS.md#configuration-evidence-maintenance) and [service insertion rules](../service/AGENTS.md#observation-insertion-boundaries) before adding instrumentation. Exact capture/disclosure types remain in `observability::configuration`, not this adapter.

`observation.rs` records source-read disposition, parser issues before effective error filtering, selected/shadowed/empty candidates, original coercion/normalization and the original validation fallback. Trace keeps finite field/source/issue identities only. Never save raw candidates/errors or invoke a second resolver for telemetry. `load_for_scope_observed` returns the same actual AgentxConfig/errors plus that pass's trace; `NativeConfigResolutionSource` implements only the separately explicit originating reevaluation port.

Scoped declarations describe the exact parsed ConfigToml read with InputOnly semantics; they do not claim effective precedence or normalized values. Effective snapshots use the actual resolved values plus that same pass's receipts. If the supplied scope is not the actual published canonical scope, do not fabricate a ScopeDeclarations identity. Terminal custom commands and overriding user presets remain withheld; the native disclosure projector owns all field policy.

`load_env_extras_observed` preserves the existing launch env parser and supplies only its same-read receipt. It does not retain the env map in observation or invent syntax validation the parser did not perform. Source reads preserve original clock/time/revision; later snapshot publication and file edits do not rewrite them. TLS capture scopes restore prior traces on nested return/unwind. The [composition Task](../../.controller/observability/implementation-tasks/composition.md) owns insertion/case handoff; native integration alone executes checks.

`EnvironmentSettings` / `read_environment_settings` in [`../config.rs`](../config.rs) are the startup-only `[environment].files` string-array and `.override` boolean contract; they intentionally sit outside ordinary `AgentxConfig` export. Higher selector/boolean sources shadow lower declarations independently. [`file.rs`](file.rs) maps `env_files`/`environment.files` and `env_override`/`environment.override` to locked edits. Follow the [originating environment design](../../.docs/architecture/environment.md) for the frozen control-scope rule and safe failure/provenance policy; do not resolve dotenv within daemon configuration reads.

`roles::list_roles_for` adds adopted-owner discovery; `list_roles` remains the public view unless `all` is selected. Two-level `OWNER.HELPER` files are auxiliary roles, with independent prompts/profiles and no default endpoint. Explicit resolution remains unrestricted. See [auxiliary role usage](../../.docs/roles-workspaces.md#角色专属辅助角色).

`roles::RoleDefinition` is a filesystem definition with an optional profile; `ResolvedRole` remains the concrete adopted snapshot. `roles/reader.rs` parses schema-tagged Markdown and same-workspace thin TOML overrides. Both role directories mark a workspace; TOML wins within a workspace, then nearest workspace wins. Disabled names suppress fallback. Discovery never resolves launch profiles. See [convention-role maintenance](../../.controller/convention-roles/AGENTS.md).
