# Event observation and listener lifetimes

For the subscription and one-shot reminder contracts, see [event subscriptions](../../.docs/architecture/event-subscriptions.md) and [the reminder implementation task](../../.controller/time-reminders/implementation.task.md). [reminders.rs](reminders.rs) owns exact caller/recipient admission, the due cursor and restart recovery. [SQLite storage](../db/reminders.rs) owns conditional transitions; the reminder event and terminal state share one write scope. System reminders bypass ordinary subscription matching.

Read [client architecture](../../.docs/architecture/clients.md) and the [client Task](../../.controller/domain-daemon/tasks/clients.md#events-compatibility-continuation-after-s9). Native [service](service.rs) owns bounded event pages, subscriptions, exact listen and temporary observer operations. [store](store.rs), [history_store](history_store.rs), [listening_store](listening_store.rs) and [observer_store](observer_store.rs) are daemon persistence adapters. Generic predicates stay inside the existing event authorizer; no table/query capability is exposed.

[CLI events](../cli/commands/events_client.rs) and [listen host](../cli/commands/listen_client.rs) own output and waits. Listener pulse updates last_stop only, preserving tcp_mode and wait_timeout. Begin cannot recreate a fired subscription on replay. End only removes its exact subscription and matching endpoint, and never overwrites a successor or newer listener status. Subscription JSON writes stay in the named helpers in db/subscriptions.rs. Host output must flush before exact mailbox confirmation; event observation alone never advances participant delivery cursors. Independent integration executes [page cases](acceptance_tests.rs), [native listen cases](listening_tests.rs) and the actual host cases.

History Query keeps a peer/generation-bound manifest of exact native-name filters and scoped source watermarks. Pages merge by timestamp/source/id with a keyset cursor; neither offsets nor a shared event ID can continue independent archives. Query replies stay within MAX_PAGE_EVENTS/MAX_PAGE_BYTES, including source labels. The host ends observed snapshots after collection/error; abandoned manifests are harmless observation metadata retained until explicit end or reset. Missing/replaced frozen sources fail, and new sources/appends stay outside the outer row window. Event-projection CTEs also fence ordinary subqueries and collision filters; volatile SQL expressions or explicit `main`-qualified subqueries keep their normal per-request evaluation. This is a watermark window, not a retained SQLite transaction. Current local one-shot queries alone request canonical unknown-agent warnings; archive, wait and follow keep warning suppression.

Observer Begin/Check/End owns a unique events_wait endpoint for an authenticated peer/invocation and exact ParticipantRef. It never changes status, heartbeat, subscriptions or inbox state. End is idempotent and cannot clear another observer even when TCP ports coincide. `db::after_event_logged` invokes observer wake only after defer_event permits postcommit effects; rolled-back events never notify. Unknown OS incarnation is not authority to wake a potentially reused port; positive dead/reused owners are cleaned up. Host waits use NotifyServer plus a five-second fallback, bounded local interruption/output checks and saturating duration math; anonymous observation polls on a short tick. Follow reacquires only an existing daemon after a query generation rejection and continues without re-resolving the retired participant. Native [history cases](history_tests.rs), [observer cases](observer_tests.rs) and [actual host cases](../cli/commands/events_client_tests.rs) are authored for independent integration; source readiness is separate from a pass receipt.

The optional ordinary observer [hint worker](../runtime/notify/observer_hints.rs) handles only refresh hints. SQLite observer qualification and stale/retired cleanup remain here; registration and database changes revoke matching pending work conservatively before it can create a new connection. Do not use this worker for retirement, launch waits, Provider or mailbox delivery. See the [post-commit design and rollout boundaries](../../.docs/proposals/daemon-postcommit-performance.md).

Retained event peer fingerprints exclude `InvocationContext.observation_origin`: each IPC attempt gets a fresh diagnostic correlation, which is not caller authority. Listener, observer and history lifetimes share `store::peer`; keep process incarnation and identity claims fenced across calls.

Participant, instance and mention filters use supplied native names directly. The parser/SQL builder performs no display-name lookup, and `resolve_filter_names` is removed. `store::predicate(query)` is now a pure filter/predicate compiler shared by ordinary, archive and listen paths. [History cases](history_tests.rs) preserve source/watermark fences and live/historical unknown-name warnings using exact names. The metadata cleanup coordinator owns independent Cargo/build execution; this source adaptation runs none.

Live and archive page output applies `AgentxDb::project_event_data` only to lifecycle metadata and native participant snapshots. Discover each source's retired columns before installing the existing event-only SQL authorizer. Archive reads preserve their original bytes, event IDs and timestamps, while unrelated message payload properties remain user data. `historical_projection_uses_source_columns_without_rewriting_archive_or_message_payloads` covers the live/native/archive read paths; coordinated independent execution supplies its pass receipt.
