# Runtime ownership

Fresh-launch cwd is explicit `--dir` or originating cwd; do not replace it with workspace membership. [`config::roles::select_workspace`](../config/roles/workspace.rs) owns the accepted project-root/inheritance/personal-default priority. Every child receives the final path or `global` in `AGENTX_WORKSPACE`, matching its persisted collaboration snapshot. Existing resume/fork history remains adopted data. See [Task](../../.controller/roles-workspaces/tasks/workspace-discovery.task.md).

PTY titles and terminal labels share the terminal-only projection in [`agents/launch_title.rs`](../agents/launch_title.rs): native name, adopted role and optional launch title. Launcher templates, process registration and delivery refresh consume it; canonical addressing and wake recipient names remain independent. See [role usage](../../.docs/roles-workspaces.md).

[`tmux.rs`](tmux.rs) owns scoped detached tmux sessions and attachment commands. Read [terminal sessions](../../.docs/architecture/terminal-sessions.md) for the separate window/headless defaults, socket/config resolution and lifecycle. Existing PTY host metadata retains the actual socket/server/pane for later attach; new configuration never redirects an existing Agent.

[`launch_profile.rs`](launch_profile.rs) selects one config base and composes native argv exactly once. CLI and Relay consume its frozen result through `launcher::prepare_resolved_execution`; runners must not read profile selectors again. [Profile usage](../../.docs/launch-profiles.md) and [Delivery](../../.controller/launch-profiles/delivery.md) own operation and evidence. Resume uses historical args/provenance, not the editable profile catalog. Early stdio project preparation defers profile selection until the effective environment is ready.

Role/workspace launch composes [filesystem role definitions](../config/roles.rs), profile selection and [native collaboration metadata](../agents/workspaces.rs) once. `launcher` checks native workspace support before new role/workspace effects, carries `AGENTX_WORKSPACE` to children and reserves adopted metadata before bootstrap. `bootstrap` appends the adopted role prompt and raw fresh-launch instruction additions to the existing fixed-instruction sources and filters the peer snapshot by persisted membership. Resume uses adopted history, not edited role files; generated resume/fork identity instructions never replace the stored additions. See [role/workspace usage](../../.docs/roles-workspaces.md) and [Delivery](../../.controller/roles-workspaces/delivery.md).

`bootstrap::ROLE_WORKSPACE_GUIDE` owns the single routine delegation example and concise role/team usage taught by both main startup and native subagent prompts. Teach direct `launch --go --headless --title ... --bind ... --agentx-prompt ...` with configured defaults; role selection is optional and profile discovery belongs to configuration work or diagnostic-driven recovery. Keep detailed role-file setup in the CLI roles declaration, which `docs --cli` and recursive help reuse. Preserve alternate-command substitution, capability exclusions and fixed-session lifetimes; publishing new guide text does not rewrite already frozen instructions. See the [guidance Task](../../.controller/roles-workspaces/tasks/guidance.md#routine-delegation-guidance-correction-2026-11-17) for scope and executed output evidence.

Read root [AGENTS.md](../../AGENTS.md), [runtime-host model](../../.docs/architecture/runtime-hosts.md) and the current [runtime Task](../../.controller/domain-daemon/tasks/runtime.md).

`launcher`, environment/project preparation, `codex_stdio`, terminal and PTY modules own caller processes and I/O. They must preserve caller cwd/effective environment, signal/status propagation and machine stdout. Native Codex app-server lifetime belongs to its native service; an outer bridge owns only its connection. Do not install executables, modify live services or recreate a PATH Codex wrapper.

[`hosts.rs`](hosts.rs) owns typed root/host operations and registration fences. Persisted process identity must come from authenticated `RequestContext.process`, never the daemon PID or caller environment. [`hosts_store.rs`](hosts_store.rs) is daemon-only capability implementation; it may borrow the daemon connection, but does not open one. Provider adapters consume `HostService`, `AttachmentStore` and `PendingInbox` through injected clients. Native declarations own exact contracts; model/task records distinguish implemented paths from unverified migration targets.

`notify` separates connect-and-close wake from request/response terminal injection. A wake is not a message receipt. Hooks commit only after output flush; native input commits only exact recorded input evidence. Keep pending claim uncertainty across disconnects.

[`process_host.rs`](process_host.rs) supplies the client process lease; [`process_host_store.rs`](process_host_store.rs) implements daemon-only process/peer/participant fences. PTY delivery uses [`messaging/delivery/host.rs`](../messaging/delivery/host.rs) for caller I/O and native [`delivery_service.rs`](../messaging/delivery_service.rs) for persistence policy. [`launch_status_client.rs`](launch_status_client.rs) owns caller waiting over instantaneous daemon snapshots; it never occupies the daemon worker with a wait. Bootstrap clients use `bootstrap::get_bootstrap_client`, rendering caller-local configuration/scripts from the typed durable projection.

Admitted relay work uses `launcher::launch_with_client` with the retained Client generation. `launch_with_context` is an originating capture wrapper; per-child invocation changes use `with_invocation`, never daemon reacquisition. Shared Codex stdio and supervisor ProcessHost composition accept that same retained Client. Launcher host/context/client scopes must agree; cross-scope work requires a separately scoped originating host.

[`kill_client.rs`](kill_client.rs) owns operator signal/pane I/O after a native one-time kill ticket grant; [`stop_effects.rs`](stop_effects.rs) applies frozen canonical retirement effects for both hooks and operator kill. A missing participant alone never proves kill completion, and an uncertain issuance cannot authorize another signal. [`resume_client.rs`](resume_client.rs) owns originating Provider discovery and argument preparation; its exact source fence is validated again in the same native transaction that reserves the launch. [`launch_options.rs`](launch_options.rs) holds the shared existing launch flag parser, while CLI files retain presentation. [`terminal_client.rs`](terminal_client.rs) uses an exact participant projection before caller-local terminal screen/inject I/O. Managed tmux launch always uses `tmux.rs` and the shared PTY runner, whether attached or detached. `LaunchResult.attach_participant` is a local-only presentation intent holding the exact reservation fence; CLI reports the launch before calling `attach_after_launch`, and serialization must not forward that intent to Relay. Explicit terminal selection overrides the implicit current-terminal default; see [terminal sessions](../../.docs/architecture/terminal-sessions.md). These ports retain the supplied Client generation and never open managed storage.

[`process_tracking.rs`](process_tracking.rs) separates host pidtrack capture/removal from the daemon's fallible supplied-facts `try_adopt_orphans` core. Native lifecycle checks each captured OS incarnation and commits exact row/binding changes before the host removes successful PIDs. The old immediate claim wrappers are test-only. Bootstrap's borrowed renderers and notify::wake_all are also test-only; production uses the typed BootstrapSnapshot plus local rendering and snapshot wake ports plus host transport. The separately accepted domain postcommit wake path remains named in the storage-boundary model.

Observability remains under [`../observability`](../observability/AGENTS.md). `launcher::launch_with_client_inner` supplies the actual same-pass scoped config trace to the originating capture, then records a safe HostPlan after real backend/regime/cwd/tool/provider-home resolution. The launch environment file supplies only the receipt of its actual read; arbitrary overlay maps, env keys/values, argv and launch JSON are excluded. Plan construction does not claim successful child startup or complete field consumption. Native host registration/renew/release callbacks run only after their existing authority/fences and successful transaction, using exact participant/process/execution projections; observation has no control token or new registration authority. The [composition handoff](../../.controller/observability/implementation-tasks/composition.md) records exact sites, limits and authored versus executed evidence.

Originating dotenv loading is owned by [`environment.rs`](environment.rs) and the [environment contract](../../.docs/architecture/environment.md). Read that contract before changing main/project/config/launcher ordering. Freeze controls from the pre-dotenv scope, preserve caller empties and source ordering, and keep `InvocationContext.environment_file_keys`/host retention metadata separate from identity authority. Internal serve/runners consume prepared values without reloading files. New-window/nested child composition must retain selected values after shell cleanup; source inspection stays local/value-free. The [Native Task](../../.controller/environment-loading/tasks/native.md) owns source handoff; independent execution belongs to its named acceptance peer.

`agent_context.rs` owns separate instruction/context contributor ports and three preparation entries. `bootstrap.rs` freezes instructions through native `agents/context_service.rs` before reading dynamic snapshot sources; `agents/context_store.rs` owns participant/session persistence and initial-context receipts. See [usage](../../.docs/agent-context.md). Keep files/commands in the originating host, native state behind typed capabilities, and Provider injection/confirmation in adapters.

Process-host RegisterProcess rejects the operator's exit:killed marker before any process/launch-context mutation. PrepareKill freezes the current PID/incarnation and delayed PTY registration cannot transfer that ownership during kill completion. See the [office integration race evidence](../../.controller/office-management/tasks/integration.md#stop-completion-race-office-04).

`inspection.rs` owns one daemon-lifetime originating collector loop: inspect generation/revision, read bounded native-selected Provider sources, submit internal samples, and finish deterministic queued reports. It runs independently of browser lifetime; collection defaults disabled. Native inspection store rechecks current source/session/instance before admission. See [live UI integration](../../.controller/live-ui-integration/AGENTS.md).

Launch provenance uses the originating `Client::invocation` through launch reservation, independently of the child process environment. `CreationSupport` capability discovery refuses a new launch client against an older decoder before mutation. Relay explicitly clears ambient worker actor claims and marks unavailable origin. Shared native-root bootstrap preserves an already reserved creation; otherwise its origin remains unknown. See [creation model](../../.controller/agent-launch-relations/design.md#source-grounded-implementation-model-pivula-2026-11-15).

`launch_profile::prepare_with_role` is the shared CLI/management fresh-launch composition boundary. Read the optional-profile definition before profile selection, respect explicit launch selection, then freeze the actual named profile into ResolvedRole. Do not put unresolved profile values into adopted history. Directory default selection and historical resume/fork retain their existing owners. See [convention-role maintenance](../../.controller/convention-roles/AGENTS.md).

`process_host_store` authenticates snapshot progress against the registered kernel peer/incarnation. The daemon read lane records it in `poll_progress` under the exact process registration token, and only the existing fenced heartbeat checkpoints it. Delivery reports expose this separately from model activity and mailbox confirmation; see [recovery usage](../../.controller/message-delivery/usage.md).
