# Product client context

## Caller identity

`router::GlobalFlagParser` and `extract_global_flags_full` expose `--iam NAME` as the explicit caller option, captured in the existing `InvocationContext.explicit_name`. There is no `--name` caller alias. `start::StartArgs.name` alone owns public `start --name` registration input; keep it separate from the caller claim. Provider arguments after `--` and internal hook RPC fields retain their own grammar. Standalone work/workbench/observe-web parsers use the same caller spelling where supported; browser calls still clear actor claims.

Commands normally resolve injected process/session/actor context. `Session::connect_required` propagates missing/expired claimed identities for send/listen; identity-free queries retain best-effort resolution. Verified actors and thread attachments still reject conflicting explicit claims. Bootstrap and fork prompts teach automatic identity and optional `--iam`; they must not require a caller flag on every command. Send treats message tokens after `--` literally. [CLI smoke cases](../../tests/cli_smoke.rs) cover implicit send/listen, explicit caller versus registration, removed alias, stale bindings and literal tails. Bundled workflows forward `--iam`.

[`attach`](commands/attach.rs) resolves an exact current participant and delegates interactive tmux I/O to `runtime::terminal_client`. [Terminal sessions](../../.docs/architecture/terminal-sessions.md) owns mode selection and usage; the tmux Task owns executed support. Preserve root/recursive help discovery and command aliases when changing dispatch.

[Native daemon CLI](commands/daemon.rs) routes `daemon status|restart [--scope PATH]` before configuration, identity and dev-root setup; `daemon serve` alone reaches main's application constructor. Omitted scope uses the originating environment's standard resolver. Keep this separate from the same file's historical `relay daemon` worker management. Status never starts a daemon; explicit restart uses the daemon-owned [lifecycle contract](../daemon/AGENTS.md). Workbench now defaults scope from the originating environment and project from cwd; local startup acquires once in either mode, HTTP cannot start/select another scope, and `--collaboration` remains explicit. The [direct-call delivery](../../.controller/direct-calls/AGENTS.md) owns the one-time upgrade and lost-reply recovery. A quiet ordinary send can submit without a preflight; use the original request ID with `send --receipt` for readback. Development binary re-exec reads the daemon's private projection through `config::dev_root`, without a CLI startup RPC.

[Work CLI](commands/work.rs) owns finite `work show/list/candidates/command/report/apply` grammar, and [workbench host](../collaboration/web/mod.rs) owns explicit startup-selected scope/project/mode. They dispatch before ordinary identity/dev-root/update setup using their own explicit native acquisition. Reports capture originating invocation/session claims and native exact assignment authority; browser calls clear actor claims and expose operator commands only. Read [native usage](../../.docs/collaboration-workbench/native.md) and [cases](../collaboration/cases.md); compile/test/package execution stays with independent acceptance.

Read [source map](../README.md), [client architecture/inventory](../../.docs/architecture/clients.md) and [migration Task](../../.controller/domain-daemon/tasks/clients.md). Native service declarations own durable operations; CLI files own grammar, presentation, local files/processes and stdout/stderr. Capture caller cwd/environment and session identity explicitly. Help/version and pure local operations bypass daemon acquisition. Never open the managed AgentX database or fall back to it after IPC failure. Provider-owned transcript files remain separate external inputs.

For overlapping lifecycle/send/runtime edits, coordinate with the owner recorded in the Task. Integration owns broad builds and executable acceptance; author cases in the Task and report actual evidence separately.

[Observe](commands/observe/AGENTS.md) owns passive diagnostics before ordinary main/router setup. Its [usage](../../.docs/observability/cli.md) and [original Task](../../.controller/observability/implementation-tasks/diagnostics.md) distinguish source release from independent executable evidence. Import native observation refs/results; never use Session, identity/dev-root/update paths, acquisition/start, live SQLite, report auto-publication or mutation recovery replay. `config-current` is the explicit local reevaluation exception to retained-only reads.

[Listen host](commands/listen_client.rs) owns caller waits, interruption and exact mailbox output. [Events contracts](../events/AGENTS.md) own the temporary subscription/endpoint lifetime; preserve wait_timeout, tcp_mode and hooked mid-turn status. The borrowed listen implementation remains test-only for historical cases.

[Config](commands/config.rs) carries explicit originating scope/environment. Pure file/editor/terminal/help operations bypass daemon acquisition; instance settings, dev_root, runtime overrides and bootstrap rendering use the original Session. File schema/locking/validation stays in config/file; Provider permission effects stay in runtime/config_effects. Instance mutation selects an exact ParticipantRef and preserves literal prefix ambiguity rules. Borrowed instance helpers are historical tests only.

[Reset](commands/reset/mod.rs) composes native summary, exact operator stops, scoped relay-worker shutdown and daemon-owned reset. The host never copies/deletes/reopens managed SQLite. Unknown reset replies fail without replay or follow-on full-reset file/config deletion. Confirmed reset explicitly binds its returned generation for relay notification and suppresses the retired actor's mailbox append. Hook-only reset is local. Historical raw-database reset helpers remain test-only; [actual host cases](commands/reset/client_tests.rs) are executed by integration.

Main extracts originating `--env-file`, `--env-override` and `--no-env-override` before command routing, preserving opaque values and the `--` separator. [`runtime/environment.rs`](../runtime/environment.rs) owns that grammar and metadata/internal-entry bypass. [`config environment`](commands/config.rs) is a passive local value-free source/provenance diagnostic and skips dev-root/session/config-edit paths. `config env_files` accepts one quoted JSON string array and `config env_override` accepts the documented boolean. The [environment usage contract](../../.docs/architecture/environment.md) owns ordering and recovery; never promote loaded values or retention metadata to actor authority.

`router::command_update_notice` lazily gates automatic update effects using the originating lightweight and local metadata classifications. Help/version and passive local environment inspection must never enter `update::get_update_notice`: that cache path can create a scope/flag directory and spawn a background worker. Explicit `update` owns its own output. Keep the causal metadata/ordinary-command cases in `router::tests` when changing this boundary.

`--help-all` is handled by [recursive help](commands/help/all.rs) at main's first argument boundary, before dotenv/direnv, config, identity, updates and native service startup. Native groups expose their existing clap declarations through `help_command`; static groups reuse `help.rs` sections and their literal command usages. Ordinary and recursive help share `help.rs::compact_help`; native parser help displays use `print_clap_error`, preserving error streams and exit codes. Keep descriptions beside arguments and omit internal blank lines; recursive output owns page separators. Preserve opaque option values and everything after `--`; never execute tools or user scripts to discover help. Unknown command paths fail rather than silently returning a parent page. See the [target/reference panorama](../../.sketches/agentx-cli-panorama.md#完整帮助模式).

Role-file setup and role/team examples live in [roles.rs](commands/roles.rs)'s help declaration. Root help and launch/send/list help route callers there; `run docs --cli` and `--help-all` consume the same declarations. The startup/native-subagent guide shares concise commands in runtime bootstrap, not this full setup text. Keep these discovery routes aligned with [current usage](../../.docs/roles-workspaces.md#从哪里发现这些能力).

## Launch CLI contract

Fresh `launch`/`l` accepts bare `--role`, `--profile` and `--tool` (including empty values) as explicit searchable choice requests. Omitted options retain normal defaults; supplied invalid names remain errors. `launch/selection.rs` normalizes bare selectors before main's environment/help scanners, preserving opaque values and everything after `--`, then resolves native catalogs after environment loading and before launch Session acquisition. Role choices share `roles::discovery_actor` and `config::roles::list_roles_for`; profile/tool choices respect explicit compatibility. `tui::select` owns keyboard filtering, stderr rendering and terminal restoration. Escape/Ctrl+C returns 130; non-TTY, JSON, stdio and remote choice requests require explicit names. Shared runtime/resume/fork option declarations remain value-required. See [the bounded Task](../../.controller/cli-selection.task.md).

`router::canonical_command` owns the public shortcuts `l` → `launch`, `r` → `resume`, `f` → `fork`, `k` → `kill`, and `a` → `attach`. Resolve shortcuts only at command boundaries, preserving literal operands and native arguments. Ordinary help, recursive help, launch dry-run and early stdio preparation share this mapping; keep these early paths aligned with runtime dispatch.

Fresh agents use `agentx launch [--profile NAME] [--tool TOOL] [--count N] [options] [-- native-args...]`; count defaults to one and must be positive. Explicit profile/tool, `AGENTX_PROFILE` and scoped defaults follow [profile usage](../../.docs/launch-profiles.md); count remains explicit with no ENV/TOML mapping. `profile` CRUD and local `launch --dry-run` dispatch before ordinary identity/service/dev-root/update setup. Bare tool and numeric-prefix launch commands remain removed. `LaunchArguments` owns new-launch selectors, replacement and dry-run; `runtime/launch_options.rs::LaunchOptions` owns shared launch/resume/fork flags and the opaque native argv boundary. Do not add profile selection to resume/fork. Unknown options before `--` fail. `run` retains its script responsibility. Configured tool args remain native; profile and legacy bases are mutually exclusive and resolved once before backend adjustments.

CLI launch changes must cover router discovery/global scanning, early stdio/direnv preparation, dotenv project selection, TUI argv and bundled workflow consumers. Do not rewrite historical acceptance receipts or live external host profiles. Existing `--stdio` host profiles using the removed grammar require a separate owner-controlled configuration change. This deliberate breaking change avoids parallel grammars; no compatibility window was requested.

Auxiliary Role discovery uses two-level `OWNER.HELPER` names and passive native identity resolution in `commands/roles.rs`. Default discovery includes public roles plus helpers from the adopted owner namespace; `--all` and explicit show/launch remain unrestricted. See [usage](../../.docs/roles-workspaces.md#角色专属辅助角色) and [Task](../../.controller/roles-workspaces/auxiliary-roles.task.md). Never acquire a daemon merely to resolve discovery identity.

Role inspection uses current optional-profile definitions; fresh launch calls `launch_profile::prepare_with_role`. Keep published Markdown discovery, thin TOML overrides, disablement, default-profile/default-recipient distinction and helper scope discoverable in roles help. Shared bootstrap guidance teaches one direct task-delegation command with optional role selection; configuration and native-argument forwarding stay in help. See [current usage](../../.docs/roles-workspaces.md).

## Omitted lifecycle targets

The default TUI, `list` and `attach` share [Agent filter arguments](workspace.rs) and the [native workspace and label projection](../service/queries.rs). Root `--dir`, `--workspace` and `--label` belong to the implicit dashboard, not to later subcommands. The bare dashboard shows the full scope; directory options filter Agent rows, not the timeline. Targetless attach defaults to the current team plus global members; `--all` opens the full-scope picker. A named attach checks any supplied filters before connecting. Preserve the exact endpoint fence and the distinction between workspace discovery and `launch/resume --dir`. See the [accepted design](../../.docs/proposals/agent-target-selection.md).

`commands/target_selection.rs` composes read-only native inventories for omitted attach/kill/resume/fork targets. Explicit targets and `kill all` retain their existing paths; non-TTY and JSON callers must supply targets. Attach selects a local live tmux endpoint by exact participant. Fork carries the active participant fence; stopped resume/fork choices capture the native stop event ID and reject a changed selected snapshot before execution. Kill uses searchable multi-selection and a complete target review before returning names plus frozen exact rows to the existing native kill path. Escape/Ctrl+C returns 130 before command effects. The common `tui/select.rs` owns input, rendering on stderr and terminal restoration. [Selection Task](../../.controller/cli-selection.task.md) owns behavior/evidence.

`kill --dir`, `--workspace` and `--label` filter only the no-target picker. Bare kill keeps the full-scope picker. Explicit names, PIDs and `kill all` reject these filters. Filtered results use the native label inventory's exact participant snapshots; confirmation executes only the accepted selection through the existing stop path, without an orphan sweep.

All Agent choices and kill review rows display `name [role]` before status/tool/location, using the adopted launch context or stopped snapshot; missing role data displays `[-]`. `Choice.label` is searchable display text only: returned values and native identity fences retain the exact Agent name.

## Model-error recovery

`recover` accepts exact local `@name` or bare names, `--all`, repeated native `--label` predicates, or an omitted-target searchable multiselect. Names and picker candidates can also be narrowed with `--dir` or `--workspace`. The picker defaults to the current workspace plus global members; `--all` spans the selected AgentX scope, accepts labels and rejects directory/workspace filters. It only accepts live managed Codex PTYs whose current native request error is still failed and whose Stop observation followed that failure. A durable native recovery ticket uses the existing PTY prompt checks while status remains `error`. This path does not drain the mailbox; only a later successful model request clears the error. Other providers and stopped Agents are outside this command. See [the accepted design](../../.docs/proposals/agent-recover.md) and [Delivery/Task](../../.controller/agent-recover/delivery.delivery.md).

## Scalar Agent labels

[`labels`](commands/labels.rs) maps get/set/remove/receipt to the existing management journal, using exact current local AgentRef and retained generation. Parse assignments through `agents::labels::parse_assignments`; `--label` is opaque to environment/help scanners and accepts one complete scalar after its first `=`. Fresh local terminal launch carries labels through LaunchParams into the reservation transaction; resume/fork do not accept initial labels and preserve their native lifecycle policy. CLI list selectors use `ListingLabels`/native Select before expensive status/unread projection, intersect workspace visibility (including its existing global members), and return labels/revision plus exact incarnation/generation in JSON. Ordinary listing batch-hydrates local labels; remote labels remain unavailable. Receipt replay returns the original operation result, so reread for current labels. See [model](../../.docs/agent-classification.md) and [surfaces Task](../../.controller/agent-labels/tasks/surfaces.task.md) for support/evidence.
