Use `with_write_scope` for owned transactions and nested savepoints, or `with_immediate_transaction` when using the transaction directly. No external provider I/O occurs while the SQLite lock is held. [Attachment behavior](../agents/attachments_store.rs) and [mailbox behavior](../messaging/inbox_store.rs) own the domain decisions; SQL alone does not supply external delivery evidence.

Claude generation attachment, subagent allocation and shell capability issuance compose with an outer native hook transaction through `with_write_scope`; their canonical policy is shared by legacy wrappers. Shell capabilities additionally retain the exact actor incarnation in owned KV state, so an old tuple/name cannot authorize a replacement row. Explicit root rebinding transfers that fence atomically. Legacy optional actor environment remains a fallback claim when revoked or invalid; native exact hook actor admission never fabricates a name to bypass root/child policy.

[post_commit.rs](post_commit.rs) defers event notifications and `wake_after_commit` under an open owned write scope. Nested rollback drops its queued effects; only the outer commit flushes them after releasing SQLite. Domain handlers must use these existing helpers for transaction-bound notifications, rather than notifying from inside a savepoint. This in-memory list is advisory notification ordering, not a durable job queue or external-effect replay guarantee.

The same list also owns safe observation projections from actual producer boundaries. `observe_domain` freezes the original epoch/sink and native references; one outer transaction shares at most 64 projections/64 KiB across nested savepoints. Constant-time admission accounting rolls back with the existing checkpoint; successful outer commit publishes outside SQLite, and an outer rollback discards all facts. Only capped size counting and atomic known-drop accounting occur during preparation; no journal append, store read, transport or resolver runs inside the transaction. Autocommit facts publish after the statement/owned transaction has returned. Collection failure cannot affect the business result.

`events.rs::insert_event_row` supplies EventAppended only from the actual positive row ID, without the row JSON. Successful message acceptance also supplies MessageAccepted with its original request/event/generation and replay flag. Output observation IDs are freshly allocated observation UUIDs; never copy/hash native output tokens or provider receipt/turn material. The [Events handoff](../../.controller/observability/implementation-tasks/events.md#composition-mapping-and-lifecycle-handoff) owns exact safe mappings; the [composition Task](../../.controller/observability/implementation-tasks/composition.md) links authored commit/savepoint/budget cases and independent execution.

`events.rs::after_event_logged` invokes the Events-owned temporary observer wake helper only after its defer_event early return. Events owns observer generation/peer/participant/port admission and cleanup in [observer_store.rs](../events/observer_store.rs); database append policy retains the post-commit placement. A bounded notification does not confirm observer output or advance a cursor.

Successful `delete_instance` and fenced `finalize_instance_stop` retain managed identity/cursor and revoke the deleted incarnation's attachments inside the deletion transaction. A failed stop CAS cannot revoke a successor. Migration from v20 adds tables/indexes in place, retaining existing events and provider state. Independent checks belong to the Delivery integration owner; domain workers do not run routine tests/builds.

Schema v26 adds [launch_relations.rs](launch_relations.rs): durable creation facts and exact incarnation aliases, indexed by creator creation and stable creation UUID for bounded downstream paging. Facts survive live-row/event deletion; stopped-event pointers supply exact retained conversations and may become unavailable. No FK cascade to instances, no transcript copy, no historical name backfill. Managed reset clears both tables with generation replacement. Native event insertion records exact stopped pointers from snapshot.created_at in the existing write scope. The exact alias also retains nullable cancelled-before-ready failure observation when native launch cleanup removes a row.


Schema v27 projects `instances` onto the current [native row columns](instances.rs), retaining internal `running_tasks`. Columns outside that contract are dropped inside the schema transaction, preserving rowids, exact incarnation bits, names, session/parent constraints and every other state plane. A prematurely stamped v27 database with extra columns reruns the same projection; newer schemas are left to their owning binary. A failed storage projection, including a projection after earlier additive repairs, returns an error with the original database and schema version intact, without archiving or replacing it.

Before dropping those dynamically discovered columns, the same transaction removes their root and embedded snapshot properties from lifecycle event data and their root properties from retained participant-session snapshots. Bound JSON paths preserve retained numeric text; malformed historical snapshots stay unchanged. Event IDs, timestamps and mailbox facts remain intact, and projection failure rolls the JSON edits back with schema edits. `events.rs::project_event_data(event_type, data, retired_fields)` projects public lifecycle snapshots onto current writable participant fields; unrelated event payloads are unchanged. Live Events and stopped-history producers share that policy; read-only archive Events discover retired columns from their own source schema without migrating the archive.

| Projection blocked by a dependent index | Roll back all column drops and earlier additive repairs; preserve the old database/version | `instance_storage_upgrade_failure_rolls_back_without_archiving` |

Schema v28 adds [labels.rs](labels.rs): normalized creation-owned `agent_label_sets` and `agent_labels` WITHOUT ROWID tables, covering `(key,value,owner)` and creation→exact-alias indexes, plus a partial adopted-workspace/name index for current-local scope traversal. `agentx_incarnation(created_at)` is a deterministic connection-local function returning the decimal **integer bits**, so current-instance alias joins reject stale resumes/name reuse before final LIMIT. It is registered on ordinary connection creation and inode reconnection. API JSON is not a second writable persistence plane.

Migration/reset integrate with the existing transaction and generation authority: retain all v27 data on additive success; rollback the full v28 migration on failure without archive; clear label rows/heads before creation aliases/owners. v28 must retain the v27 prematurely-stamped retired-column repair by restarting at the projection step when extra columns exist. New native cases in [labels.rs](labels.rs) and [labels_store/tests.rs](../agents/labels_store/tests.rs) await the labels integration owner's coordinated execution; do not treat authored cases as runtime evidence.

Current selection returns at most `limit+1` rows in name order, hydrates <=100 exact current targets in one statement (<=6,400 label rows), and never computes automatic full counts. Scope/selector/generation-bound opaque cursors reject historical or changed-query pages. The temporary SQLite progress handler applies the caller deadline (at most 2s) and 20 million VM operations; exhaustion returns Unavailable rather than a partial page. Plans use production query construction and bundled SQLite in a disposable fixture, not the earlier design SQL experiment.


## Schema stamp recovery

`mod.rs::ADDITIVE_TABLES` associates replayable additive table groups with their introducing migration. Compatibility detection and earliest-repair selection share this inventory; update it with table-adding migrations. A current version stamp does not prove those tables exist. Repair selects the minimum of the recorded version and every missing table/column/projection prerequisite, then runs the existing canonical migrations in one transaction. Missing additive tables never authorize archive/reset; any recognized migration error preserves the original database. `init_db` is bootstrap, not migration: it rejects nonzero versions other than the current version rather than promoting or downgrading a versioned database.

The [home-scope root-cause correction](../../.controller/agent-metadata/cleanup.task.md#authorized-root-cause-correction-2026-11-17) records the historical v20→v26 skipped-migration cause, recovery and bounded regression evidence. The local daemon bootstrap adapter in `src/main.rs` retains the full database initialization error chain. Future-schema databases remain untouched by older code.
