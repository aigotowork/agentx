## Labels projection and writes

`contract.rs` owns browser LabelsSnapshot/LabelsPatch/SubmitLabels and nullable AgentView labels/revision; current local references are populated and historical snapshots without retained fields remain unknown. Descriptor `supports_labels` gates consumer support. `store.rs` adapts native labels get/select/patch; filtered selection happens before live_view and limit, ordinary page hydration is batched. A PatchLabels journal submission commits labels and Succeeded LabelsPatched receipt in one native transaction with no host worker/ticket. GET labels uses generation and exact incarnation; POST labels uses SubmitLabels; existing operations reads reconcile uncertain writes. Repeated HTTP `label` parameters are AND, require explicit `current_only=true`, and use the native selector-bound cursor; historical cursors are invalid. Writable maps retain duplicate-key rejection at native deserialize and strict HTTP wire decoding. Generate TS with the command in [usage](../../.docs/agent-management/README.md); Web client owns draft and conflict/reconciliation decisions. [Surfaces Task](../../.controller/agent-labels/tasks/surfaces.task.md) records actual checks and support limits.

## Native consumer management entry

`service::ManagementService::new(scope, project, invocation, workers)` captures trusted host configuration and the shared `Arc<Semaphore>` worker budget. The pilot methods `describe`, `list_agents`, `get_agent`, `submit_message` and `get_operation` retain their contracts; the complete host boundary also supplies typed lifecycle/labels/mailbox/activity/history, workspace/Role/directory and binary attachment operations. Exact inputs live in `contract.rs`. Do not deserialize invocation/environment/worker admission from remote callers. `client`, `call` and `submit_command` support existing nonpilot host adapters; these internal methods are not public HTTP/RPC endpoints. Reuse this orchestration rather than copying journal/worker policy into an adapter or wrapping every native variant in another trait.

Management list pages are reads; the Management runtime performs periodic dead-process maintenance independently using the same native reaper and applies accepted retirement effects outside dispatch. List limit omission uses 50 and valid limits are 1..100; current selection uses native selector-bound paging. Labels require current selection and retain AND meaning. Each detail, message and receipt call passes the HTTP generation directly to an existing daemon. The daemon confirms it in the operation exchange. Describe reads current native status; passive Management calls never start a daemon or open the database. The HTTP error mapping distinguishes `StaleGeneration` from `StaleReference` within a generation. Submission retains the original command before resolving worker cwd and obtains the native journal grant even when the shared worker semaphore is full. A replay never gets another private execution ticket. HTTP response loss/disconnect never cancels a worker or permits automatic new-ID retry.

For exact workspace membership and launch result identity, use the [Management consumer contract](../../.docs/api-panorama/service-contract-design.md#workspace-membership-and-launch-identity) and the [native handoff](../../.controller/typescript-domain-sdk/tasks/native-completeness.task.md). The workspace page uses the checked saved collaboration snapshot before limiting on the WAL reader; it is separate from catalog discovery and CLI visibility. Launch, resume and fork use one receipt projection of successful native reservations. Older receipts and mixed builds can lack exact references; never reconstruct one by name.

`service/tests.rs::caller_flow` is an executable typed five-method consumer using real native IPC in a disposable same-process daemon fixture. The fixture primes an accepted native grant and uses zero worker permits to verify refusal/replay/conflict/restart uncertainty without running a Provider or subprocess. Existing store journal tests own exact claim, durable completion, bound results and reconciliation cases. [Pilot native Task](../../.controller/contract-service-projections/tasks/pilot-native.task.md) owns execution evidence and handoff; [contract design](../../.docs/api-panorama/service-contract-design.md) owns the consumer semantics.

## Native consumer Service and generated HTTP projection

`service.rs` owns the consumer capability and reused native host/worker coordination, `service/resources.rs` owns typed resource/office/disk orchestration, and `service/inspection.rs` owns the bounded Inspector caller binding; captured scope/project/invocation and the shared worker semaphore are trusted construction inputs. `web.rs` owns admission, parsing, encoding and actual annotated HTTP bindings. `openapi.rs` derives their public OpenAPI, owns the exhaustive HTTP error-envelope mapping, and exports offline through `agentx __export-management-openapi` before runtime/environment startup. Use [projection usage and codec policy](../../.docs/api-panorama/openapi/README.md) and [HTTP Task](../../.controller/contract-service-projections/tasks/pilot-http.task.md) for current emission/integration evidence. ToSchema covers only public reachable DTOs; Request/Response, worker tickets and InvocationContext remain private. Preserve serde as wire authority and regenerate rather than hand-editing generated schemas.

The complete [native Task](../../.controller/contract-service-projections/tasks/full-native.task.md) owns consolidated batch/integration state. All Management handlers consume the same concrete Service. `TargetAction` is host-only lifecycle selection shared by kill/stop compatibility routes. `AttachmentBytes` is an internal metadata/bytes product; HTTP owns binary headers and body framing. Scope catalog, directory inspection and attachment downloads confirm generation through their resource calls. Role catalogs are host-only and confirm generation with one status read. Upload confirms generation before disk persistence and again within native registration; this preserves existing upload effects without inventing a new idempotency promise.

Inspector's public POST selection is `inspection::contract::PublicMutation`, sharing ConfigureInput/AnalyzeInput/CancelAnalysisInput/RequestContinuationInput with native Request. Serialize those four external tags unchanged; never derive/decode the full native Request as the public input. Snapshot, AnalysisJob and RecoveryAttempt remain separate from management Operation. The runtime collector owns Collect/RunAnalysis; the Service does not add a collection/analysis scheduler or another worker process. Whole-batch native cases live in `service/tests.rs`; authored checks and actual concentrated execution are distinguished in the full Task.

Current browser access and embedding use [shared open-origin policy](../../.docs/api-panorama/openapi/README.md#browser-access-policy) through `browser/admission.rs`; [the native Task](../../.controller/web-sdk-adoption/http.task.md) owns source/acceptance status. OPTIONS is side-effect-free. Every actual route retains native authority, identity, input/size bounds and unknown-outcome recovery.
