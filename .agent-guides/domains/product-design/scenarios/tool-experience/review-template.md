# Tool-experience review working format

Use the needed fields in the product's existing review/design/Task, following the [method](../tool-experience-review.md). A small scope may need one finding and a recheck. Delete irrelevant fields; state unknowns and next actions rather than guessing. This is neither a second requirement source nor a mandatory document set.

## Decision and boundary

- Decision to make; canonical scenario/criterion:
- Actor/experience and evidence or assumption:
- Starting identity/version/scope/data/authority:
- Candidate/build, environment, viewport, input and simulation:
- Main path, decisive branch and exclusions:
- Evidence available and unexecuted/unverified boundaries:
- Strengths and promises to preserve:

## Goal, task plan and capability mapping

State the goal and plan, including order, conditions, repetition and exit. Reuse original criterion references; do not substitute a menu tree.

| Criterion/subgoal | Facts needed | Object/version/use site | Action, precision and scope | Native capability/provider | Visible result and continuation | Support/evidence |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

Classify supported, gap, conflict, undecided, out of scope or unverified. Separately identify placeholder, extension, implementation defect or evidence gap. Unknown capability providers remain unknown.

## Critical-step walkthrough

| Node/visible starting state | Form the intention? | Discover/reach/use? | Connect to object/scope/effect? | Understand feedback/continue? | Observed fact versus prediction |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

Record knowledge assumptions, instructions, assistance and prior familiarity. Expert predictions are not first-use participant observations.

## Switch and return

Name the switch, whether it serves the same goal or an independent task, and why the chosen local surface/page helps. Record alternatives and tradeoffs when consequential.

| Relevant context | Before leaving | Holder/checkpoint/lifetime | Expected return and invalidation | Actual observation or unverified gap |
| --- | --- | --- | --- | --- |
| Object/version/scope | | | | |
| Selection/filter/sort/location | | | | |
| Draft/edit mode | | | | |
| Comparison baseline/candidate/difference | | | | |
| Work identity/completed/pending/unknown items | | | | |
| Focus and next-step cues | | | | |

Select relevant stale/deleted/permission-changed, pending or partially completed cases. Record actual repeated finding, selecting and entering; do not infer population frequency, time loss or cognitive scores.

## Precision and visible operation

Keep task/data/viewport fixed. Link representative states and observations of hierarchy, region proportions, grouping, typography, icons/color roles, operation states, keyboard/focus, zoom and narrow layout. Verify actual precision round trip, mixed values, eligible batch scope, preview/apply/undo and native effects. Static, simulated and real-service evidence stay separate.

## Actionable finding

```text
Finding / canonical criterion / trigger:
Build, state, object/version/scope and environment:
Observation and located evidence:
Expected promise/contract or labeled assumption:
Interpretation/consequence; fact, expert hypothesis or participant report:
Gap/conflict/undecided/evidence/preference:
Responsible object/layer and affected neighbors:
Severity and reason / evidence certainty / frequency or unknown:
Proposed result, retained strengths, alternatives and tradeoffs:
Disposition and reason:
Decisive recheck / actual result / limit / receiving owner:
```

For continuity, use one path that changes draft, selects a nondefault candidate/baseline, leaves and returns, then checks identity/scope/draft/comparison/focus. Add a stale-object branch when promised recovery depends on it. Two fresh independent snapshots do not prove preservation.

Close with established conclusions/evidence, selected but undelivered changes, and unresolved owned questions. Link affected original requirements, models, components and designs. Do not equate report completion or automatic checks with delivered user outcomes.
