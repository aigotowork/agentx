# Technical explanations

Use this domain for technical articles and substantial technical explanations, including an interactive example, small application, game or video as the primary artifact. It owns reader decisions, technical arguments and teaching experiences. General document conventions stay in [documentation](../../documentation.md); exact API reference and product usage stay with their existing owners. A spelling correction uses the existing argument and a bounded review.

Apply these constraints to substantive work:

- Identify a concrete reader obstacle and a transferable decision, model or technique. A repository provides cases; its feature inventory is not an argument.
- Establish the important objects, relationships, states and claims. Identify what the reader must observe or operate, then choose the primary form before outlining prose.
- Distinguish actual implementation, platform guarantees, observed results, proposed designs and simplified teaching models. Preserve conditions and failure boundaries in every representation.
- Consider dedicated runnable work when using the mechanism reveals something essential. Justify effort by the resulting experience; production cost alone does not select the form.
- Provide access to the central relationship and conclusion if the primary medium is unavailable. Keyframes, a trace or a visual transcript may suffice; state which exploration remains available only in the running work.
- Discover the consumer's actual source, renderer and publication contract. A plan creates no runtime capability or permission for external effects.

Apply all matching routes and reuse loaded context. Feature or promotional media can enter through materials with their own audience and outcome; technical claims still require evidence. These methods do not require a full article, curriculum, fixed media count or separate reviewer. Keep intermediate decisions and actual checks in the existing content Task or brief. Stop research when the consequential claims are supported and material unknowns are explicit; revise the thesis when the evidence changes it.
