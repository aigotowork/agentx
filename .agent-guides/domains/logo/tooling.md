# Select an actual making and delivery path

Use when choosing a craft medium, a rendering/export tool, a model-assisted operation or a capability for a requested workbench. Start from the intended output and source editability. This guide declares no executable commands or installed adapters. Discover actual capabilities through the consuming project's asset/tool entries and the session's available tools; a Skill description, package dependency or product feature page does not establish a working integration.

## Make useful progress with available capabilities

| Available situation | Action | Claim boundary |
| --- | --- | --- |
| Existing canonical vector/native source and exporter | Use its declared editing path and intended document, then regenerate affected outputs | A configured single-mark generator may not accept arbitrary new artwork |
| Direct SVG/path authoring is sufficient | Keep primitives/paths, meaningful parameters, true holes and editable structure; use the actual available renderer if needed | Rendering is distinct from geometry construction and visual judgment |
| Professional vector or lettering application is connected | Check its host/version, intended document/object, selection/mode and unsaved work before operations; preserve its native source and derived exports | An operation on the currently active document is not an adequate target contract |
| Dimensional expression requires a 3D source | Use a real curve/mesh and material/light/camera path when available; preserve the scene and source lineage | A flat bevel filter or model-generated image is not editable volume or a fabrication master |
| Raster or image-model study serves the brief | Follow the available capability's actual skill, authority and input/output contract; retain art brief, prompt, references, role, outputs and changes | A raster, traced approximation or raster embedded in SVG is not a clean vector master |
| A tool, external source or reference corpus is missing | Use owned/user-supplied references, direct editable studies, plans or comparisons that can be made accurately; name the blocked operation and dependency | Do not fabricate retrieval, source fidelity, an installed application or successful execution |
| Image inspection is unavailable or disallowed | Produce agreed artifacts where possible, inspect structural/render status, and continue from actual user feedback | State visual review as not performed; do not request repeated inspection permission |

If a missing capability is essential to the promised format or fidelity, retain usable partial work and state precisely what remains incomplete. Do not silently replace an editable master with a mockup or lower the agreed fidelity. A method/planning task can finish at that scope without invoking production tools.

## Making and auxiliary construction

Keep four responsibilities distinct: geometry relationships control radii, tangency and spacing; a generation rule explores a constrained family; professional editing changes actual nodes, handles, letters and optical relationships; expression/presentation makes the source judgeable in a medium and context. None chooses the brand idea automatically.

Choose the simplest real source that supports the task. A fixed wordmark may need only outlined paths and optical spacing; a font family needs glyph outlines, metrics and pair positioning in a font source. Keep repeated parameters with their dependent pieces and retain intentional optical departures. A generative family retains code, algorithm/version, parameters and seed when available; a seed alone does not establish reproducibility.

A Boolean result must contain the resolved boundary or a supported live expression with a real evaluator. Operation metadata and a placeholder path are insufficient. Union, compound paths, clipping and region coloring have different consequences. Specify operands/order, preserve useful operands or native history, and verify the actual result for the selected use. A source-derived construction overlay remains a separate version-linked view.

For volume, distinguish curve extrusion/bevel/profile from material, light and camera. Bump/normal shading, displacement, modeled grooves and through-cuts are different operations. Check silhouette, holes and recognition cues after conversion; a larger bevel or centerline tube may change the mark. The actual editable dimensional source and its rendered image are separate assets.

An adapter must return a real editable revision and source/export relationship, or report that editing is unsupported. A tool success message does not establish good joins, correct anatomy or visual balance. Apply [construction](craft/construction.md) and the relevant [evaluation](evaluation.md) checks to the result.

## Source, composition and rendering

The canonical source owns geometry or pixels. A presentation definition owns question, exact source/variant versions, view roles, layout/background/size settings and output target. A renderer executes those inputs; it does not choose concepts or silently redraw masters. Preview and export should resolve the same versions when implementing a maintained tool.

A single-ink or reversed view needs a real asset or an explicit conversion with stated limitations. Do not flatten arbitrary complex artwork by changing one fill. Distinguish display/CSS size, bitmap dimensions and device scale. Support optical scale equalization as a declared comparison policy without editing canonical geometry.

Resolve only declared resources in imported SVG, fonts and media. An import/render path must not execute embedded scripts or fetch unexpected network resources. Preserve intended bounds, alpha, definitions and font policy; namespace SVG IDs during composition. Unsupported constructs, missing fonts and clipped content must remain visible diagnostics rather than silent successful output.

Write completed generated output to a new target or replace it only after successful rendering; preserve the previous usable artifact on failure. Check source fidelity and the actual export/runtime path where that matters. A second renderer is justified by a concrete compatibility risk, not by ritual. Audit execution, reported findings and readiness decisions are separate results.

## Model-assisted expression and provenance

State whether an operation produces inspiration, a subject study, material, a candidate, a source-preserving expression or an application image. Keep generated references labeled as generated. An input reference needs a role and permitted transformation, not merely a URL.

Reuse the current round's art brief: intent, exact source version, retained recognition cue, material/light/detail, use, unwanted changes and check. Retain the actual provider prompt and input/output versions, model identity when known, parameters and postprocessing. Do not retain credentials. Do not silently switch provider, model, fidelity or output role after failure; use the actual tool's supported recovery and authorization.

If shape, topology or lettering drifts while applying metal or texture, record a changed source/candidate rather than claiming an unchanged selected mark. Raster-to-vector tracing is a separate editing step with contour/topology cleanup and fidelity checks. Similar prompts or seeds do not guarantee identical future outputs.

## Conditional tool-development boundary

When tool development is explicitly requested, first derive a complete user path through [collaboration/workbench](collaboration/workbench.md). Keep native schemas, endpoints, commands, persistence and duplicate/retry behavior with the implementation owner. These guides own semantic meaning, not a competing exact API.

Select one useful slice, such as rendering existing sources into an honest comparison, performing one real editable craft operation, or resuming one compare/annotate/continue round. Test the promised boundary: source versions and holes/IDs/fonts for rendering; actual editable geometry and correct target document for making; mixed/late feedback, partial results, failed or unknown saves and restored context for collaboration. Do not infer interactive correctness from a static gallery.

A reference browser can begin with appropriately sourced records, facet filters and text. Automatic tags require attribution/review; rights can remain unknown. Scoped likes, dislikes and uncertainty stay correctable. Similarity search cannot establish rights or legal clearance, and one liked minimal sample cannot justify filtering away ornate work. No populated corpus or preference model is provided here.

Existing records and assets remain useful without an image provider. Broaden the implementation only for a demonstrated task; cloud storage, embeddings, autonomous teams and a universal geometry engine are not prerequisites for using this method.
