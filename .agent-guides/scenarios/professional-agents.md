# Establish a professional Agent

Use when matching a task to a profession, when a domain lacks usable professional guidance, or when maintaining a reusable professional entry. A Controller organizes this work; a qualified method researcher or domain owner selects and composes the professional method. Follow the project's actual delegation authority. A bounded specialist already equipped for its task reuses that basis.

## Match the work to an existing capability

Start with the intended outcome, domain responsibility, required judgments, inputs, structural outputs and environment. Find the owning module and its local professional entries, then applicable project/shared entries through their existing maps. Read only candidates relevant to the gap.

Distinguish three questions:

| Question | Establish before assignment |
| --- | --- |
| Is there a suitable professional profile? | Scope, methodology, workflow, artifact obligations and known limits fit the task |
| Are its prerequisites available? | Selected Skills/resources, supported tools, runtime and actual access are usable in this environment |
| Is an Agent instance ready? | The authorized backend reports a real identity, compatible context, free assignment capacity and necessary resource ownership |

A directory, role name or installed Skill does not answer all three. Several Skills may support one profession, and several instances may use one profile. A current instance can take another compatible task only after an explicit handoff and context refresh.

Use explicit scope and composition rules when local and project profiles overlap. A nearer filename does not silently replace shared responsibilities. Retain one authoritative method and reference it from narrower entries; route a substantive conflict to its owner.

## Commission a missing profession

When suitable capability is missing, assign a finite professional-construction Task before dependent domain execution. Describe the domain, decisions it must support, intended consumers, required results, constraints and usable research resources. Select a builder with the relevant research/adaptation methods; do not assume a fully formed domain specialist already exists.

The result is a usable professional basis and entry, not the pending business solution. Continue unrelated ready work while the builder investigates the gap. Reuse or extend an existing profile when adequate; do not create a new Agent type or Skill for every task.

## Select and compose the method

For substantive construction or adaptation, use the [role and method construction method](../domains/role-methods/AGENTS.md) and its optional [workspace template](../domains/role-methods/workspace-template.md). The [steward role](../roles/role-method-steward.md) supplies a focused professional responsibility when needed; bounded changes do not require a new Agent or intermediary.

Use [Skill research](skill-research.md) to inspect actual source and support resources, and [external adaptation](../domains/harness-authoring/scenarios/adaptation.md) to fit the selected method to the domain and system. Consider professional knowledge, standards and native tools as well as Skills.

Compare candidates against the actual domain and task: judgments covered, workflow, inputs/outputs, assumptions, tools, authority, important failure cases and adaptation cost. Record why a method was selected, combined, adapted or rejected. Catalog popularity, installation success and a matching label do not establish suitability.

Preserve attribution and license when carrying resources. Keep upstream snapshots distinguishable from local adapters. Skill instructions do not override the user's authority or the shared [test and image limits](../principles.md#quality-tests-and-images). A missing prerequisite remains explicit; do not silently invent competence or replace unknown behavior with an unsupported claim.

## Publish the professional entry

Use the existing domain AGENTS.md as the aggregate entry when sufficient. Add a focused role guide when distinct responsibilities need their own entry, following [professional profile placement](../documentation.md#professional-agent-profiles). Keep shared reusable methods in shared source, and project-specific tools/access in the consuming project's local guidance.

The entry must let an Agent recover:

- Its cohesive responsibility, professional decisions and limits, including the duty to test external Task assumptions and propose evidence-based corrections rather than treat assignment wording as professional truth.
- Required domain concepts, canonical contracts, selected methods and Skills.
- The domain workflow, important decision points and expected intermediate results.
- Inputs, structural artifact requirements, downstream consumers and completion criteria.
- Tool/runtime/access prerequisites, actual routes and unsupported situations.
- Failure, uncertainty, feedback and context-recovery behavior.

Link authoritative methods and resources instead of copying them into the profile. Put selection rationale in the owning design or research record. Register the entry in the owner's existing map or nearest guidance route; do not introduce a separate global registry. A guide's presence does not register it with a host or start a process.

## Establish scoped usability and hand off

Walk through a representative task and the boundary cases that challenge the selected method. Check whether the Agent can choose the right method, identify missing inputs, produce consumable results and stop or escalate at its limits. Distinguish static walkthroughs from observed execution; apply [guidance validation](../domains/harness-authoring/scenarios/validation.md) for the changed scope without starting an unrelated campaign.

Retain the profile location, usable scope, selected resource routes, prerequisites, remaining limitations and any actual evidence. The Controller then binds a suitable runtime instance through [task handoff](task-handoff.md), carrying the profile and real assignment. Documentation readiness, runtime readiness and business delivery remain separate facts.

Revisit the profile when a demonstrated gap changes its method or support. Feed the reusable correction back to its owner; keep live worker status and task history out of the professional guide.
