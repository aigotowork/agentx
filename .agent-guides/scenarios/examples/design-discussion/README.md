# 提交与恢复：设计沟通的小示例

这个页面讨论一个服务端领域/协议问题：客户端没有收到提交结果，能否再提交？它不是产品前端原型，也没有调用真实服务。公共方法见[视觉模型沟通](../../interactive-design-communication.md)，前端专项见[持续预览](../../../domains/webdevelopment/continuous-preview.md)。这是一个可直接打开的单 HTML 文件；若要共享给用户，再通过 LAN HTTP 提供同一文件。该示例保留按钮驱动的历史模拟方式，不是当前视觉方法的组件化范例。

此页保留早期的按钮驱动、逐步模拟方式，仅可参考简化协议语义和 LAN/手动刷新运行机制，**不作为当前模型可视化方法的表达范例**。当前方法要求先呈现模型全景：本题应并列展示成功、明确拒绝、响应丢失分支，并对齐客户端认知、请求/结果记录身份和服务实际效果；选择请求时联动高亮其恢复路径。现有 HTML 尚未按此方式重做。

## 运行与分享

本示例只有一个无依赖的 HTML 文件。在本目录启动静态服务器，端口被占用时选择其他端口，保留已有实例：

```sh
python3 -m http.server 6391 --bind 0.0.0.0 --directory .
```

将实际局域网 IPv4 地址代入 `http://<LAN-IP>:6391/`，从浏览器打开并验证后分享给用户。示例不需要 HMR 或构建；编辑文件后，用户普通刷新即可重新读取。服务器运行期间，当前页面不会自动改变。终端 Ctrl+C 只停止本次示例服务器。Python 服务器用于说明页，实际前端应用继续用自己的开发入口。

## 用这个场景讨论什么

| 操作 | 预期与设计含义 |
| --- | --- |
| 选择“明确保存成功”，提交、接收结果 | 确认保存，派发次数为 1；区分调用与业务实体 |
| 选择“明确拒绝”，提交、接收结果 | 本例明示未保存，允许修正输入并发起新请求 |
| 选择“响应丢失”，提交、接收结果 | 显示结果未知，禁用再次提交；服务可能已经产生效果 |
| 继续“核对原请求” | 使用原 requestId 查询结果，派发次数不增加 |
| 点击或键盘选择三个对象 | 查看各自责任，理解稳定请求身份、结果记录与业务实体的关系 |
| 重置、切换场景或减少动效 | 可重复探讨，场景独立；信息与操作不依赖动画 |

本例的概念模型就在 [index.html](index.html) 的 `model` 中；实际项目应链接其权威设计/原生合同，不能把这个简化模型当成生产协议。在一个真实讨论中，先确认问题和规则，再在原 owner 修改模型，随后更新页面的关系、步骤、样例和拒绝条件。保持同一 URL，告诉用户变化在哪个场景、刷新后如何尝试。

例如，讨论“明确失败是否一定没有效果”时，先明确本例只模拟**明确未保存的拒绝**。如果真实协议存在部分效果，就要修改其权威合同并增加 partial 的场景、恢复路径和派发约束，不能只改页面文案或让所有失败都允许重发。

## 前端开发中对应的最小模式

源代码页面：先启动既有开发服务器并分享实际 LAN URL；开放页面保持稳定，手动刷新加载最新代码。关闭 HMR 后仍需验证服务器缓存会失效，必要时在 HTML 导航时清除 Vite 服务端转换缓存；对 dist 依赖须先构建，或在明确的开发入口直接使用源码。配置/Node 服务实现改变仍可能需要重启。

DancingAI 曾用这个模式修复反馈输入区：先提供可访问页面，再迭代图片移除与清空；Vite 手动刷新回归覆盖了“文件删除重建、watcher 未失效”的情况。这个项目证据解释了方法来源，示例本身不依赖该项目的绝对路径、端口或运行数据。
