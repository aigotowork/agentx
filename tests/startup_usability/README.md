# Bounded startup outcome fixture

Owner: [startup acceptance Task](../../.controller/domain-daemon/tasks/startup-acceptance.md). [Delivery](../../.controller/domain-daemon/startup-usability.md) owns requirements; [canonical evidence](../../.controller/domain-daemon/startup-evidence.md#completed-bounded-result-and-handoff) owns completed Linux local results and retained attempts. Current migration verification is linked from the [direct calls Task](../../.controller/direct-calls/task.md). The native owner supplies focused tests; this fixture establishes actual packaged-process behavior without a Provider. Other-platform runtime support is not established by this fixture.

| Case | Initial condition and user action | Required observation |
| --- | --- | --- |
| SU1 passive diagnosis | No participant identity; missing selected scope; `daemon status` using environment and explicit scope | Useful missing state; no scope/DB creation, no daemon acquisition; explicit override wins. |
| SU2 ordinary cold acquisition | New private scope; ordinary `list --json`, followed by explicit status | Success without manual daemon serve; selected endpoint kernel PID matches staged artifact; no actor required for status. |
| SU3 genuine legacy wire mismatch | A published epoch-3 or epoch-4 binary starts a disposable daemon and durable named manual participant; candidate ordinary call/status | Direct Call is refused by legacy transport before business mutation; actionable restart command and scope/client facts; unavailable old build facts remain explicitly unknown. |
| SU4 explicit recovery | SU3 old owner remains live; candidate `daemon restart --scope` while environment selects a separate running scope | Only selected old owner drains/exits; candidate acquires once; lifetime lock inode and durable named participant identity survive; unrelated scope PID/incarnation remains; no uncertain business call is retried. |
| SU5 singleton and refusal | Concurrent bounded restarts/canonical alias; impostor or held ownership lock without verifiable peer | At most one owner per canonical scope; substantive refusal or bounded timeout; no signal to unrelated process, no lock/data deletion or fallback spawn. Exact fixtures follow released native contract. |
| SU6 short workbench | Asset-free temporary project cwd, normal scope environment, no actor, omitted scope/project flags | Local cold acquire; embedded HTML/assets load, descriptor fixes canonical scope/project and default read-only mode; browser renders usable workbench without errors. |
| SU7 explicit workbench scope/mode | Environment and cwd differ from explicit scope/project; `--collaboration` selected | Descriptor uses explicit values and finite collaboration mode; requests cannot redirect/acquire another scope. No real business workflow rerun. |

[`outcome.py`](outcome.py) runs the composed lifecycle path and independent Web continuation; `--only-web` reuses earlier SU1–SU5 evidence and `--reuse-http-from` consumes successful same-artifact HTTP receipts without rerunning them. [`fixture.py`](fixture.py) supplies exact disposable command receipts, authenticated kernel endpoint identities and pidfd-bound cleanup. [`impostor.py`](impostor.py) is the deliberately unverified same-user negative peer; [`browser.mjs`](browser.mjs) reuses the existing DOM/ARIA/render checkpoint adapter and readonly status locator. Helpers never discover user processes or import secrets. Only fixed artifact paths and a newly allocated `/tmp/agentx-startup-fixture-*` root are accepted. Runtime requires coherent source release and assigned execution authority. Use existing Node22 helper/locked dependencies and source freezer; do not create another installer or generic supervisor.
