# Bigboss mailbox and decorative cat cases

Owned outcome/model and actual evidence: [Task](../../.controller/office-details/bigboss-cat.task.md). `acceptance.py` composes the existing isolated management fixture, seeds real human-addressed messages through the candidate CLI, starts only its private daemon, exercises the actual embedded Space in Chrome, then restarts its owned daemon to check durable handling. It never reads or writes live bigboss messages or selected LAN service state.

```sh
python3 tests/bigboss_cat/acceptance.py /absolute/path/to/candidate /tmp/new-evidence-directory
```

The browser records native pending/history/pagination, deliberate one/current-page handling, duplicate idempotence, unseen later arrivals, reload, narrow actions and stale generation. Motion evidence is explicitly demo supply with seeded random and virtual browser elapsed time; it compares actual Canvas draw bounds with the public last-presented debug projection and covers repertoire, stable nest/selection, reduced motion and pause. It does not establish native work/read completion or arbitrary indoor routes. Existing geometry has no exterior route to south-only room doors; patrol stays in valid entrance space.

The source-native store case is `human_mailbox_explicit_handling_retains_history_and_never_consumes_unseen_or_agent_letters`; pure and affected scene checks are `web/agent-space/tests/bigboss-cat.test.mjs`, `scene-runtime.test.mjs` and `scene-debug.test.mjs`. Execute only relevant checks under the Task's resource/input window. Passing source checks are distinct from candidate/browser or selected-service adoption.

The later grouped-mailbox and common interactions extension has a separate exact-candidate harness:

```sh
python3 tests/bigboss_cat/interactions.py /absolute/path/to/candidate /tmp/new-extension-evidence
```

It uses generated native Qoder hooks to send two letters from one actual Agent, checks safe Markdown/exact sender navigation, group handling, retained drafts, input/IME/overlay Escape and shortcuts, long-press/drift/cancel/context actions, and real new-Agent/kill/stop-participation operations. The browser observes supported Qoder fork capability without clicking or submitting it; this is a deliberate test omission, not an inert product handler. Focused LiveSpace cases verify supported exact-target fork dispatch and unsupported refusal; successful provider fork execution is not established by this fixture. Pure interaction cases live in `web/agent-space/tests/interactions.test.mjs`. No real user Agent or mail is mutated.
