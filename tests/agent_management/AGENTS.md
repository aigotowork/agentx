# Independent management acceptance

Read [the assigned Task](../../.controller/agent-management/tasks/acceptance.md), [design](../../.docs/agent-management/design.md), [native contract](../../src/management/contract.rs) and [case map](README.md). Results belong in [evidence](../../.controller/agent-management/evidence.md).

`acceptance.py` is the public HTTP/browser entry; `fixture.py` owns disposable scopes and exact process cleanup; `provider.py` is a finite local Qoder substitute using candidate-generated hooks and a fixture transcript; `browser.mjs` drives the actual embedded page. No fixture or client opens managed SQLite. Use only an explicitly supplied integration-owned candidate. Never build, replace installed binaries, target existing scopes, or launch a paid Provider. Every run allocates a new root and retains separate receipts, including failures.

For explicitly assigned consolidated system acceptance, `Fixture(..., root=owned_path)` creates one private `agentx-management-*` directory inside the controller-owned existing workspace instead of allocating another top-level environment. An existing path is refused; it is never implicitly adopted or overwritten. Keep that fixture object and scope for the whole session, including controlled owned daemon restart. Default management-suite allocation remains unchanged. [Contract-system acceptance](../contract_service_projections/AGENTS.md) owns that consumer lifetime and evidence.

`Fixture.reopen_owned(candidate, evidence, previous_receipts)` explicitly continues only a previous cleaned private fixture with matching candidate identity. Use it to retain scope/data through ordinary harness repairs; prior receipts remain immutable. Configure prepares scope0700 so passive observation validates it before any daemon acquisition. The finite Provider loads `contract_actor.py` only when the owning consolidated harness explicitly stages that sibling in its private bin; ordinary suite behavior remains unchanged.
