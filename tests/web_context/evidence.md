## Material defect and layout assessment

Reported to `tuli`/`nube` in #27706, accepted for ordinary repair in #27719/#27748. In the actual 450px iframe, expanding `.live-receipts` anchors its wide popup to the small left-side summary. The popup extends to negative child coordinates; original receipt action is clipped outside the iframe. Playwright's real pointer click repeatedly hits the parent form, so the user cannot reliably recover an admitted message after a lost reply. See `/tmp/web-context-acceptance-r1-b/browser/failure-lost-admitted-response/viewport.png`, corresponding child JSON and `result.json`/trace. This is a usable recovery failure, not a request for stylistic polish. The screenshot shows the narrow clipped popup layered across the left edge while the actual message/composer remain visible. No force-click or DOM click was used to manufacture success.

Inspected `/tmp/web-context-acceptance-r1-c/browser/WC15-sidebar/viewport.png` for the concrete task of reviewing/removing an image then deliberately sending in a 360px sidebar. Exact member header, tabs, message history and local pending/composer/remove/attach/send remain legible and reachable; history scrolls independently and long names wrap within the child. The real native-path guidance is message content and can occupy history, but does not displace the fixed composer. This observation supports this finite screen/task, not every viewport, assistive technology or motion state.

R3 source/asset receipt resolves the defect. Source-manifest comparison independently confirms only the five declared UI files differ from r1 (Conversation history composition, optional model/projection fields, BoundWork and space.css), with native/scene source unchanged. Normal pointer recovery succeeds at 450px and 360px. Inspected r3-b `WC13-popup-open/viewport.png` for whether the user can see/reach the original lookup within the sidebar: panel remains inside the frame and the lookup button is readable/clickable. Underlying reader text is visible through the popup treatment, reducing visual separation; recorded as nonblocking polish for `tuli`, since the required recovery action and state transition work without force clicks. No extra build/review cycle is requested.

The r3-a affected sidebar screenshot retains exact member identity, compact tabs, durable history and local pending/remove/composer/send after BoundWork insertion. Gabi independently owns binding-specific state/disclosure evidence on the byte-identical final asset snapshot; this acceptance does not substitute empty fixture bindings for that evidence. Native/intake and scene suites were not broadly replayed. No remaining material web-context defect or required execution dependency remains within the declared finite acceptance scope.
