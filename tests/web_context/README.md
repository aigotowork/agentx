## Contract binding

Consumed implementation design handoff #27078 on 2026-11-15. These are links/bindings to the canonical design, not independent product decisions:

| Consumer seam | Binding for the forthcoming runner |
| --- | --- |
| Binary upload | `POST /api/v1/attachments?generation=G&name=NAME&media_type=TYPE`, raw octet-stream, 201 Attachment. Known PNG and arbitrary file bytes; 0, 10 MiB and 10 MiB + 1 boundaries; names 255 UTF-8 bytes and media type 128 ASCII bytes. |
| Download and storage | `GET /api/v1/attachments/ID?generation=G`; bytes under private `<scope>/management-attachments/<generation>/` with UUID filename. Raster preview whitelist versus forced non-raster download; no deletion/GC promise. |
| Native send/history | Existing SubmitMessage adds optional attachment IDs; empty text with ready attachment is valid. Public MessagePage retains structured attachments. Original request IDs govern duplicate/conflicting body and uncertainty. |
| Exact initial focus | `/space/?scope=S&generation=G&agent=NAME&incarnation=BITS&office=PATH&view=chat&layout=sidebar`; history replaces incarnation with stopped_event. Exactly one instance/history selector. No query text upload. |
| Readiness | Parent hello `{protocol:"agentx.context.v1",type:"hello",requestId}` after load; await correlated ready even before native data loads. Then wait for actual sendable exact target before context submission. |
| Add context/result | Parent addContext envelope carries `{scope,generation,agent}` target and `{title,text,url,files}` context; File/Blob via structured clone. Result `added` is draft-only. Same in-flight/completed request ID must append once (128-entry page cache); reload loses draft/cache without replay. |
| Partial failure | Multi-file addContext upload error leaves previous draft intact; failed orphan uploads may persist. Late completion requires final exact-target/scope validation. No error result may imply native send. |

Add duplicate in-flight/completed parent request checks to WC03/WC05 and partial multi-file failure to WC11. WC02 invalid office must be explicit; WC04 invalid URL scheme and unsupported launch operation have no effect. WC14 includes SVG/HTML forced download. WC12 rejects cross-scope attachments; uploads are generation-owned, not recipient-owned, so deliberate same-scope attachment use by another recipient is not itself a defect. The design explicitly has no total storage quota or automatic unused-file cleanup; verify finite per-file/message limits without inventing a global quota requirement.

Controller clarification #27097: iframe postMessage structured clone supports the direct File/Blob case, but Chrome extension runtime hops may JSON-serialize. The extension example must describe transporting bytes and reconstructing File/Blob in the wrapper; direct iframe tests cannot establish extension-runtime File/Blob preservation. Documentation/example review will check this distinction. A packaged extension and actual extension runtime execution remain outside this Delivery.

## Existing infrastructure and execution plan

Compose [management Fixture/Http](../agent_management/fixture.py) for private HOME/XDG/AGENTX_DIR, port-zero native management startup, candidate-generated local Qoder hooks, public operation reconciliation and Linux pidfd/exact-process cleanup. Its local [Provider](../agent_management/provider.py) supplies mailbox/transcript/native reply evidence; it never establishes real Provider multimodal ingestion. Reuse [live-UI adaptations](../live_ui_integration/live_fixture.py) only where their finite behavior is needed. The agent's selected model is separate from these local test Providers.

Use installed Playwright/Chrome via `AGENTX_PLAYWRIGHT_PACKAGE` / `AGENTX_BROWSER_EXECUTABLE`, following the [existing browser consumer](../live_ui_integration/browser.mjs). No dependency install or product build is assigned here. Add a small disposable loopback parent server for the actual iframe; a sibling frame supplies the non-parent source case. Serve only owned parent harness content and test fixtures. The native candidate must serve the real child and real HTTP uploads/messages. Assert loopback and exclude protected ports 18959, 18967, 18971 and 38023 for every owned listener.

Native checks use public HTTP/CLI and direct reads of paths returned in attachment receipts, after asserting those paths are confined to the disposable scope. Never open managed SQLite or seed privileged internal routes. Hash fixture inputs and downloaded/persisted bytes; retain original HTTP headers, bounded bodies, operation IDs, exact Agent refs and Provider logs. For binary HTTP adapt the consumer client locally rather than mistaking the existing text-decoding evidence helper for byte evidence.

Bind runnable payloads/selectors only after usable design/contracts are available. Require an immutable integrated candidate path/hash before any runtime/browser execution. One fresh evidence directory per attempt; no broad historical suite runs. A repair gets a bounded continuation/new attempt for affected cases, linked to retained prior passes and failures. Candidate changes require an explicit impact decision before reusing results.

## Checkpoints, judgments and limits

Capture meaningful browser states: exact target initially focused; parent context pending; upload pending/error; deliberate send committed with native receipt; refreshed durable image/file history; narrow sidebar with attachment controls and error recovery. Reuse [checkpoint](../collaboration_workbench/browser_checkpoint.mjs) for DOM/ARIA, focus/geometry, viewport/DPR and bitmap plus explicit selected ref/draft/receipt supplied as nativeState. Parent and child require separate captures, with frame-aware actual content. These are sequential observations, not atomic React state inspection. Retain network/events and Playwright trace to correlate transitions; pure HTTP/disk cases need no artificial UI capture.

For the narrow layout, inspect the actual bitmap specifically to judge whether identity, context chips/cards, composer, removal and send remain readable/reachable; explain any mismatch and limits in this Task's evidence handoff. DOM text alone cannot establish visual usability. Browser-dispatched paste/drop covers the app event path, not physical clipboard/extension installation; the parent harness covers the documented bridge, not a packaged extension.
