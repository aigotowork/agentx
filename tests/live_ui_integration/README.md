## Evidence and execution boundary

Reuse [management fixtures](../agent_management/README.md): candidate-generated hooks, local Qoder substitute, transcript and real native reply. No managed SQLite clients or arbitrary public seeding of internal `Collect`, recovery attempts or job state. HTTP failure injection may discard a real upstream response or block a read; it must not fabricate a successful API/domain response. Internal deterministic store/episode/dedup races are authored by the native owner and executed by integration, linked separately rather than substituted for independent browser evidence.

Entry: `python3 tests/live_ui_integration/acceptance.py --candidate /absolute/frozen-candidate --sha256 EXPECTED --evidence /absolute/new-directory`. Both actual browser paths run by default; `--api-only` explicitly records partial evidence. Existing Playwright/Chrome paths reuse the management runner's environment overrides; no install occurs. Native collection/report predicates allow 40–45 seconds for the documented 10-second host cadence.

For a corrected browser driver on an unchanged candidate with retained passed API evidence, `--browser-only` creates a new isolated scope with only prerequisite native Provider/collection/error-episode setup. Link it to the original API run; it does not rerun or replace the passed API case ledger.

When a later case exposes a harness binding issue, `--browser-start inspector-message-transcript`, `inspector-lost-admitted-response` or `stop-history-resume` continues only the remaining coherent journeys with fresh prerequisite state. Retain all earlier reports and explicitly link the passed checkpoints; a partial-start run alone never proves the whole map. Successful earlier segments retain their failure report because a later step failed; do not relabel the historical run as passing.

No execution, daemon startup, browser navigation or candidate probing before frozen path/hash handoff. The final candidate must contain both maintained applications; separate source mock runs cannot satisfy L01–L09. Every failed attempt retains its original evidence; later fixes use a new candidate hash/run directory. Finite dependencies unavailable through generated hooks or public routes remain explicit blockers, not silently skipped passes.

The [local Codex substitute](codex_provider.py) parses candidate-generated `-c hooks.*` declarations, participates in native `SessionStart`, and executes generated failed/completed model hooks only on fixture-owned control commands. Native launch trust discovery requires a subprocess named `app-server`; the private substitute implements only `initialize` and `hooks/list`, rejects model/session RPC, and never invokes a real Codex process. This fixture is authorized by integration AgentX #24929. It establishes native Hook composition, not Codex application/model compatibility. Qoder text/native replies reuse the existing management fixture. [The scoped adapter](live_fixture.py) extends only its private staged message pattern to accept native `[new message #id]` for Inspector's legitimate `intent:null` send; upstream test/product source remains untouched. Controlled usage is appended only to its owned Provider-format transcript for real parser collection.

I05 browser action is deliberate policy configuration followed by native automatic admission. The current collector admits eligible episodes in the same sample transaction, so UI manual continuation cannot reliably race automatic admission; API replay verifies the retained once-only attempt, and native-owned deterministic guards cover manual admission races separately. Queued audit must remain unresolved until a later real generated successful model hook, whose native status is `observed_error_cleared` and explicitly does not establish continuation causation.
